# 视觉核验标准流程 SOP

> **一句话**：每批剩余图片核验（2597 张「机器误判修正」工程）从选批 → 逐张看图 → 四类判定 → 知识分组 → 批次记录 → **可信图库整批入库** → 导航统计同步 → 验证收尾的标准化链路。
> 本 SOP 是 [[10-索引与统计/视觉已验证图片索引]]（可信图库）的配套执行规范。入库节奏统一为 **整批统一入库**（原子性优先：一批要么完整入库、要么整批返工，统计数字只动一次）。

---

## 1. 目的与适用范围

- **目的**：把「人工视觉核验通过」的图稳定沉淀进可信图库，让每批次核验不只是一次性打标，而是**持续扩充 agent 可信任的搜图层**。
- **适用范围**：`「机器误判修正」2597 张视觉复勘` 及其延伸批次（周公度/赵鑫光/真题源等全部未核验 HIGH 图）。
- **核心理念（用户指示，2026-08-05 归档）**：
  1. **高质量可视化优先**（Visual Quality First）：晶胞模型、3D分子/配合物构象、反应机理/箭头推导图、实验装置图、相图/能级图/等温做功曲线/电势差曲线等优先；纯文字算式/方程式能直接用 Markdown/LaTeX 表达的，**坚决不占高价值讲义图位**。
  2. **书籍教材优先**（Textbook Source First）：权威书籍教材源（赵鑫光《高中化学竞赛基本理论学习笔记》295张、周公度《结构化学基础》900张等）优先，待教材体系清理完成后再推进真题试题库源。
  3. **按章节/题号逻辑顺序连贯复勘**（Sequential Audit）：废除跨章节散落抽图，按教材/资料章节/题号顺序逐页连贯推进，利用同组图片的天然承接关系提升精准度。

## 3. 六阶段流程

### Phase 0 · 批次规划（选批）

- **候选来源**：总索引中 `description` 含 `【机器误判修正】` 且尚未核验的条目；或已核验清单中标记"待上下文"的条目。
- **选批规则**：
  1. 按**书籍教材优先**顺序推进：赵鑫光 Ch1-199（逐一验证）→ 赵鑫光 Ch200-350 → 周公度 Ch1-10 / Ch11-20 → 其他教材源 → 真题源。
  2. 每批 **5–15 张**，严格按源章节/题号**顺序连贯**选取，与上一批末尾锚点拼接（例：批次35末 `b80aca9c…` → 批次36头接续）。
  3. 优先选 `HIGH` 级、源描述疑似可可视化的条目。
- **产出**：候选清单（哈希短码 + 源描述 + source_file + 批次号）。
- **动作**：建 MCP Task 卡（MAINTAIN/FORMAL/NORMAL），记录本批范围。

### Phase 1 · 逐张视觉核验

对每张候选：

1. `kb_read` 源 `_index.md` 对应行 + 总索引条目，拿到源描述与语义别名。
2. **Read 图片本体**：`媒体仓库/<完整64位哈希>.jpg`（视觉核验必须看图，禁止只读描述）。
3. 对照**源描述** + **同批次/同链路上下文图**（承接关系：同一机理链条、同类晶体多视角、同一高分子链节）判定。

**四类判定**：

| 判定 | 含义 | 是否入库可信库 |
|:---|:---|:---:|
| ✅ **确认可用** | 图内容与描述一致，且为优质可视化 | ✅ |
| 🔄 **纠偏可用** | 描述与实际不符，但图本身是好图 → 按实际内容重写描述后确认可用 | ✅ |
| ⬇ **降级** | 纯文字算式/方程式片段/二维码/数据表 | ❌（记录防重复） |
| ❓ **保守命名** | 图能看但无法精确判定主题 | ❌（待上下文） |

- **哈希错位**：若源描述与图内容不符（Ch1-199 错位率 53%），记录到 [[10-索引与统计/视觉已验证图片索引]] 的「哈希错位记录」节，并在源 `_index.md` 修正。
- **降级项**：description 统一追加 `（纯文字算式片段，不推荐讲义配图）`；记录到已核验清单 degraded 节，**防止未来批次重复核验**。

### Phase 2 · 知识分组判定

> **铁律：以"视觉内容的主体"归类，绝不盲信源索引 `knowledge_points`（机器误标重灾区，已出现整组传导性错配）。**

- 判定依据：图的**核心教学对象**，参考 §6 分组对照表。
- 判定技巧：
  - 同批次同链路图通常同组（同题机理链、同章图表）；
  - 参照可信图库已有同组条目确认口径；
  - 跨主题综合图 → 入「综合」组，宁宽勿错；
  - **拿不准就看图再判，或标 ❓ 保守命名，不硬塞错误专属组**（教训：手性亚砜[2,3]-σ迁移、分子内SN2′手性产物曾误入配位组）。

### Phase 3 · 批次记录（源修正）

整批核验完成后（入库前）先行落盘：

1. 追加 `已核验图片清单.md`：本批确认/纠偏/降级/错位明细（哈希短码+判定+描述）。
2. 更新 `09-审计报告/图片视觉复勘汇总-2026-08-05.md`（批次记录、累计数）。
3. 同步源 `_index.md` 与核心 Markdown/JSON：修正 description / semantic_alias / knowledge_points。

### Phase 4 · 可信图库整批入库（★ 本 SOP 的核心新增环节）

> 节奏：**整批统一入库**。核验完成、四类判定全部稳定后再执行，避免中途返工造成不一致。

1. 收集本批全部 ✅+🔄 条目（排除降级/保守命名）。
2. **反查完整 64 位物理哈希**：在 `全库核心图谱总索引.json` registry 中按 `physical_filename` 匹配；短码匹配到多条时，用 source_file / semantic_alias 消歧。
3. 按 Phase 2 分组结果，将每行追加到 `视觉已验证图片索引.md` **对应分组表格末行**（列格式：`物理哈希文件名 | 语义别名 | 视觉内容(人工确认) | 核验批次`）。
4. 更新该分组标题张数（如 `## 有机反应机理 （133张）` → 133+N）。
5. 更新统计区：`哈希体系确认图` +N、`合计` +N。
6. 若含 zgxg（media/ 目录可读名图），同步更新附录A。

### Phase 5 · 导航与统计同步

- `00-首页/图片索引.md` 导航行「**447 张人工确认图**」→ 新合计。
- `已核验图片清单.md` 统计总览「累计视觉核验」。
- `状态摘要.md`「图片资产治理」口径（若数字变化）。
- `待办交接清单.md` 最近已完成 + 累计核验数。
- `计划-图片识别后续任务.md` 对应批次项打勾并更新累计。

### Phase 6 · 验证与收尾

- **验证**：
  - 新行完整哈希在 `媒体仓库/` 真实存在（Glob 抽查）；
  - 无重复哈希（每行只出现一次）；
  - 各分组实际行数 = 标题张数；
  - 统计区合计 = Σ各分组 + 附录A = 导航数字。
- **MCP 收尾**：`kb_gate verify → close → archive`。
- **工作日志**：追加当日批次记录。

## 7. 踩坑记录（实战沉淀，新增批次持续补充）

- **赵鑫光 Ch1-199 源哈希错位率 53%**：源描述与实际内容系统性不符，**必须逐张看图**，不得信任源描述批量打标。
- **分组错配传导**（08-06 批次31-32 补齐时发现）：总索引 `knowledge_points` 机器误标会整组传导（例：34 行分子轨道组实际含大量有机机理/晶体/电化学图）。**分组一律以视觉内容主体为准。**
- **纯文字降级项**：已核验清单 degraded 节是防重复核验的"黑名单"，每批先查。
- **短码撞车**：8 位短码反查完整哈希可能命中多条，必须用 source_file/semantic_alias 消歧。
- **入库防漂移**：分组标题张数、统计区合计、图片索引导航数字三处必须一致，改一处同步三处。
