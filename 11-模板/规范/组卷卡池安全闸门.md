# 组卷卡池安全闸门规范（group_gate）

> 定位：**组卷前的卡池准入检查**，与 `render_gate`（公式渲染）并列，同属"交付前必须全过"的闸门。
> 工具：`11-模板/scripts/group_gate.py`
> 建立：2026-10-07（题库三元素体检第二批）

---

## 一、为什么必须有这个闸门

组卷器（`build_multi.py` / `build_org.py`）通过 **`mv_extract.extract()`** 切分题面与答案，而该函数
**只把以下两种形态当作答案起点**：

| 认可的答案起点 | 正则 |
|---|---|
| 独立成行的答案节标题 | `^#{2,4}\s*(参考答案\|解答\|答案\|详解\|解析)\s*[::]?\s*$` |
| `<details>` 折叠块首行 | `^<details>\s*$` |

**若一张卡的答案写成 `**答案**：` 内联行、`> **答案**：` 引用块行、裸行 `答案：`，
抽取器找不到答案起点 ⇒ 把整张卡当成题面 ⇒ 学生版直接印出答案。**

2026-10-07 全库实测（6088 张在役卡，用真实抽取器逐张实跑）：

| 状态 | FATAL | 说明 |
|---|---:|---|
| 治理前 | **68** | 答案泄露 38 ／ 题面含答案 25 ／ 题面丢失 5 |
| 治理后（单题卡已归一 + 其余已标注禁卷） | **67** | 全部为「一卡多题 + 题答案交错」卡，结构无法靠改标题解决 |

另注：组卷器自身虽有 `len(answer) < 25 → 弃卡`、`题面含讲稿口播 → 弃卡` 等过滤，
但**拦不住"答案被切一半到题面区"**的情形（此时 answer 段够长，过滤放行）。

## 二、强制用法

```bash
# ① 对已选定的卡清单跑（★ 组卷流程必跑，用 --cards 而不是 --all）
python -X utf8 11-模板/scripts/group_gate.py --cards 选卡清单.txt

# ② 对某个来源目录做全量摸底
python -X utf8 11-模板/scripts/group_gate.py --domain "04-题库/教材习题/赵鑫光"

# ③ 全库体检（耗时约 6 分钟）
python -X utf8 11-模板/scripts/group_gate.py --all --quiet --out group_gate_all.json
```

**退出码：`0` = 无 FATAL；`1` = 有 FATAL（禁止进卷）；`2` = 参数/依赖错误。**

⚠️ 与 `render_gate` 同理：pre-commit 钩子有 75 秒预算会漏检，**本闸门必须显式运行**，
不能指望提交时被自动拦截。

## 三、分级与处置

| 级别 | 判据 | 处置 |
|---|---|---|
| **FATAL** | 答案泄露（抽取后 answer 为空但卡内有答案）／题面丢失（抽取后题面为空）／题面含答案标记 | **禁止进卷**。先修结构或换卡 |
| **WARN** | 一卡多题（答案点 ≥3 或题号小节 ≥3）／无答案可用／题面指图但无图 | 人工确认后方可进卷 |

### 「一卡多题」为什么不能靠调答案节位置解决

组卷抽取只能定位**第一个**答案起点，于是只有两种结局：

1. 不补答案区标题 → 学生版印出整卡（含全部答案）→ **答案泄露**；
2. 补了答案区标题 → 第 2 题及以后的题干被切进答案区 → **学生版缺题**。

因此这类卡只能**拆分为单题卡**（题面/答案/图逐题对应）后再入卷。
库内已有 95 张此类卡已在卡内标注 `禁止直接组卷`，拆分为独立待办。

## 四、卡池准入规则（写给组卷者）

1. **先跑闸门再选题**：对候选清单跑 `group_gate --cards`，FATAL 卡直接换掉，不要"先组卷再说"。
2. **只认 `## 参考答案`**：新卡入库时答案节标题必须独立成行；不要用 `**答案**：` 内联。
3. **一题一文件**：多题合并的卡（选择题组、章节习题合集）不要进组卷池。
4. **答案与题面必须分离**：答案逐小题内嵌在题面区的卡（题答案交错），一律不进卷。
5. **WARN 项逐条确认**：`题面指图但无图` 的卡即使答案正常，也会让学生做不下去。
