## 三、四个关键事实（都经实测核实）

### ① 只有 1 条管线按考点抽题

19 条里只有 `gen_weak_drill.py` 做 **KP 精确命中**（降档链式：测试题档 → 习题书档 → 习题集档）。
其余全部按章节模块 / 学科 / 难度 / 固定清单选题：

- `gen_module_set.py` 按 `subject_module` + `pack`
- `testpaper_v2.py` 按学科 + 子模块 + 难度配额 + 随机种子 42
- `build_module_book.py` 的 KP 只用于**印刷显示**，不参与选题
- `build_exam_paper.py` 的 KP 只在「剥离字段」列表里（不印在卷上）

⚠️ KP 覆盖率已达 100%，但**消费方只有 1 条**。全局目标「考点可检索 ⇒ 考法↔题目双向可达」
在组卷侧尚未落地。

### ② 答案来源有 4 种形态，各管线处理已核对

| 形态 | 规模 | 处理现状 |
|---|---:|---|
| 标准 `## 参考答案` | 主体 | 各管线正常 |
| 异形标题（`## 答案`/`## 解答`/`## 解析要点`） | **465** | 机检原判为「无答案区」，实为写法差异 |
| 外链型（答案在卷册，**有意不复制**） | **577** | 各管线均不跟随；补强卷已改为明确标注 |
| `<details>` 折叠 | **355** | 习题书线展开、学生卷线剥离；**已核实学生版产物 details 全为 0** |
| 已标注「源确缺答案」 | 140 | 带 `> [!warning]` 规范标注，组卷按无答案处理 |

**外链型为何不复制**（卡内原话）：「派生文件**不复制**卷内 OCR 答案
（源答案文本存在跨题粘连等缺陷，复制会引入错误）」——**这是有意的设计决定，不是缺陷**。

### ③ `fm_parse.py` 已成为 FM 解析的唯一口径

库内 FM 数组有**六种书写形态**（同行 / 跨行 / 块列表 / 标量 / 空值 / 值内含逗号），
今天在这个问题上累计失误 **11 次**。现已固化为 `11-模板/scripts/fm_parse.py`：

- 判「键是否存在」**只认键名**；取值**限定字段边界内**；数组**括号配平扫描**
- 形态覆盖自测 **11/11**（含标量）
- 已被 `kb_metrics.py`、`gen_module_set.py`、`gen_weak_drill.py` 三处采用

### ④ 管线脚本入库位置

**`11-模板/scripts/` 是管线脚本的入库位置**（`.workbuddy/` 被 gitignore，清理工作区即丢）。
本轮已迁入 3 条在用管线，去掉硬编码 vault 绝对路径（原 `C:\Obsidion\妙妙屋` → `__file__` 自动定位）。

## 六、判据纪律（本轮血泪）

1. **凡落盘的长文本一律用 Write 写文件**，绝不内联进 `python -c`/shell
   （bash 会吞反引号，今天累计 8 次：提交消息 3、日志 3、脚本片段 2）。
2. **下结论前先问「这个判据自己测过吗」**——今天多次出现「脚本能跑但判据没测」。
3. **统计口径必须声明扫描范围 + 分类判据，并做 Σ 对账与第二口径交叉验证**。
4. **看到某脚本不识别某标记，不等于该问题存在**——要核实源文件是否真含该标记
   （details 泄露误判就是这么来的）。
