## 〇、铁律（最高优先级）

**铁律一（题面侧）**：每一道进卷的题，必须【对照原 PDF】用视觉能力核验「题目／图片／答案」三元；
只信 OCR 中间产物一律判不合格。发现问题**优先换卡**（池内另选），不硬修；确需修源卡时逐条回源、带断言、可复核。

**铁律二（`$$` 独占一行）**：`$$` **必须独占一行**。行尾 `$$`（inline）不被转换器识别为数学定界符 ⇒
**整卷答案区数学解析静默崩塌**（docx 出现数百段字面 `$`）＋ **图片不写入 docx**（`图=0/N`）。
拆长公式一律改用**段落式行内 `$…$`**（公式过长被页宽截断时尤其常见）。

**铁律三（答案侧）**：**答案区也必须逐页视觉核验**。交付前把答案版 docx **全页渲染、逐张打开**，
对照 md 原文与 docx 的 OMML 文本（`docx_probe.py`）三方核验；不得只看缩略图下结论
（缩略图会把 `=63.97` 误读成 `=−63.97`）。

**铁律四（格式工具不得在题面区生成评分标记）**：`build_org.LEAK` 判据把「**（N 分**」视作答案特征 ⇒
若把**题面区**的 `(2')` 规范成 `（2 分）`，该卡会被判「题面泄露」而**掉出池**；
而 `load_plan_picks` 的规则是「**计划内任一张不在池 ⇒ 整卷重选**」⇒ **整卷题目被悄悄换掉**
（2026-10-08 实测：`题-GChO-03-02` 掉池 ⇒ 卷 XII 十题全换）。
⇒ 硬性要求：① 评分标记类规范化**只在答案区**跑（`volpost.SC_NAMES`）；
② **改完源卡、组卷之前，必须验证卷内 10 卡仍在池**（`xii_poolchk.py` / `volpost --diag`）。

## 五-e、表格列宽·字体度量模型（v1.3 新增 · 清单表折行根治）

> 病象（10-07 起记录、10-08 根治）：卷末《选题清单》表的「**来源**」列被压到 1.06cm ⇒
> `chemy`→`che my`、`质心GChO`→`质 心 GC hO`；「**模块**」列 1.70cm ⇒ `结构化学` 折两行；
> 「**难度**」列 1.75cm ⇒ 4 颗 ⭐ 折两行。旧实现按「字符数比例」分列，**不知道真实字宽**。

**度量模型（`build_chusai_zhenti_layout._ch_pt / _txt_pt`）** —— 由卷 XII 答案版 PDF 的 span bbox 实测标定：

| 成分 | 值 | 校验实例（实测／模型） |
|:--|:--|:--|
| 正文字号 | **10.5pt**（五号） | — |
| CJK / 全角 | **10.5pt/字** | `结构化学` 42.0／42.0 |
| ASCII（Times New Roman 字宽表） | 按 em 千分宽 | `chemy` 27.95／27.99、`GC` 14.54／14.58、`che` 14.55／14.57、`Xe` 12.20／12.24 |
| ⭐ U+2B50（SegoeUIEmoji 回退） | **14.41pt/颗** | 2 颗 28.81／28.82（4 颗＝57.6pt，≈2.03cm） |
| **CJK↔半角字母/数字 自动间距** | **+2.6pt/处**（≈1/4 em） | `质心GChO` 48.4pt 却塞不进 49.7pt 可用宽 —— 真因 |

- 🔴 **单元格可用宽 = 列宽 − `CELL_PAD`**，`CELL_PAD = 12.0pt`（108twips 左右边距×2 ＋ 余量；实测 `汇智` 21pt
  折于 30pt 列、`分值` 21pt 存于 32.05pt 列 ⇒ 边距 ∈ (9,11]；`质心GChO` 折于 60.45pt 列 ⇒ 叠加自动间距后才自洽）。
- 🔴 **「CJK↔拉丁自动间距」是最隐蔽的坑**：不加这一项时，纯 CJK 的「分值」能进、混排的「质心GChO」却进不去，
  **会得出互相矛盾的两个边距区间**——遇到这种矛盾，先怀疑这项，别怀疑模型。
- `wid` 由 pt→twips 一律**向上取整**（`math.ceil`），余数只补给**最宽列**；刚性列**永不吃余数**（0.02pt 也会翻车）。

**两处消费**（同一模型，单一真源）：

1. `set_list_table_widths`（**清单表**，命中「7 列 ＋ 表头含『卷内题号』」）：
   来源/模块/难度/分值 四列**刚性**＝`最长单元格单行所需 ＋ CELL_PAD`；卷内题号固定 1.30cm（表头设计上折两行）；
   题名/题卡两列分剩余宽（**能用「题名单行＋题卡两行」就用**，题名单行无望时按内容比例各让一步）。
2. `set_table_widths`（**通用表**）新增「短列保底」步：任何列不得窄于 `min(所需＋CELL_PAD, 45%表宽)`，
   缺口由「有余量的列」按余量比例承担 —— 修掉 `2-1-1`／`7-1` 之类短 token 被断成两行。
   🔴 顺带修掉一个**既存畸形**：旧 `wid[-1] += 9752 − Σwid` 在「下限超配」时会把末列写成**负宽度**
   （X 卷答案版表20 实测 `w:w="-468"`）；新实现保证全列为正且和为 9752。

**审计工具**：`.workbuddy/scripts/table_wrap_audit.py`（只读，秒级；直接 import 上面的模型）
`python table_wrap_audit.py [-all] [-v] [docx]`；判读见 §四 闸门 9。

**新卷复用手册（补）**：⑥ 出完 docx 后跑 `table_wrap_audit.py`；报折行且非「题名/题卡/卷内题号表头」⇒ 查模型参数
（首选怀疑：字号变了、表格字体换成非宋体/Times、⭐ 换了字体、`CELL_PAD` 需重标）。

## 五-h、构建期「图有效分辨率」封顶（v1.5 新增 · 2026-10-09 · **治本**）

**病根**：物理档封顶（`land 7.0×5.2` / `sq 5.6×5.6` / `port 4.6×6.6` / `page 16.5×21.0`cm）
**与源像素无关** ⇒ 一张 153px 的切片被拉到 7.0cm 打印，有效分辨率掉到 **72dpi**（§五-g 的 40 处全是这一类）。
**光靠调物理档封顶治不了**——同一物理档里既有 800px 的清晰图也有 153px 的糊图。

**治法**：在**全部物理档封顶之后**再加一道**按源像素**的封顶（`build_volX_zhenti.py::apply_dpi_cap`）：

```
渲染宽 ≤ px_w / MIN_DPI × 25.4 mm      （MIN_DPI = 150，只缩不放）
```

**实现要点（照抄，别改错地方）**：
- 挂在 `process_document_xml` 的**最终 pass**（monkey-patch 包一层），在 `<w:drawing>` 粒度上处理
  ⇒ **段落图与表格内图一并覆盖**。⚠️ 只在 `cap_image_width` 里加是**不够的**：表格图走 `cap_table_images`，不经那条路。
- 图名从 `<pic:cNvPr descr="文件名">` 取（`resolve_images` 输出的**暂存实际文件名**）；
  像素表 `IMG_PX` 由 `stage_image()` 记录 ⇒ 必须是**降采样后**的最终像素（否则 dpi 算虚高）。
- 只缩不放（`scale = min(1.0, …)`）⇒ **已达 ≥150dpi 的图完全不受影响**，改动面天然有界。
- `--no-dpi-cap` 可关闭（仅供 A/B 对比）。

**为什么取 150dpi**：线稿印刷的合格线（扫描件常用 150／照片 300）。它同时是 §五-g 判据（105）的**上游保证**
⇒ 构建期守住 150，渲染层就永远不该报 BLUR。

**实测（2026-10-09 全量重出）**：
| 项 | 值 |
|:--|:--|
| 受影响图 | X 28、XIp 26、XI 27、XIV 22、XV 16 张（**共 119 张**；XII/XIII 无图） |
| 全量结果 | **431 张图，最低 150.00dpi，<150dpi = 0 处** |
| 渲染层 | **BLUR 34 → 0**；`SMALL` 6 细分为 `THIN 6`（细长条源切片，223~782dpi）＋ `SMALL 1`（手写小片） |
| 版面 | 图变小 ⇒ 版面**更紧凑**（XIV 答案版 23→22／XIp 29→28／XI 38→36 页），无新增溢出/空白页 |
| 已达标图 | **零改动**（≥150dpi 者 scale 取 1） |

**🔴 判读纪律**：
1. 出现「图看起来偏小」先算 dpi——**小 + 150dpi 优于大 + 72dpi**（后者印出来是糊的）；源切片本来就只有 100 多像素时，**不存在**既大又清的选项。
2. 极低清源（<200px）会缩到 2~3cm，属**正常代价**；若某图确实需要更大 ⇒ 那是**源切片要重裁**（`locate_source_pdf.py` 流程），不是放开封顶。
3. ⛔ **不要用「调大 MIN_DPI」当通用手段**——越大图越小；调之前先按 §五-g 的 dpi 分布看有无必要。

## 五-i、工具链与「静默风险」防护（v1.7 新增 · 2026-10-11）

## 五-j、题面图位置缺陷（S1）的判定与修复（v1.7 新增 · 2026-10-11）

> 病象：**题面以「下图/如右图」引用图，但题面区无图**（图被切进答案区，或根本不在卡内）⇒
> **学生版只出题面 ⇒ 题目不可做**。判据 S1（机器可筛）：题面区图引用 = 0 且题面含图指代词。

**判定（机器预筛只作候选，定性必须逐张读图）**：
1. 🔴 **「题面含图指代词」≠「引用已有图」** —— 「**画出 X 的结构／投影图**」属**作答要求**（答案区才出现图），**不是 S1**。
2. 分三类：**真 S1**（图在卡内、位置错）／**题面图缺失**（图不在卡内任何位置）／**假阳性**（作答要求）。
3. ⚠️ **答案区重述题干**是机构域常见版式 ⇒ 同一句在题面与答案各出现一次，**锚点须限定题面区**。
4. 🔴🔴 **「题面图引用数 = 0」的计数必须含 HTML `<img>` 与 `$$` 公式**（2026-10-11 实测）——
   只数 Markdown `![](…)` 会把**题面图以 HTML 表格拼版**（`CM-12-07` 方向/X/Y 投影 6 图；`CM-17-02` 晶胞＋小立方体 A/B 3 图）
   或**以 `$$` 公式表示合成路线**（`CM-95-08`／`UChO-02-06`）的卡**误判为「题面 0 图」** ⇒ **假阳性**。
   ⇒ S1 伪命中后**必须先看题面区原始行**（含 `<table>`／`$$`）再定性，别只信计数。
5. 🆕 **真吞图附带同源残留**（2026-10-11）：题面区常残留 **破碎 math**（`CM-138-09` 的 `\begin{array}{l}…BrMgCHCHCH…`，未包 `$$` ⇒ 印字面）
   或 **OCR 碎片行**（`HYS-03-04` 的 `NOH OH /`）——搬图时一并清除。

**修复**：
| 类别 | 处置 | 硬约束 |
|:--|:--|:--|
| **甲·位置搬移** | 把图引用行从答案区**剪切**到题面区引用语句后 | 🔴 **图若带答案标注（「共N分」等）⇒ 禁止搬移，必须回源**；HTML `<table>` 行内图按**整行**处理、断言按**图数守恒**；同锚点多图会**顺序颠倒**（事后交换）；答案区文字给分点**不动** |
| **乙·回源裁图** | 源 PDF（`fitz` 高 dpi，200~300）裁图 → `images/<sha256>.jpg`（`git add -f` 入库）→ 插题面区 | 扫描件**无文字层** ⇒ 先用 `pdf_sheet.py` **拼图定位页**；⚠️ **L0 源 md 的「紧跟图」可能是水印**（须目检）；源卷缺图时**先全库检索同题异版本**（跨卡复用），再考虑回源 |

**验收**：题面区图 ≥1 且图文件实存；FM 严格解析 OK；`validate_kb` 0E0W；**池规模零漂移**；若卡在卷计划锁内 ⇒ 重出交付件。
