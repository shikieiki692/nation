# MD 通用规范：Word/PDF 共同最优子集

> **一句话**：两条管线核心相通，但不完全同口径。源 Markdown 统一按更严格的共同子集写，优先保证 Word 稳，再让 PDF 自然兼容。
> **定位**：本文档定义“源 md 应该怎么写”；结构样板看 [[11-模板/MD讲义格式参考（原子结构样板）]]，公式速查看 [[00-首页/Word友好 Markdown 符号速查表]]，编译流程看 [[11-模板/LaTeX PDF管线使用手册]]。

## 二、总原则

1. 先写自然正文，再判断是否需要数学模式。
2. 固定短记号优先 Unicode。
3. 复杂表达式必须整段放进一个 `$...$` 或 `$$...$$`。
4. 严禁“半截 math”，不要把一个最小记号拆成正文和公式两半。
5. 图片、图注、callout、表格只保留一套正式写法，不依赖历史兼容层。

## 三、共同最优子集写法

| 场景 | 统一写法 | 说明 |
|:---|:---|:---|
| 图片引用 | `![[media/xxx.png]]` | 正式图片只认 vault 根目录 `media/` |
| 图片宽度 | `![[media/xxx.png|420]]` | 需要控宽时显式写宽度 |
| 流程图/示意图 | `![[media/xxx.png]]` 或表格/步骤列表 | Mermaid 先转成最终图片，不把代码块留在讲义源稿里 |
| 图注 | `*图 1 对象 + 用途*` | 图注尽量纯文本、短说明 |
| 教学提示块 | `> **理解要点**：...` | 统一一行式 blockquote |
| 章节结构 | `##` / `###` / `####` | 不混用 HTML heading |
| 行内数学 | `$...$` | 一个最小公式一次性包完整 |
| 显示数学 | `$$...$$` | 复杂推导整段处理 |
| 化学式/反应式 | `$\ce{...}$` | `\ce{}` 放在数学模式里用 |
| 简单离子/简单上下标 | `Na⁺`、`S²⁻`、`H₂O`、`I₁` | 固定短记号优先 Unicode |
| 字母下标/变量下标 | `$K_p$`、`$K_c$`、`$K_{sp}$` | 不写裸下划线 |
| 轨道与群论标签 | `$e_g$`、`$t_{2g}$`、`$d_{xy}$` | 这类一律走数学模式 |
| 复杂角标/复杂排布 | `$4f_{x(x^2-3y^2)}$`、`$Z^{*}$` | 不用残缺 Unicode 硬凑 |
| 标准态热力学符号 | `$\Delta_\mathrm{r} H^\theta$`、`$E^\theta$` | 统一用 `\theta`/`θ`，不用 `°`/`\circ` |
| 正文箭头/趋势符号 | `→`、`↑`、`↓`、`≤`、`≥` | 纯解释句里可直接写 Unicode |
| 内链 | `[[页面名]]` | 两条管线都会各自预处理 |

## 四、公式边界

### 1. 直接写 Unicode 的范围

这些是共同子集里最稳的一类：

- `Na⁺`、`Cl⁻`、`Fe²⁺`
- `H₂O`、`NH₄⁺`、`SO₄²⁻`
- `2s²2p³`、`3d¹⁰4s¹`
- `I₁`、`I₂`

判断标准：

- 是固定短记号，不需要进一步推导。
- 上下标只含数字或简单电荷。
- 放在中文解释句里，希望阅读连续自然。

### 2. 必须整段进数学模式的范围

这些不要再写成正文 + 半截上下标：

- `$K_p$`、`$K_c$`、`$K_{sp}$`
- `$e_g$`、`$t_{2g}$`
- `$d_{x^2-y^2}$`、`$d_{z^2}$`
- `$4f_{+3}$`、`$4f_{x(x^2-3y^2)}$`
- `$Z^{*}$`
- `$\Delta_\mathrm{r} H^\theta$`、`$\Delta G^\theta$`

判断标准：

- 下标里出现字母、括号、正负号组合。
- 需要真正的公式排版，不只是符号展示。
- 是变量名、轨道标签、热力学记号、推导式。

### 3. 严禁写法

| 错误写法 | 问题 | 推荐改法 |
|:---|:---|:---|
| `Na$^+$` | 半截上标公式 | `Na⁺` 或 `$Na^+$` |
| `2s$^2$2p$^3$` | 一个排布被拆碎 | `2s²2p³` 或 `$2s^22p^3$` |
| `4f$_{+3}$` | 正文 + 空基底下标 | `$4f_{+3}$` |
| `2p$_0$` | 正文 + 空基底下标 | `$2p_0$` |
| `$I_1$(Na)` | 公式刚结束就黏正文 | `I₁(Na)` 或 `$I_1(\mathrm{Na})$` |
| `Z$^*$` | 半截上标公式 | `Z*` 或 `$Z^{*}$` |
| `K_p` | 裸下划线不会稳定渲染 | `$K_p$` |
| `e_g` / `t_2g` | 裸下划线不是正式下标 | `$e_g$` / `$t_{2g}$` |
| `ΔᵣH°` / `ΔG°` | PDF 能兜底，Word 共同规范不采用 | `$\Delta_\mathrm{r} H^\theta$` / `$\Delta G^\theta$` |

### 4. 标准态符号的专项规则

- 标准态上标统一写 `\theta` 或 `θ`，不要写 `°` 或 `^\circ`。
- 温度单位 `25 °C`、`100 °C` 仍可正常使用度数符号；这里说的是热力学标准态记号，不是温度单位。
- 如果同一句里既有正文又有热力学记号，优先把记号整段写成 `$...$`。

## 五、图片、图注与版面

### 1. 正式图片路径

- 只保留 `![[media/xxx.ext]]`
- 不再使用 `![[foo.png]]`
- 不在学生讲义中直接保留 `![[mineru/...]]`

### 2. 图注写法

- 图注统一为 `*图 N 对象 + 用途*`
- 图注尽量不写复杂公式
- 图注尽量不写长解释，长解释移回正文或写成 `> **读图提示**：...`

### 3. 图片使用习惯

- 同一张图不要重复摆放充版
- 并排图片应确实承担并列对比功能
- 文件名尽量稳定英文名，不新增 `Pasted image ...`

### 4. Mermaid 与流程图

- 学生讲义源 Markdown 不直接保留 ```` ```mermaid ```` 或 `~~~mermaid` 代码块。
- 不使用 `![[xxx.md]]` 把 Mermaid/笔记页面当成图片兼容引用。
- 正式交付写法只有两类：
  - 先渲染成最终图片，再引用 `![[media/xxx.png]]`
  - 直接改写成表格、步骤列表、判定清单
- 判断标准：如果它是“给学生看的成品讲义元素”，就不要把可执行图源码留在源稿里。

## 六、表格与结构

- 标题层级统一 `## / ### / ####`
- 表格对齐线统一 ASCII：`|:---|:---:|---:|`
- 表格单元格内继续遵守同一套公式边界
- 不把表格包进 blockquote
- 表头若只是固定标签，优先纯文本或稳定短记号，如 `I₁`、`电子排布`

## 七、PDF 能兜底，但不再继续扩散的写法

下面这些可能在 PDF 管线里还能编译通过，但不属于共同最优子集：

| 历史写法 | 为什么不继续扩散 |
|:---|:---|
| `<center>图 ...</center>` | 只是 PDF 兼容层，结构不统一 |
| `![[foo.png]]` | 路径不显式，后续 agent 容易误判 |
| ` ```mermaid ` / `~~~mermaid` | Word 会直接漏成代码，PDF/Word 共同子集不采纳 |
| `![[xxx.md]]` | 依赖历史兼容层，不是正式图片引用 |
| `K_p` / `e_g` / `t_2g` | Word 端最容易渲染失稳 |
| `ΔᵣH°` / `ΔG°` | 依赖 PDF 预处理兜底，不是共同口径 |
| 公式塞进图注长句 | Word/PDF 都容易在版面上出问题 |

> 历史稿如果已经手工修通，可以暂时不大规模回改；但新稿、重构稿、样板推广稿不要继续复制这些写法。

## 八、写稿自检清单

- [ ] 图片都写成 `![[media/...]]`
- [ ] 没有 ` ```mermaid ` / `~~~mermaid` 代码块
- [ ] 没有 `![[xxx.md]]` 这类历史嵌入
- [ ] 图注都是 `*图 N ...*`
- [ ] callout 都是 `> **标签**：内容`
- [ ] 没有 `Na$^+$`、`2s$^2$2p$^3$` 这类半截 math
- [ ] 没有 `K_p`、`K_c`、`e_g`、`t_2g` 这类裸下划线
- [ ] 标准态记号没有再写成 `°` 或 `^\circ`
- [ ] 表格对齐线是 ASCII，不是中文破折号
- [ ] 长解释没有塞进图注
