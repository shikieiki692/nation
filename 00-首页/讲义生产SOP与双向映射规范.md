# 讲义生产 SOP 与双向映射规范

> 定位：学生讲义与配套习题集是本库的主产出。本文是二者生产流程的单一事实来源。
> 配套阅读：[[学生讲义模板（v1.2 填充式）]]、[[MD通用规范（Word-PDF共同最优子集）]]、[[Word友好 Markdown 符号速查表]]、[[MD讲义格式参考（原子结构样板）]]、[[知识库治理待办]]。

## 一、总原则：源-派生分离

1. **内容只在一处写**。KP 正文归 [[首页|03-知识点]]，题目题干归 04-题库/05-真题库，教材提炼归 07-资料提炼，教学洞察归 12-教学洞察。讲义是「组织者」，不是「抄写员」。
2. **学生讲义正文必须自足**（v1.2 修订）：概念讲解完整写在正文，KP 链接只作锚点增强，不允许只链接不讲解；题目采用「题号链接 + 题干内嵌 + 解析」三件套，题号是溯源键不是内容替代品。「只引题号不抄题干」的口径仅适用于**习题集 md**（题库索引型文档）。学生讲义与习题集是两类文档，不得混用规范。
3. docx / PDF / 试印版全部是**派生物**，统一放 06-学生侧材料，可随时删除重新导出，删除不算损失。PDF 不进源目录。

## 二、讲义内容来源（多路汇聚）

一份讲义的素材按以下优先级汇聚，**不限于 KP**：

| 来源层 | 位置 | 角色 |
|---|---|---|
| 教材骨架 | 原书 + 07-资料提炼 提炼页 | 决定章节顺序与讲解主线（第一轮骨架=普化原理 + 高中化学竞赛笔记） |
| 知识点 | 03-知识点 | 原子化概念卡，讲义的概念锚点 |
| 教学洞察 | 12-教学洞察 | 讲法、比喻、易错预判、课堂节奏 |
| 专题页 | 04-专题与题型 | 题型归纳与解题策略 |
| 题目 | 04-题库（含教材习题实体：普化原理习题、上海中学竞赛教程习题等）+ 05-真题库 | 例题/练习/教材自测题的题号池；教材题一律链接题库实体，无实体先补实体 |
| 图片 | 见 §三 | 结构图、机理图、决策树等视觉骨架 |

frontmatter 必须交代来源（见 §四），做到「任何一段内容能回溯到出处」。

优先级补丁（SOP 试跑 v1.1）：**有备课大纲时以大纲为纲**。第一轮讲义的骨架实际由备课大纲 + 教学逻辑提炼决定，教材提炼页起校准作用；无大纲的讲次才以教材提炼页为主线来源。

## 三、图片资产规范（重点）

图片是讲义的第一等公民，与文字同等管理。

### 3.1 图片的三类来源

1. **教材提取图**：mineru 等管线从教材 PDF 提取（`mineru/`、各资料目录）。
2. **自绘图**：excalidraw / 流程图 / 关系图 / 决策图，以 md 包装（如 `00-首页/学生讲义Word/media/*.md`）。
3. **通用图库**：顶层 `media/` 目录的共享图片。

### 3.2 存放与引用规则

- 讲义引图一律用**相对路径**，禁止使用绝对路径；导出 Word/PDF 时 media 目录随讲义一并打包。
- 图片文件命名带语义：`主题-内容.类型.md`（自绘）或保留 mineru 原命名（提取图）；禁止 `img_8` 这类无语义命名新增（历史遗留不溯及）。
- 讲义 frontmatter 必须维护 `has_images` 与 `image_count`，与正文实际引用数一致（审计脚本以此校验）。
- 已知历史欠账：`mineru02/`、`高中化学竞赛笔记/`、`无机化学 习题集/` 三目录的图片相对路径待批量改写（见 [[知识库治理待办]] 结构专项），新讲义不得沿用这三处的旧路径写法。

### 3.3 图片发现（SOP 试跑 v1.1 新增）

- media 图库图片多按教材图号命名（如 `6-1-lgKp-T-NH3-synthesis.jpg`），按主题关键词 glob 必漏，容易导致新讲义「合规地无图」。
- 起草前**先查同主题存量讲义的图片引用作为候选池**（如化学平衡可查旧版引用的合成氨 lgKp-T 图），核实文件存在后复用。
- 找图基础设施已在：第一入口 [[00-首页/图片索引]]（精标表 + 主题分类 + `audit_image_index.py` 核验脚本），优先级规则见 [[00-首页/规则-配图来源优先级]]。起草时先查精标表与同主题存量讲义引用池，命中即复用；精标表与主题分类的增量充实属常态维护。

## 四、讲义 frontmatter 规范

在现有惯例字段基础上标准化（✳=新增）：

```yaml
---
title: 学生讲义-<主题>
type: 学生讲义
source_book: <主骨架教材，多本用分号>
chapter: <对应章节>
serve_rounds: [第一轮]
serve_topics: [主题词...]
difficulty_level: 基础~中等
related_notes:          # 链接：KP、备课大纲、专题页
  - "[[KP名]]"
sources:                # ✳ 教材提炼页链接（骨架来源）
  - "[[07-资料提炼/提炼-xxx]]"
insights:               # ✳ 教学洞察链接（可空）
  - "[[12-教学洞察/xxx]]"
problems:               # ✳ 本讲引用题号（双向映射主键）
  - "题-0123"
has_images: true
image_count: 10
stage: draft            # draft → reviewed → published → taught
template_version: 基础版 v3.0
created: YYYY-MM-DD
updated: YYYY-MM-DD
last_audit: <最近审计记录，可省>
---
```

- `stage` 口径：`draft` 起草 / `reviewed` 校验通过 / `published` 定稿可印 / `taught` 已上课（等反馈回写）。
- 教师侧管理信息（深度边界、使用建议、来源审计、课堂推进建议）只允许出现在 frontmatter 或 HTML 注释，**禁止进入学生可见正文**（v1.2）。
- 存量讲义不强制回填 `sources/insights/problems`，**新讲义必填**；老讲义在下次大修时补齐。

## 五、讲义 ↔ 习题双向映射

1. 讲义侧：`problems` 列出本讲全部引用题号（含例题与作业题）。
2. 题目侧：`used_in` 回填**不在起草时做**，集中在**定稿（stage→published）时由独立批次**完成（一次回填本讲全部题号，避免起草任务变成多文件写任务）。
3. **题号唯一性是硬前提**：`题-xxxx` 全库唯一。已知欠账：初赛讲义 4 个「题-001」、ABOC 约 20 对题面/答案拆页（见待办），未唯一化前这些题不进 `problems`。
4. 习题集 md 只组织题号清单（按节/难度分组），题干不复制；课堂用的「学生合集」允许嵌题全文，但由脚本从题库拼装生成，不手工抄。
5. 受益：改题改一处，讲义零改动；可反查「这道题被哪些讲义用过」「这份讲义的题来自哪些 KP」。

补充口径（SOP 试跑 v1.1）：题库里存在无 `题-xxxx` 题号的题目文件（如 `04-题库/化学原理/Ch06-化学平衡/06-33.md`，frontmatter 题号是「6.33」这类章节号）。这类题目**暂允许用全路径链接进 `problems`**（如 `[[04-题库/化学原理/Ch06-化学平衡/06-33]]`），批量补挂 `题-xxxx` 题号属结构专项欠账；补号完成后统一改回题号引用。

## 六、生产流程（8 步闭环）

```
1 备课思路      轮次/课时切分（备课思路/ 目录）定本讲目标与深度边界
2 汇聚取材      按 §二 表格收齐骨架教材提炼页 + KP + 洞察 + 候选题号
3 起草          agent 起草讲义源 md，严守三个模板文件；半截 math 零容忍
4 校验          validate 脚本 + build_link_map 查链接 + 人工抽查两节
5 定稿          stage→published，回填 problems 与题目 used_in
6 导出          docx/PDF → 06-学生侧材料（media 随行）
7 上课          试印/讲授，stage→taught
8 反馈回写      学生错题数据回写题库（难度校准、易错注记），反哺 KP 教学视角
```

- 第 8 步是第二轮相对第一轮的**新增环节**：学生实测错题是库外独有资产，回写后难度标注从「估的」变「实测的」。
- 每轮教学结束把本论讲义批量转 `taught` 并触发一轮反馈回写。

## 七、agent 协作与省 tokens 约定

- 批次作业走「索引文件 + 子代理 resume」模式；禁止任何 agent 逐文件重读全库。
- 统计一律脚本出 CSV，人与 agent 都看 CSV 不看原文。
- 校验用现成脚本（`11-模板/scripts/`），不重复发明。
- 单讲起草的 context 预算：备课大纲 + 骨架提炼页 + 涉及 KP + 候选题清单，其余一律链接不带全文。

## 八、验收清单（每份新讲义）

- [ ] frontmatter 字段齐（含 sources/problems/has_images/image_count）
- [ ] 图片全部相对路径且随包可导出
- [ ] 无半截 math、无高风险符号写法（对照 Word 速查表）
- [ ] build_link_map 复扫本讲链接零新增断链（入口：主代理或人在 Bash 跑 `python "11-模板/scripts/build_link_map.py" "C:\Obsidion\妙妙屋"`；待 kb_bash 白名单加只读 python 后 agent 可自跑）
- [ ] problems 中题号全部唯一且题目侧已回填 used_in
- [ ] stage 状态与实际一致
- [ ] 正文无教师向元信息（深度边界/使用建议/审计等只在 frontmatter 或 HTML 注释）（v1.2）
- [ ] 题量充足且每题随带解析（学生讲义三件套：题号链接 + 题干内嵌 + 解析）（v1.2）
- [ ] 机器可查：frontmatter `problems` 条数 == 正文例题+练习总数；`image_count` == 正文 `![[media/...]]` 数量（v1.2.1）
