# 讲义生产 SOP 与双向映射规范

> 定位：学生讲义与配套习题集是本库的主产出。本文是二者生产流程的单一事实来源。
> **权威声明（2026-09-11 收口）**：本文件 §四 是学生讲义 **frontmatter schema 的唯一权威**。
> `[[学生讲义模板（v1.2 填充式）]]` 自本次收口起定位为**写作细则**（推导/例题/图片/符号的写法），不再是规范权威；
> 两者冲突时以本文为准。历史背景与实测依据见 [[09-审计报告/学生讲义规范脱节审计与优化提案-2026-09-11]]。
> 配套阅读：[[学生讲义模板（v1.2 填充式）]]（写作细则：备课框架深度边界 + 写作前信息收集 + 完整写作规范）、[[MD通用规范（Word-PDF共同最优子集）]]、[[Word友好 Markdown 符号速查表]]、[[MD讲义格式参考（原子结构样板）]]、[[知识库治理待办]]、[[00-首页/规则-讲义质量检查清单]]。

## 一、总原则：源-派生分离

1. **内容只在一处写**。KP 正文归 [[首页|03-知识点]]，题目题干归 04-题库/05-真题库，教材提炼归 07-资料提炼，教学洞察归 12-教学洞察。讲义是「组织者」，不是「抄写员」。
2. **学生讲义正文必须自足**（v1.2 修订）：概念讲解完整写在正文，KP 链接只作锚点增强，不允许只链接不讲解；题目采用「题号链接 + 题干内嵌 + 解析」三件套，题号是溯源键不是内容替代品。「只引题号不抄题干」的口径仅适用于**习题集 md**（题库索引型文档）。学生讲义与习题集是两类文档，不得混用规范。
3. docx / PDF / 试印版全部是**派生物**，统一放 06-学生侧材料，可随时删除重新导出，删除不算损失。PDF 不进源目录。
4. **正文叙述去列表化与首行缩进（De-bulleting）**：正文核心原理、机理分析与定量推导一律采用连贯完整的学术自然段落（段落之间空行），**严禁通篇堆砌 `- ` 无序列表**。Word 管线自动为中文自然段注入 2 字符首行缩进（21pt），呈现出版社经典教材级质感。

## 二、讲义内容来源（多路汇聚）

一份讲义的素材按以下优先级汇聚，**不限于 KP**：

| 来源层 | 位置 | 角色 |
|---|---|---|
| 教材骨架 | 原书 + 07-资料提炼 提炼页 | 决定章节顺序与讲解主线（第一轮骨架=普化原理 + 高中化学竞赛笔记） |
| 知识点 | 03-知识点 | 原子化概念卡，讲义的概念锚点 |
| 教学洞察 | 12-教学洞察 | 讲法、比喻、易错预判、课堂节奏 |
| 专题页 | 04-专题与题型 | 题型归纳与解题策略 |
| 题目 | 04-题库（含教材习题实体：普化原理习题、上海中学竞赛教程习题等）+ 05-真题库 | 例题/练习/教材自测题的题号池；教材题一律链接题库实体，无实体先补实体 |
| 图片 | 见 §三 | 结构图、机理图、决策树等视觉骨架 |

frontmatter 必须交代来源（见 §四），做到「任何一段内容能回溯到出处」。

优先级补丁（SOP 试跑 v1.1）：**有备课大纲时以大纲为纲**。第一轮讲义的骨架实际由备课大纲 + 教学逻辑提炼决定，教材提炼页起校准作用；无大纲的讲次才以教材提炼页为主线来源。

## 三、图片资产规范（重点）

图片是讲义的第一等公民，与文字同等管理。

### 3.1 图片的三类来源

1. **教材提取图**：mineru 等管线从教材 PDF 提取（`mineru/`、各资料目录）。
2. **自绘图**：excalidraw / 流程图 / 关系图 / 决策图，以 md 包装（如 `00-首页/学生讲义Word/media/*.md`）。
3. **通用图库**：`媒体仓库/` 的哈希名共享图片。

### 3.2 存放与引用规则

- 讲义引图一律用**媒体仓库 64 位哈希名**：`![[<64位哈希>.jpg]]`，**不写子目录前缀、不写替代文本（alt）**（2026-09-11 修订，与 [[11-模板/学生讲义排版规范]] §5.1 对齐）。
  > 本条曾写作"一律用相对路径"，与排版规范冲突且已过期——全库实测哈希名 331 处、`media/` 0 处、`mineru/` 0 处，实践中早已收敛为哈希名，现将规范改到与实际一致。
- 存量 `media/`、`mineru/`、`06-外部资料导入/` 前缀与 184 处带 `|别名` 的引用为历史遗留，不溯及，随大修归一。
- 图片文件命名带语义：`主题-内容.类型.md`（自绘）或保留 mineru 原命名（提取图）；禁止 `img_8` 这类无语义命名新增（历史遗留不溯及）。
- 讲义 frontmatter 必须维护 `has_images` 与 `image_count`，与正文实际引用数一致（审计脚本以此校验）。
- 已知历史欠账（07-24 核实）：`mineru02/`、`高中化学竞赛笔记/`、`无机化学 习题集/` 三目录为原始数据存放目录，讲义中无引用，无需批量改写。新讲义引图一律从 `媒体仓库/`（哈希名）或同主题存量讲义引用池取，不从原始数据目录直接引用。

### 3.3 图片发现（SOP 试跑 v1.1 新增）

- media 图库图片多按教材图号命名（如 `6-1-lgKp-T-NH3-synthesis.jpg`），按主题关键词 glob 必漏，容易导致新讲义「合规地无图」。
- 起草前**先查同主题存量讲义的图片引用作为候选池**（如化学平衡可查旧版引用的合成氨 lgKp-T 图），核实文件存在后复用。
- 找图基础设施已在：第一入口 [[00-首页/图片索引]]（精标表 + 主题分类 + `audit_image_index.py` 核验脚本），优先级规则见 [[00-首页/规则-配图来源优先级]]。起草时先查精标表与同主题存量讲义引用池，命中即复用；精标表与主题分类的增量充实属常态维护。

### 3.4 图片 100% 视觉核验铁律（2026-09-25 升级）

- **五严禁**：严禁把公式/反应式误作为图片插入；严禁图注张冠李戴（杜绝伪 Latimer 图）；严禁模糊毛刺扫描图；严禁巨幅撑破版面图（单图统一 $\le 320\mathrm{px}$）；严禁未在 `媒体仓库/` 顶层落盘的孤儿引用。
- **四必备**：写入 `![[<哈希>.jpg]]` 前必须使用 `view_file` 视觉能力在磁盘上亲自查看图片内容，核验清晰度、微观结构立体键、坐标轴文字无失真；对比图/机理循环强制使用 2 列三线表并排（单图宽度 `|220|`~`|260|`）；必须配纯中文学术图注（禁复杂 LaTeX）；优先复用高清原生/矢量重绘资产。

## 四、讲义 frontmatter 规范

在现有惯例字段基础上标准化（✳=新增）：

```yaml
---
title: 学生讲义-<主题>
type: 学生讲义
tags: [化竞, 学生讲义, <主题>]
source_book: <主骨架教材，多本用分号>
chapter: <对应章节>
serve_rounds: [第一轮]
serve_topics: [主题词...]
difficulty_level: 基础~中等
related_notes:          # 链接：KP、备课大纲、专题页
  - "[[KP名]]"
sources:                # ✳ 教材提炼页链接（骨架来源）
  - "[[07-资料提炼/提炼-xxx]]"
insights:               # ✳ 教学洞察链接（可空）
  - "[[12-教学洞察/xxx]]"
problems:               # ✳ 本讲引用题号（双向映射主键）
  - "[[题-0123]]"       # 规范写法 = wikilink：只有 wikilink 才能反查「这道题被哪些讲义用过」
                        # 纯文本题号（"题-0123"）历史文件里仍有，校验脚本兼容，但新讲义不要写
exercise_count: <总题数>  # ✳ 练习题总数，统一 6~8 题、全部取自 04-题库（见 §四.1，v1.5 口径）
exercise_levels:         # ✳ 来源构成，纯文字，禁 emoji/特殊符号、禁难度分层（2026-09-24 收口）
  - "题库卡 7（上中·卤族元素）"
  - "初赛真题卡 1"
has_images: true
image_count: 10
stage: draft            # draft → reviewed → published → taught
template_version: 基础版 v3.0         # 格式：<类型> vX.X，类型见命名约定
                                        # 现有类型：自学完整版 / 基础版 / 教师增强版 / 超级充实融合版 / pipeline
                                        # 与 version 字段不重复：template_version 标识模板版本，version 标识内容版本
created: YYYY-MM-DD
updated: YYYY-MM-DD
last_audit: <最近审计记录，可省>
---
```

- `stage` 口径：`draft` 起草 / `reviewed` 校验通过 / `published` 定稿可印 / `taught` 已上课（等反馈回写）。
- 教师侧管理信息（深度边界、使用建议、来源审计、课堂推进建议）只允许出现在 frontmatter 或 HTML 注释，**禁止进入学生可见正文**（v1.2）。
- 存量讲义不强制回填 `sources/insights/problems`，**新讲义必填**；老讲义在下次大修时补齐。

### 四.1 统一口径（2026-09-11 收口，实测依据见 [[09-审计报告/学生讲义规范脱节审计与优化提案-2026-09-11]]）

此前同一口径在三份文件里各说各话，现统一如下，**其他说法一律作废**：

| 项 | 统一口径（2026-09-24 v1.5 修订） | 作废的旧说法 |
|:---|:---|:---|
| **练习题量** | **6~8 题**，**全部取自 `04-题库/`**，每题标来源并回链题卡；题库无合适题时宁缺毋滥 | ⛔ **原「25 题（10+9+6）」作废**（与语言规范 v1.3 §6.4 冲突）；模板 v5.3「5+5+5=15」；SOP 旧版「≥12 理想≥23」 |
| **练习题组织** | **连续编号、平铺一节**；可按**来源**分组标注；**禁止按难度分层**（无「基础巩固/竞赛入门/真题挑战」小标题） | ⛔ 原「分级术语＝基础巩固/竞赛入门/真题挑战」作废 |
| **题面完整度** | 内嵌题面须可脱离链接独立作答；禁「一句话概括＋完整题面见……」半截题；>60 行真题只留延伸阅读回链 | — |
| **特殊符号** | 分级与难度标记**一律不用 emoji、不用特殊符号**；仅深度分层保留 📝🌟🔒 | 🌱🔥🏆；⭐ 星级 |
| **难度标记** | `difficulty_level` 统一**文字档**：`基础` / `基础~进阶` / `进阶` / `进阶~挑战` / `挑战` / `竞赛综合` 等 | `⭐⭐~⭐⭐⭐⭐` 星级；`第一轮~第四轮` 轮次充当难度 |
| **图片路径** | `媒体仓库` 64 位哈希名，无 alt | SOP 旧版「相对路径」；`media/` `mineru/` 前缀 |
| **本讲小结** | **必写**（唯一强制的收尾节） | — |
| **认知冲突 / 易错清单** | **改为可选**：新建讲义建议写，存量缺的不补 | v5.3「每讲必设」「≥3 条」 |

> **为什么本讲小结必写、另两节改可选**：全库实测认知冲突 5%、易错清单 3%、本讲小结 26%——强制要求一个 97% 存量都不满足的项，等于规范失效。骨架构型见 [[11-模板/学生讲义内容结构规划]] §七。

## 五、讲义 ↔ 习题双向映射

1. 讲义侧：`problems` 列出本讲全部引用题号（含例题与作业题）。
2. 题目侧：`used_in` 回填**不在起草时做**，集中在**定稿（stage→published）时由独立批次**完成（一次回填本讲全部题号，避免起草任务变成多文件写任务）。
3. **题号唯一性是硬前提**：`题-xxxx` 全库唯一。初赛讲义题号唯一化与 ABOC 拆页合并已闭环（07-23）。新欠账：题库多题文件分题锚点问题（如题-051 一个文件装7题，讲义 `problems` 无法精确到题，需拆题规范）。
4. 习题索引 md 只组织题号清单（按节/难度分组），题干不复制；面向学生的独立练习题组（`type: 题组`，参见 `[[11-模板/模板-习题组]]`）允许嵌题全文；课堂用的「学生合集」也可由脚本从题库拼装生成，不强制手工抄。
5. 受益：改题改一处，讲义零改动；可反查「这道题被哪些讲义用过」「这份讲义的题来自哪些 KP」。

补充口径（SOP 试跑 v1.1）：题库里存在无 `题-xxxx` 题号的题目文件（如 `04-题库/化学原理/Ch06-化学平衡/06-33.md`，frontmatter 题号是「6.33」这类章节号）。这类题目**暂允许用全路径链接进 `problems`**（如 `[[04-题库/化学原理/Ch06-化学平衡/06-33]]`），批量补挂 `题-xxxx` 题号属结构专项欠账；补号完成后统一改回题号引用。

### 5.1 校验脚本（2026-09-02 落地）

```bash
python .workbuddy/scripts/check_lecture_problems.py                 # 全量
python .workbuddy/scripts/check_lecture_problems.py --list-unresolved # 列不可解析明细
python .workbuddy/scripts/check_lecture_problems.py --strict          # 历史欠账也算失败
```

严重度对应「新讲义强制 + 历史不动」：

| 级别 | 触发条件 | 处理 |
|:--|:--|:--|
| ERROR | 新讲义（`created >= 2026-09-02`）`problems` 缺失 / 为空 / 指向不存在的题目 | 必须修，退出码 1 |
| WARN | 历史讲义的 `problems` 不可解析 | 已知欠账，不阻塞 |

**为什么按 `created` 切而不是按 `stage`**：若按 `stage=published` 强制，当前 84 份已定稿的
历史讲义会一次性变红，与「存量不强制回填」冲突。按 `created` 切则新讲义为 0、脚本绿灯，
规则只对未来生效。口径可用 `--since` 调整。

**已知欠账（2026-09-02 实测）**：217 份讲义里 22 份有 `problems`，共 148 条引用，
其中 **38 条（25.7%）解析不到**：

- 7 条是编号多了一层（讲义写 `题-039-1-1-雄黄…`，实际文件是 `题-039-1-雄黄…`），降一级即可修；
- 31 条讲义写的是**讲次内部自造编号**（如 `37届Q5-NO与H2S反应`、`38届Q1-炼丹元素推断`），
  与题库文件名无关，需人工对应，或等 §五.3 的拆题规范落地；
- 另有 1 条是没填的模板占位符 `题-NNN`。

结论：`problems` 此前是人工手写且从未校验过，属于 §五.3 记载的同一笔欠账的两个表现。
新讲义有了校验脚本后不会再新增，存量建议随下次大修逐讲清理。

## 六、生产流程（双轨闭环）

### 6.1 新写线（从零创作，9 步）

```
1 备课思路      轮次/课时切分（备课思路/ 目录）定本讲目标与深度边界
1b 定考纲       取 02-考纲条目/ 本讲域条目 + 04-课件/备课大纲/ 对应备课记录，定「必须讲/可讲/不讲」三档（教材规范 §4.0）
2 定源          FM source_book/sources 定位本讲全部对照教材**原文**文件（06-外部资料导入/**、mineru/03-教材书籍/**）
                ⚠ 只认原文；07-资料提炼/ 与 B 类笔记仅作检索线索，**且禁止进入 FM sources**（语言规范 §15.3、§22.4）
3 原文扫描      原文逐节扫描出考点清单（含例题、脚注、边栏——初赛命题常取自边栏）
4 起草          agent 起草讲义 md，严守三个模板（[[学生讲义模板（v1.2 填充式）]] + [[学生讲义内容结构规划]] + [[学生讲义排版规范]]）
                同步起草**覆盖对照表**（原文考点 × 现状 有/部分/无，格式见语言规范 §17）
5 校验          validate 脚本 + build_link_map + 语言规范 §10 机检 + render_gate
  ↓ 通过标准：validate 0 error、build_link_map 零新增断链、render_gate PASS、练习题 100% 源自题库；warning 定稿前清零
6 定稿          stage→published，回填 problems/used_in/exercise_count；覆盖对照表归档 09-审计报告/
7 导出          docx → 06-学生侧材料/讲义/<模块>/（media 随行）；产出后核验落位目录与文件名（语言规范 §19）
8 上课          试印/讲授，stage→taught
9 反馈回写      学生错题数据回写题库（难度校准、易错注记），反哺 KP 教学视角
```

- 第 9 步是第二轮相对第一轮的新增环节：学生实测错题是库外独有资产，回写后难度标注从「估的」变「实测的」。
- 每轮教学结束把本论讲义批量转 `taught` 并触发一轮反馈回写。

### 6.2 存量重建线（按原文级重建，逐份闭环）

> 工序详情见《[[11-模板/讲义语言规范·执行手册]]》§一（精改档 12 步）；此处只记与生产线的接口。

```
① 定源（FM sources/last_audit 定位原文文件，原文缺失则降级「不可对照」并登记）
② 原文通读 → ③ 覆盖对照表（逐节 有/部分/无）→ ④ 补写（挂原文路径锚点）
⑤ 语言轨 + 纯净度轨（伪标签/元信息/口诀/类比/emoji 清零）
⑥ 练习题题库化（§6.4）→ ⑦ 存疑登记（语言规范 §18）
⑧ 三闸门（js-yaml ／ validate_kb ／ render_gate）→ ⑨ docx 重出并核验
⑩ 四件套提交（md＋docx＋覆盖对照表＋执行手册台账行）→ ⑪ 同篇一致性 grep → ⑫ 台账回写
```

**两线共用铁律**：① 一批一讲，交付四件套齐全；② 存疑不改数、一律登记；③ 提交后用 `diff-tree --name-only` 核对条数，主索引对齐（D=0）。

### 9.2 冲突裁决顺序

1. **先查样本**：同类问题在库内已有达标件时，以达标件的实际做法为准（语言规范 §15.5 标杆件、语体参照样本）；
2. **层归属**：语言/内容判据 → 语言规范；结构/字段/命名 → 本 SOP；工序步骤 → 执行手册；**流程顺序与质量评判 → 流程总纲（地基件）**；
3. **新旧对抗**：同一层内以**版本号更高者**为准，并在执行手册 §五 判例库登记「旧条目作废」；
4. **事实层**：数值/机理冲突以**可复算数据**为准（语言规范 §18），无法判定时标存疑不猜；
5. 裁决结果必须回写执行手册台账/判例库，禁止只在对话里说。
