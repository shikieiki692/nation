# 题库入库闸门

> [!success] 核心原则
> 新题必须“字段合规后入库”，不再允许“先入库、后补字段、后登记”。本页规则由 `.workbuddy/scripts/question_intake_gate.py` 自动检查。

## 一、适用范围

- 新增或批量导入 `04-题库/`、`05-真题库/` 的题目文件；
- 对现有题库执行健康检查；
- 修复旧题后进行回归验证。

非题目型 Markdown 会被跳过，不计入题目缺陷。

## 二、必填字段

| 字段 | 要求 | 作用 |
|---|---|---|
| `type` | `题目` 或 `真题` | 决定题目归类与统计口径 |
| `source` | 非空字符串 | 追溯教材、真题或原始来源 |
| `status` | `active`、`deprecated` 等受控值 | 控制可用状态与弃用收口 |
| `subject_module` | 非空字符串 | 标记学科模块，支撑检索与课程映射 |
| `teaching_level` | 非空字符串 | 标记教学层级，防止题目跨层误用 |

建议但暂不阻断写入的字段：

- `title`；
- `qid` / `question_id` / `id` 任一题号字段；
- `used_in` 消费登记。

## 三、弃用收口

当 `status: deprecated` 时，必须至少提供一项：

- `superseded_by`：替代题目的文件或稳定标识；
- `deprecation_reason`：明确弃用原因。

禁止只改状态而不留去向或原因。若替代关系成立，应在替代题上保留必要的反向说明，避免知识链断裂。

## 四、题号唯一性

- 同一批次内 `qid`、`question_id`、`id` 不得重复；
- 重复题号会阻断 `--strict`；
- 当前全库重复题号为 **0**，新批次必须继续保持为 0。

## 五、消费闭环

`used_in` 用于记录题目被哪些讲义、卷组或训练材料消费。其状态应是可判断的：

- 已用于具体产物：填写目标链接或名称；
- 已评估但暂不使用：明确标记为“未使用”；
- 尚待判断：标记为“候选”。

长期空值会让题库无法回答“这道题为什么存在”，因此 warning 必须进入治理清单，不能无限堆积。

## 六、执行命令

新题入库前：

```powershell
python .workbuddy/scripts/question_intake_gate.py --strict "04-题库/.../新题.md"
```

全库健康摘要：

```powershell
python .workbuddy/scripts/question_intake_gate.py --json
```

需要完整问题清单：

```powershell
python .workbuddy/scripts/question_intake_gate.py --full
```

只有 `--strict` 返回退出码 `0` 的新批次才能正式入库。

## 八、验收条件

1. 新增批次在 `--strict` 模式下退出码为 `0`；
2. 关键字段五项均通过；
3. `deprecated` 文件均有 `superseded_by` 或 `deprecation_reason`；
4. 重复题号保持为 `0`；
5. `used_in` 不再为空，至少处于“候选 / 已消费 / 未使用”之一；
6. 存量问题纳入分批修复，并在 [[00-首页/指标事实源]] 更新剩余数量。
