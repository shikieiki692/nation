## 二、关键经验教训

### 1. Agent的边界——最核心的教训

| 问题 | 原因 | 解决方案 |
|:---|:---|:---|
| Agent消失/丢失 | 任务范围过大，超出上下文 | **缩小范围**，10-15文件/Agent |
| Agent报告虚假结果 | 大量文件读取时上下文溢出 | **关键结果必须手动验证** |
| Agent全库扫描卡死 | 3500+文件一次性扫描 | **用Grep/Glob做定向搜索**，不用Agent遍历 |

**核心原则**：Agent擅长"处理已知文件列表"，不擅长"发现未知文件列表"。
- 发现问题 → 用 Grep/Glob（快10倍）
- 处理文件 → 用 Agent（需要理解上下文）
- 批量修改 → 用 PowerShell（一次执行）

### 2. PowerShell批量操作——先测后跑

```powershell
# ❌ 错误：正则没考虑updated出现在frontmatter中间
(Get-Content $f) -replace '(?m)^---\r?\n(.*?)updated:.*?---', '$1---'

# ✅ 正确：逐行处理，只保留第一个updated
$lines | Where-Object { $_ -notmatch '^updated:' -or ++$count -eq 1 }
```

**教训**：先5个文件测试 → 确认 → 全量执行 → 二次扫描验证

### 3. 审计方法论——三轮递进

- **第一轮**：6个并行Agent各扫600文件 → 浅但广，发现表面问题
- **第二轮**：针对标记"有问题"的文件深入验证 → 发现遗漏和误报
- **第三轮**：Grep/Glob全文搜索（断链、空字段、重复内容）→ 补盲区

**比一轮全覆盖更有效**——浅→深→补盲区。

### 4. 工具选择矩阵

| 场景 | 推荐工具 | 原因 |
|:---|:---|:---|
| 单文件精确编辑 | `kb_edit` | 自动标记脏模块、原子操作 |
| 批量100+文件同类修改 | PowerShell | 一次执行，不需逐文件调用 |
| 搜索/发现文件 | Grep / Glob / `kb_search` | 比Agent扫描快10倍 |
| 内容创作/填充 | Agent（限定文件范围） | 需要理解上下文 |

### 5. 命名冲突根治流程
1. `crossref` 查所有引用该文件的地方
2. 更新引用 → 验证目标文件存在
3. 导航文件中编号要连续，删一行修序号
4. 删除空壳文件

## 四、可复用的工作流模板

### 批量KP元数据补全
```
1. Grep/Glob 发现缺失文件列表
2. PowerShell 写批量脚本
3. 5个文件测试 → 确认无误
4. 全量执行 → 输出统计
5. 二次扫描确认0遗漏
```

### 题型骨架批量填充
```
1. 确认骨架文件列表（status:骨架）
2. 按10个/组分配给并行Agent
3. 每个Agent读取文件+填充模板内容
4. 汇总验证：status字段是否全部更新
```

### 系统文件标准化
```
1. 列出所有系统文件（type:系统/工作日志/任务卡）
2. 检查必填字段（title, type, tags, updated）
3. 批量补全缺失字段
4. 交叉验证Dataview查询能正确聚合
```
