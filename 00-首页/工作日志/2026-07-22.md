## 六、kb-vault-mcp Windows 化与状态安全修复（当日第三会话，Task task-1784740196740-qiknngb）

**背景**：总报告第九节定位的 MCP 缺陷——kb_search/kb_move/kb_index/kb_delete 依赖 unix grep/find/wc，Windows 下全静默失效；kb_delete 软弃用保护（P0）因此不触发；checkpoint 非原子写入且恢复丢失 readRegistry；console.log 污染 stdio。

**修复内容（src/ 10 文件，版本 2.0.0/2.2.0 → 统一 2.2.1）**：

| 文件 | 修复 |
|:---|:---|
| kb_search.ts | grep/glob 改纯 Node 遍历（自写 globToRegExp，零新依赖）；顺带修 column 恒 0、glob 的 scope 参数无效两小 bug |
| kb_move.ts | findReferences 改纯 Node；顺带补上原 grep 漏写的 exclude（不再扫进 trash 快照） |
| kb_index.ts | rebuild 改纯 Node；totalFiles 语义改为真实 .md 总数 |
| kb_delete.ts | getRefCount 改纯 Node——**MAINTAIN 软弃用保护恢复生效**；frontmatter 正则兼容 CRLF；补排 node_modules |
| state/manager.ts | checkpoint 改原子写（tmp+rename）；rotation 后立即回写最新快照消除恢复空窗；readRegistry 入 checkpoint 并恢复（旧格式向后兼容）；损坏行跳过；incrementReworkCount 加预留注释 |
| hook-runtime.ts / orchestrator.ts | 6 处 console.log 全改 stderr，stdio 只留协议帧 |
| kb_bash.ts | 重定向正则收紧：>两侧空格可选也能拦截，2>/&> 写文件被拦，2>&1/>=/heredoc 不误判 |
| kb_gate.ts | archive 守卫收紧为仅 CLOSING（与迁移表一致），死代码清理 |

**验证**：项目无 tsconfig.json（npm run build 本就不可用的隐疾），用 Kimi 桌面端自带 node + CLI 参数 tsc 全量编译零错误；node 直跑烟囱测试：grep 39 命中、glob 定位准确、**kb_index rebuild totalFiles=5350 / totalLinks=85647（前一 session 被清空的反向索引已重建）**、crossref 229 引用。

**生效条件**：运行中的 MCP 进程仍是旧 dist，需重启 Kimi 桌面端（或重载 MCP 连接）后新代码生效。生效前 kb_search 仍是旧行为。

**遗留（审计外新发现，未改）**：kb_move.fixReferences 只替换精确 `[[fromName]]`，带别名/路径/锚点的引用检测得到但修不了；crossref 缓存键只按裸文件名精确匹配（fallback 已正常）；getRefCount 计入自引用（与原行为一致）。
