## 十七、「只有 id」证实：我的第二次误判 ＋ 鉴权机制真相

owner：「MinerU 客户端没有API Token，只有id」⇒ **owner 是对的，我上轮又错了**。

### 17.1 🔴 那 96 字符不是 token，是**设备 ID**

客户端源码（`out/main/index.js`）的生成算法：
```js
const SECRET_KEY = Buffer.from('1234567890abcdef1234567890abcdef');
const IV = Buffer.from('1234567890abcdef');
function generateToken(mac, version) {
    const cipher = createCipheriv('aes-256-cbc', SECRET_KEY, IV);
    let token = cipher.update(mac + version, 'utf8', 'hex');
    return token + cipher.final('hex');        // ← 96 hex
}
```
**明文 ＝ MAC 地址 ＋ APP_VERSION**，密钥/IV 是**硬编码公开常量**。
config.json 里的 `client_api_token` 正是这个 ⇒ 字段名叫 token，**实际是设备标识**。

### 17.2 真实鉴权三要素

| 要素 | 内容 |
|:--|:--|
| **免登录白名单** | `["/users/current","/users/logout","/users/auth"]`（`NPn=[200,0]`） |
| **登录入口** | `POST /api/v4/users/auth` ⇒ **手机号 ＋ 验证码** ⇒ 换**账号 Cookie** |
| **业务调用** | `token` 头（＝设备ID）＋ **Cookie**（登录态），`code==0` 判成功 |
| **错误文案** | 客户端自带：`token已过期，请重新登录 或者 最新api token` |

⛔ **API 侧不存在「长期 API Key」** ⇒ 我上轮说「去设置页刷新 API Token」是**错的**，
客户端**根本没有那个入口**。

### 17.3 🔴 本轮停止的位置：安全边界

继续往下要**代填手机号＋收验证码＋登录** ⇒
