## 三、陈旧 docx 复核（判据升级 —— 本轮最重要方法学收获）

**问题**：`_数学工具/` 有 5 份 docx 的 `mtime < md.mtime`，看似全部陈旧。

**判据升级**：
- `docx.mtime < md.mtime` **只是「候选」** —— 改 frontmatter（如 `related:` 链接）会抬高 md mtime 却**不改产物正文** ⇒ **假陈旧**。
- **真陈旧判据 = 重渲染后 `word/document.xml` 有差异**；`core.xml`（时间戳）/`styles.xml` 逐份必不同，是**噪声**，不得作判据。
- 实现：`zipfile` 读 `word/document.xml` 做逐字节比对。

**实测结果**：5 候选 → **真陈旧 2 / 假陈旧 3**。

| 文件 | 结论 | 实际差异 |
|:---|:---|:---|
| `_数学工具/数学工具-第5讲-偏导与全微分.docx` | **真陈旧** | `a/V_m2` → `a/Vm2` |
| `_数学工具/数学工具-第6讲-量纲数量级与估算.docx` | **真陈旧** | `顺带看出` → `由此亦可看出` |
| 其余 3 份 | 假陈旧 | `document.xml` 逐字节一致 |

**全量兜底**：84 份在役 md（133 产物）逐份重渲染比对 → **真陈旧 0 / 一致 82 / 无 docx 2**，证明**全库讲义产物与 md 源 100% 同步**。**提交** `fc4460695`（2 files）。

```
17:11:54  并行线  git reset --soft HEAD~1        ← 217 项全部退回 index
17:11:56  并行线  git commit -F msg -- <28 路径>  ← 只写回自己的 28 项
          → 新 HEAD 03ecf13aa
          → ✗ 本会话 189 项永久掉出 HEAD
```

**并行线的推理**：「只 commit 自己的 28 项，其余暂存原样保留 → **零损失**」。
**错在**：`reset --soft` 已把 index 与 HEAD 一起回退，那 189 项**只存在于 index，不在 HEAD**；随后的路径限定提交只写回 28 项，189 项**再没人写回**。

**双方当时认知**：并行线认为「189 项仍在 index = 原状保持」；本会话认为「已入库」。**互相以为对方安全**。

**为什么 `git status` 看不出来**：`reset --soft` 不回退工作区 → 文件内容与 index 一致 → **status 一片干净**。

**发现路径**：收官复核时**比 blob 哈希** `git hash-object <f>` vs `git rev-parse HEAD:<f>` → 5 个关键文档**对不上** → `git merge-base --is-ancestor dd777a207 HEAD` → **NO**（已出链）→ `git reflog` 看到 `785dddb08 ← reset --soft ← dd777a207`。

**无损验证三连（全通过）**：① `dd777a207` 有 / HEAD 无的 **165** 项，工作区**缺失 0**；② 各项与 `dd777a207:<路径>` 的 blob **不一致 0**；③ HEAD 有 / `dd777a207` 无的 **161** 旧路径，工作区**仍存在 0**（移动真实生效）→ **工作区 100% 完好，仅 index+HEAD 丢**。

**恢复**：`git add -A -- "04-课件/习题集/"` + 逐项 add 4 份关联文档 → 核暂存范围「22 关联 + 167 习题集，**零外部混入**」→ `git commit -F msg` → **`dba248f4a`，189 files**：`R100×158 / R096 / R095 / R070 / A4 / M24`，与 `dd777a207` 等价。

**新铁律（第三条 git 纪律）**：
1. **`reset --soft` 不是"零损失"** —— 它把 index 与 HEAD **一起**回退，若 index 中混有他会话改动，这些改动会**随重做提交一起消失**。
2. **执行 `reset --soft` 前必须逐项确认 index 归属**（`git diff --cached --name-status -M`）。
3. **见到陌生暂存项，正解＝保留 index + `git commit -F msg -- <自己路径>`**，**永不 reset**。
4. **收官前必比 blob 哈希**（`hash-object` vs `rev-parse HEAD:<f>`）—— 这是唯一能发现「自己的改动被他人 reset 挤掉」的手段；`git status` 干净**不等于**已入库。
