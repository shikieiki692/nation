## 〇、这条线在做什么（判断标准）

同一份 md 经**三条出口**产出，任一条渲染失真都算缺陷：docx 线 `11-模板/scripts/build-all-handout-docx.py`、PDF 线 `11-模板/scripts/convert_handout_to_pdf.py`、QA 诊断工具 `11-模板/scripts/qa/*.py`（3 个，方言与产线不一致）。

核心难点：**「渲染失败」有闸门，「渲染不对」没有**。前者（残留字面美元符、texmath 转换失败）`render_gate.py` 能拦；后者文本一模一样但渲染结果错，只能靠「源 vs 渲染产物」按**结果**比对（判据须独立于被验收对象）。

## 四、纪律要点（接手必看）

- 环境：脚本/闸门用 managed Python 3.13.12；**PDF 线必须用系统 Python 3.12**（managed 3.13 无 pypdf，会把「结构校验失败」误报）。
- 普查 pandoc 调用点**禁用 git grep**（ignore 盲区，本库实测第一遍只捞到 1/5）→ 用全盘搜索，再用 `git ls-files` 分已跟踪/未跟踪。
- 「未推送数」**只信 `git ls-remote origin master`**（本库 refs/remotes/origin 整只目录缺失，`origin/master..HEAD` 会虚报）；推送成功判据＝远端 tip == 本地 HEAD；**本线默认不代推**。
- 改生成器/转换器后必须**换维度复跑**（拿含括号/系数/结晶水/同位素的典型式跑真实输出）——这是唯一能抓「渲染不对」的招。
- 红区 `04-题库/`、`05-真题库/`、`_归档/` 禁碰；`.workbuddy/memory/*` 一律不提交。
