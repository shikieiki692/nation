# 习题书 V2：内容瘦身与排版迭代计划

> **目标**：把四篇 31 章习题书收敛成可长期迭代的正式版——正文只保留完整题目、完整解析、适当拓展/相关知识点，另可保留来源与知识点；图片位置明确；表格排版稳定；后续加新题或优化内容时能用同一套流程重生成、重校验、重出 Word。

### 1.2 问题一：成书携带大量非白名单教学块

教师版扫描到约 2,016 处“非白名单”行命中，分布在与教学注释相关的块标记上：

学生版同样携带 `小问关联` 271 处；部分 `相关图片`、无标题知识点残块也会进入学生版。

根因在生成器，不在成书本身：

- `11-模板/scripts/build_module_book.py` 的 `clean_section_text()` 只清理普通 wikilink、dataview、H2 降级和图片归一化，没有按块过滤教学注释。
- `split_question_answer()` 把 `解题思路 / 知识点映射 / 易错分析` 当作答案入口，处理时会吞掉标题但保留正文，因此成书里常出现无标题的 `- 知识点 · ...`、`1. 读题定位 ...`、`### 解题思路1. ...` 残块。
- 源文件 `## 题目`、`## 参考答案` 与后续文字挤在同一行（如 `## 题目> 来源：...`）时，标题层级也会错乱。

### 1.3 问题二：图片“在”但位置错

图片资产没有缺，但语义归属不可靠，典型证据：

- `04-题库/真题/第39届初赛/有机化学/题-039-8-2-α-氟代羰基构象分析.md` 第 32 行出现 `---![[...]]![[...]]`，图片紧贴题干文本和横线；教师版 `第三篇-有机化学/2-立体化学.md` 约 4674 行同源复现。
- 多届决赛源文件在 HTML `<td>` 内放 `![[哈希.jpg]]`，例如 36 届决赛 `题-36决理-2-7-明星分子的配位作用.md` 第 27、66 行，37/38/39 届决赛亦有同型写法。
- 教师版原残留 27 个 `<img src="images/...">`（集中在结构篇 5 个章节，多位于 HTML 表格单元格内）；2026-08-30 批 B 已全部归一化为 `![[哈希名.jpg]]`，复审计 `html_img=0`。
- 全量扫描到约 200 处高风险行：图片贴文本、多个图片同行、`---![[`、`<td>` 内嵌图、`相关图片` 块内无归属堆图。

### 1.4 问题三：HTML 表格与排版不稳定

- 教师版 11 个章节共 66 个 HTML `<table>`（其中 14 个单元格使用 `colspan/rowspan`）；批 B 后剩余 56 个（`colspan/rowspan` 7/4）。

- 表格单元格同时混有裸公式、`<br>`、图片，不能直接走稳定的 Markdown pipe table。

### 1.5 问题四：Word/公式预检警告未清零

### 1.26 大题合并方案与风险

- 推荐做法（不改 586 个源文件）：**生成器在构建时按 `题-XXX-Y` 前缀分组**，归一输出一道“大题”，题干取共同题干 + 各小问，答案按小问分块；保留每小问的难度/KP 到小问级。
- 需处理：小题文件常各自重复大题题干——首个小问作共同题干，其余小问只保留差异语句；难度取组内最高或聚合；source-map 由“每小问一条”改为“每大题一条 + 小问清单”。
- 风险：生成器改动较大、映射/门禁口径变化、Word 单题页变长；需先在 1 个大题（如 27 届 2-x）做 A/B 试点，验证题数、图片、答案完整性后再全量。

## 二、方案原则

1. **内容白名单化**：成书只保留 `题目 / 解析 / 适当拓展 / 来源 / 知识点`；教学注释保留在源文件侧，但不再进入成书。
2. **先审计后过滤**：`相关图片`、`解题思路`、`易错分析` 中可能藏有原题必需图，不能直接删块，必须先做图片归属审计。
3. **源文件与生成器分层治理**：源文件负责语义正确，生成器负责统一呈现；同一问题优先修生成器，特殊情况才修源文件。
4. **题数/图片/表格三条基线不可倒退**：每阶段结束时 1,685 题、答案块、媒体缺失 0、Word 严格图片校验必须保持。
5. **迭代闭环**：加新题 = 改源文件 → 重生成 → 自动校验 → 重出 Word，全流程可重复、可对账。

## 五、风险与待定决策

1. **过滤顺序风险**：先删 `解题思路/知识点映射/易错分析` 可能改变答案切分点。必须用 A/B 差异报告校验题干和答案，不能只看题数。
2. **图片误删风险**：`相关图片` 块里可能混有原题图。Phase 2 必须在 Phase 1 全量过滤前完成，或两者同批逐张核对。
3. **题号稳定性**：当前生成器按章内难度排序后连续编号，加新题会使后续题号漂移。默认方案用源文件映射清单追踪；如希望印刷版题号永久稳定，需在 Phase 5 前单独决策是否改为稳定 `source_id` 排序。
4. **HTML 表格边界**：`colspan/rowspan` 不能无损转成普通 pipe table，需要逐表人工决策拆表或改版式；建议把剩余 56 个表格先按“可转/需拆/需改版式”三档分类。
5. **教师参考内容去向**：默认保留在源文件侧，不进成书；若以后要出独立“教师教学版”，可基于源文件另行生成，不影响本计划。
