# 任务卡-git 仓库膨胀治理（.git 12 GB → 4.3 GB）

> **状态：已完成（2026-09-13）**
> 归属：基础设施 / 运维（非知识库内容线）
> 诊断报告：[[.workbuddy/backups/pre-gc-20260913/诊断报告-20260913]]
> 工作日志：[[00-首页/工作日志/2026-09-13]]

## 一、问题

`.git` 从 3.9 GB 反弹至 **12 GB**，pack 从 4 个变成 10 个，C 盘可用余量一度只剩 12 GB。

## 二、根因

**12 个畸形 pack（malformed pack）**：`.idx` 中有对象 SHA 登记，但 `.pack` 中**无实体数据**。
识别特征：**对象数极少（0~563）但体积巨大（1.6 MB~2.75 GB）**，且其对象全部 `git cat-file -e` 失败。

## 三、🔴 方法论修正（决定性）

| 判据 | 可信度 | 原因 |
|:--|:--|:--|
| `git fsck` 的 missing 报告 | ❌ **不可信** | 依赖 pack 的 `.idx` 登记，**不校验 .pack 实体**；畸形 pack 空登记会漏报 missing（假阳性「健康」） |
| `git cat-file --batch-check` | ❌ 并发下不可信 | 整批误报 missing |
| **`git cat-file -e <sha>`** | ✅ **唯一可信** | 返回码 0 = 真实存在 |

## 四、修复：中转仓库回填法

1. 建独立 bare 中转仓库，`git fetch --no-tags origin '+refs/heads/*:refs/heads/*'` 拉取远端全量历史
   - ⚠️ **不可用** `--filter=blob:none` 的 promisor 克隆（会触发 on-demand 联网拉取，schannel handshake fail）
2. 缺失对象以**松散对象**回写主仓库：`zlib.compress(b"<type> <size>\0" + body, 6)` → `.git/objects/<sha[:2]>/<sha[2:]>`
3. 迭代收敛：`562 → 441 → 254 → 206 → 16 → 97 → 0`（共回填 1576 个对象）

**终极验证**：原 562 个 SHA **可读 562 / 不可读 0** ✅

## 五、🔴 本仓库永久禁忌（写入基础设施备忘）

**禁止一切 pack 层面的写操作**：

- ❌ `git gc` / `git repack` / `git prune` / `git prune-packed`
- ❌ `git fetch <sha>`（会制造新畸形 pack）

**血泪教训**：

| 命令 | 后果 |
|:--|:--|
| `git prune-packed` | 畸形 pack 的 idx 空登记干扰「pack 中是否有副本」判定 → 删掉 19 个实体不在 pack 中的松散对象（fsck 冒 19 missing / 6 broken） |
| `git repack -a -d -f` | 卡死 45 分钟，产出 `pack-74797ff4`（563 对象 / 2.75 GB）空壳 |

**安全白名单**：`status` / `log` / `show` / `checkout` / `add` / `commit` / `push` / `fsck`（配合 `cat-file -e` 交叉验证）/ `clone --local`

## 六、防护配置（已设置）

```bash
git config gc.auto 0
git config gc.autodetach false
git config maintenance.auto false
```

## 八、顺手完成：C 盘清理（约 12 GB+）

回收站两轮 12.4G + Camtasia 崩溃转储 3.7G + 用户 Temp 更新包 600M + npm cache 271M + 剪映缓存约 400M + 剪映 Log 114M + 用户 CrashDumps 97M。

> ⚠️ **关键发现**：`rm -rf`/`Remove-Item` 删除的文件**会进回收站**，必须再执行一次 `Clear-RecycleBin` 才真正释放。
> 清理流程 = **删除 → 清空回收站 → 复查 `df`**（第一轮报「释放 12.6 GB」时回收站实为 7.8 GB）。

**清理后的大户排查（仅排查未动，均属个人文件）**：
- `AppData` 110 GB（剪映 Projects 9.3G 是用户项目、Programs 12G 是已装软件，不可删）
- `Documents` 22 GB（Tencent Files 5G / WPSDrive 4G / WeChat Files 3.5G / origin 3.3G）
- `WPS Cloud Files` 18 GB、`Downloads` 11 GB、`Desktop` 9 GB

**应用日志可清候选（`.workbuddy/`，约 9.9 GB）**：
- `logs/` 4.9 GB（历史会话日志）、`workspace/sessions/` 3.2 GB、`traces/` 1.8 GB
- 均为应用自身数据、非教学内容，可保留最近 3 天清理更早记录（待用户确认）
