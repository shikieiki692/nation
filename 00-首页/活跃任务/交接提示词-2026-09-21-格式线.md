【〇、这条线在做什么（先读，它决定你的判断标准）】

同一份 md 会经**三条出口**产出，任何一条渲染失真都算本线缺陷：
· docx 线（主入口）`11-模板/scripts/build-all-handout-docx.py`
· PDF 线         `11-模板/scripts/convert_handout_to_pdf.py`
· QA 诊断工具   `11-模板/scripts/qa/*.py`（3 个，方言与产线**不一致**，见 §二 T3）

本线的核心难点：**缺陷分两类，「渲染失败」有闸门，「渲染不对」没有**。
· 闸门可见：产物里残留字面 `$`、texmath 转换失败 → `render_gate.py` 能拦
· 闸门不可见（本线主战场）：**文本内容一模一样、渲染结果错**。已抓到过的真实实例——
  - 区间被吞成下标：`300~500°C` → 出货 PDF 里成 `300500°C（573773 K）`（**已出货实证**）
  - 带电物种丢下标：`\ce{MnO4^-}` 渲染成 `MnO-4^-`
  - 多位数下标只吃一位、分隔符 `+` 被抬成上标、箭头标注丢下标
  - `\ce{}` 内 `^`/`v` 未转 mhchem 语法（`\ce{A^}` 是「向上箭头」不是上标）
  - 中文控制词未断词：xeCJK 下中文是 catcode 11 ⇒ `\箭排` 被当**一个**控制词 → Undefined

**判据纪律**：判据必须按**结果**（源 vs 渲染产物），*不按形状*（不去猜「代码里写没写全」）；
且判据必须**独立于被验收对象**（拿不变量签名，不复刻转换器规则）。

· **暂存区可能被并行会话污染** ⇒ 正解＝**临时索引三防**：
  `GIT_INDEX_FILE=<tmp> git read-tree HEAD && … add … && … commit`（**同一条 `&&` 链**）
  · 提交后 `git show --numstat HEAD` 核**文件数 == 本批文件数**
  · ⚠️ 用过临时索引后**必须把真实索引对本次路径 re-add 对齐**，否则新增文件会变
    **幻影「已暂存删除」（`D `）**，其他会话据此提交会**真删你的文件**
  · 收尾必查 `git status --porcelain -uall | awk 'substr($0,1,2)=="D "{n++}'` == 0
· 撞 `.git/index.lock` **勿手删**（先看时效）
· 🔴 **「未推送数」只信 `git ls-remote origin master`**

  ⇒ **禁用** `git branch -vv` / `origin/master..HEAD` 报数；
  **「推送成功」判据 ＝ 远端 tip == 本地 HEAD**
  ⇒ 推送命令：`git -c http.proxy=http://127.0.0.1:7897 -c credential.helper=manager push origin master`
