# 题库字段与消费状态规范

> 本规范是题库正式组卷、审计和后续迁移的统一口径。历史题卡允许缺少新字段，但正式发布组卷不得依赖 legacy 缺字段状态。

## 1. 核心字段

### `answer_status`

只允许以下值：

| 值 | 含义 | 是否可进入正式组卷 |
|:--|:--|:--|
| `完整` | 题干、答案、解析或明确外链答案均可用 | 是 |
| `待补` | 已有题干，但答案、关键数据或必要解析缺失 | 否 |
| `存疑` | 答案、数据或口径存在已知争议，必须人工复核 | 否 |
| `仅题干` | 只保留题面，暂无可用答案 | 否 |
| `不适用` | 题目类型本身不要求独立答案，或永久退役 | 是，仅在 `consumption_status = 可用` 时 |

历史写法如“答案见源卷（指针式）”不得作为新题的 `answer_status` 值。存量 deprecated 题卡可暂时保留历史值，但不得进入活跃池。

### `consumption_status`

| 值 | 含义 | 组卷策略 |
|:--|:--|:--|
| `可用` | 题干和必要题图已经达到**题目练习池**质量要求；不等同于答案完备 | 可进入练习池；能否进入正式答案组卷池另查 `answer_status` |
| `隔离` | 保留审计或人工修复，不进入组卷 | 自动排除 |
| `退役` | deprecated、误立、不可恢复或已被替代 | 自动排除 |
| 缺失 | legacy 题卡，尚未迁移 | 仅兼容浏览；正式发布前必须补齐 |

`status: deprecated` 是历史工作流状态；只要出现，强制退出活跃池，即使其他字段不完整。

### `replacement_status`

| 值 | 含义 |
|:--|:--|
| `无替代` | 当前没有可证明的一一对应替代题 |
| `待人工对账` | 有候选或同主题题，但尚未证明可替代 |
| `已替代` | 已由 `superseded_by` 指向确定的替代文件 |

`superseded_by: null` 不得臆造替代目标。没有证据就保持 `无替代` 或 `待人工对账`。

### `question_image_status`、`image_audit_status` 与 `image_asset_status`

图片题必须把“物理文件在哪里”“文件确实存在”“图片内容与题意匹配”分开记录：

| `question_image_status` | 含义 | 题目练习池 | 正式答案组卷池 |
|---|---|---|---|
| `已核验匹配` | 已逐张视觉核验，物理文件、实际内容与题意一一对应 | 可 | 可 |
| `已存在未核验` | 文件存在，但尚未完成可靠视觉/题意匹配，或视觉工具结果存在缓存串图等污染 | 否 | 否 |
| `错配` | 图片真实存在，但不属于本题或标签/顺序无法可靠对应 | 否 | 否 |
| `缺失` | 必要题图不存在 | 否 | 否 |
| `不适用` | 题目不依赖图片 | 可 | 可 |

历史值 `完整` 不能自动等价为 `已核验匹配`。只有形成“物理路径 ↔ 实际图像内容 ↔ 题意”三方一致的可追溯证据后，才可写 `question_image_status: 已核验匹配` 或 `image_audit_status: 已核验匹配`。不得仅凭 hash、文件名、OCR 邻近关系、历史摘要或答案结构推断匹配。

`image_audit_status` 用于记录审计证据状态，只允许：`已核验匹配`、`待视觉核验`、`错配`、`缺失`、`不适用`。

`image_asset_status` 用于记录 Word/PDF 管线可访问性，只允许：

| 值 | 含义 | Word/PDF 管线 |
|---|---|---|
| `已入库` | 同名物理文件已在 `媒体仓库/` 顶层 | 可直接扁平解析 |
| `待入库` | 文件存在但仍在 OCR `_images/`、答案目录或其他子目录 | 阻断；必须先原子化落盘到 `媒体仓库/` 顶层 |
| `失联` | 全库找不到物理文件 | 阻断；禁止引用 |
| `不适用` | 题目不依赖图片 | 不进入图片资产解析 |

同名 hash 在不同目录可能不是同一内容；迁移后仍须重新核对文件大小/指纹，并在首次可靠视觉核验前不得写 `已核验匹配`。

## 2. 双层准入：题目练习池与正式答案组卷池

### 2.1 题目练习池（以“完整可做”为核心）

准入条件：

1. `type` 属于 `题目`、`真题` 或 `题组`；
2. `status != deprecated`；
3. `consumption_status = 可用`；
4. 题干、必要数据、单位、表格、反应对象和设问完整，能够独立理解和作答；
5. 图片题必须 `question_image_status ∈ {已核验匹配, 不适用}`；
6. 图片题还必须 `image_asset_status = 已入库`，才能进入 Word/PDF 导出链；仅用于 Obsidian 纯文本练习时也至少要完成内容匹配核验；
7. 不得含伪答案、伪结构、伪机理或从答案反推补出的题面。

**答案不是题目练习池的硬要求**：`answer_status ∈ {待补, 仅题干}` 的题，只要题面和必要题图完整，就可以进入练习池；但必须显式保留答案缺口，禁止伪造答案。

### 2.2 正式答案组卷池（发布/印刷/带答案导出）

在题目练习池全部条件之上，再要求：

1. `answer_status = 完整` 或 `不适用`；
2. 图片资产已进入 `媒体仓库/` 顶层，且 `image_asset_status = 已入库`；
3. 答案、解析、评分点与题面来源一致；答案可空缺的题不得冒充完整；
4. 无重复自链污染；
5. 以完整文件路径作为唯一键，禁止仅用 basename、`qid` 或题号去重。

现阶段筛选器可兼容缺字段 legacy 题，但两个池都必须显式通过图片与题干完整性检查；“正式发布”必须同时满足 `consumption_status: 可用`、图片核验、资产入库和 `answer_status` 检查。

## 3. 统计口径

- **题库 universe**：`04-题库` 与 `05-真题库` 下 `type` 属于题目类的文件；
- **活跃池**：universe 中 `status != deprecated` 且未被 `consumption_status` 排除的题；
- **题目练习池**：活跃池中题干完整、必要题图已核验匹配的题；允许 `answer_status ∈ {完整, 待补, 仅题干, 不适用}`；
- **正式答案组卷池**：题目练习池中同时满足 `answer_status ∈ {完整, 不适用}`、图片资产 `已入库` 的题；
- **分母必须写明**：6,062、6,125、6,090、6,348 等数字不能混用，报告必须注明是文件数、题数、frontmatter 命中数还是查询结果数。

## 4. 审计规则

审计脚本和人工复核都应检查：

- `answer_status`、`consumption_status`、`replacement_status` 枚举值；
- `status: deprecated` 且 `superseded_by: null` 的退役收口；
- 同号、同 `qid`、同 basename 的复用风险；
- `used_in`、`cross_references`、`aliases` 中的反向引用冲突；
- 图片缺失、重复自链、答案占位和题干缺失；
- XES 等专题题卡的 `answer_status: 待补`，不要使用已过时的“无图”描述替代当前证据。

## 5. 新题入库最低字段

新题至少写入：

```yaml
type: 题目
title: ...
fidelity: 原书逐字 | 原书改写 | 自编
difficulty: 1-5
exam_stage: 初赛 | 决赛 | 省预赛
subject_module: 化学原理 | 结构化学 | 有机化学 | 元素与分析
pack: 章节练习 | 模块习题集 | 综合模拟卷 | 预赛专项
knowledge_points: [...]
answer_status: 完整 | 待补 | 存疑 | 仅题干 | 不适用
consumption_status: 可用 | 隔离 | 退役
question_image_status: 已核验匹配 | 已存在未核验 | 错配 | 缺失 | 不适用
image_asset_status: 已入库 | 待入库 | 失联 | 不适用
image_audit_status: 已核验匹配 | 待视觉核验 | 错配 | 缺失 | 不适用  # 图片题建议显式写入
```

正式组卷前再补 `source`、`source_norm`、`teaching_level`、`question_type` 等消费字段。
