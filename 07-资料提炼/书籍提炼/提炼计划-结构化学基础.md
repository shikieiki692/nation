## 四、执行流程

```
Phase 0: 读速查+摘要 → 确认OCR章节对应关系
Phase 1: Batch 1-5 (P0) → 逐章读OCR(limit) → 提炼 → 写入
Phase 2: Batch 6-10 (P1) → 按需读OCR → 提炼 → 写入
Phase 3: 汇总 → 更新章节摘要 → 考纲映射 → 知识点查漏
```

### Phase 0 检查清单
- [ ] 确认 OCR 文件中各章节的行号范围
- [ ] 确认已有习题提炼是否可直接复用部分内容
- [ ] 确认知识点文件是否已覆盖 Batch 1-5 的核心概念

### 每批次操作步骤
1. `kb_read` 读 OCR 源文件对应章节（`limit` 控制，不全读）
2. 交叉参照已有习题提炼中同章内容
3. 按模板生成提炼文件
4. `kb_write` 写入 `07-资料提炼/书籍提炼/`
5. 标记 `kb_dirty` 脏模块
6. 更新章节摘要索引

## 五、风险与约束

| 风险 | 应对 |
|------|------|
| OCR 质量差（公式/图片乱码） | 用图片替代文字描述，标注 `[OCR待校对]` |
| 内容超出考纲 | 在 `## 四` 中明确标注"超越初赛"/"超越决赛"，不删除 |
| 与已有知识点文件重复 | 在 `## 六` 中交叉链接，不重复创建 |
| Token 超限 | 每批次独立执行，不累积上下文 |
