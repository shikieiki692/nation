# 块级 HTML 表格内公式不渲染（「乱码」）根因报告

> 日期：2026-09-19
> 起因：用户指出「看着还是乱码，没渲染出来」——**修正**前一轮（`\cdot` 间距）的诊断方向。
> 结论：**真根因是 HTML 表格被 markdown-it 判为 `html_block`，其内部 `$…$` 不进入 inline 解析。**

## 一、现象

用户在 Obsidian 看到（以 `（已压缩）化学竞赛能力测试.md` 第 843 行为例）：

```
[BBr_3], \mathrm{mol}\cdot\mathrm{L}^{-1}   ← 公式源码原样显示，未渲染
```

不是间距问题，不是 `·` / `\cdot` 问题——是**根本没渲染**。

## 二、根因（实测确认）

### 2.1 该行结构

```html
<table><tr><td>Temperature, °C</td><td> $[BBr_3], \mathrm{mol}\cdot\mathrm{L}^{-1}$ </td>…</table>
```

- 整行 **1029 字符**，`<table>` **位于行首**，整行独占一行
- `$` 配对正常：**52 个（偶数）** ✅ —— 排除「定界符不配对」这一可能

### 2.2 markdown-it 的解析路径（Obsidian 阅读视图同引擎）

实测（`.workbuddy/tmp/_final_verify.js`，对 `math_inline` 规则插桩计数）：

| 输入形态 | 顶层 token | `math_inline` 调用次数 | KaTeX 渲染数 | 残留 `$` |
|---|---|---|---|---|
| `<table>` 行首独占一行（**库内现状**） | `html_block` | **0** | **0** | **2** |
| 表格前加空行 | `html_block` | **0** | **0** | 2 |
| 表格前加文字段落 | `…, html_block` | **0** | **0** | 2 |
| 表格紧贴文字 | `…, html_block` | **0** | **0** | 2 |
| 表格前后各留段落 | `…, html_block, …` | **0** | **0** | 2 |
| **Markdown 表格** | `table_open, thead_open, …, inline, …` | **4** | **2** | **0** |

**判定**：行首 `<table>` 触发 markdown-it 的 HTML 块规则（整块直到空行），
块内内容**完全不经过 inline 解析** → `math_inline` 规则零次调用 → `$…$` 原样输出。

### 2.3 关键否证

- ❌ **加空行无效**（实测 0 次调用）—— 常见的「HTML 块前后要空行」的经验在这里救不了
- ❌ **加前后段落也无效**（实测 0 次调用）
- ✅ **只有 Markdown 表格形态**能让单元格内容进入 inline 解析（实测 4 次调用 / 2 个渲染 / 0 残留）

## 四、修复路线（待定，需用户拍板）

### 路线 1：HTML 表格 → Markdown 表格（根治）

- **优点**：单元格内 `$…$` 进入 inline 解析，公式正常渲染；符合库内主流写法
- **难点**：`<table>` 存在 `colspan` / `rowspan` / 空单元格 / 单元格内换行 等复杂结构，
  机械转换可能破坏版式；需逐表核对
- **风险**：**数量大（2,563 行 / 425 文件）**，且 `04-题库/`（红线）、`04-课件/`（活跃）在内

### 路线 2：单元格内容剥离为独立段落（不推荐）

把 `$…$` 抽到表格外——**破坏表格语义**，不可取。

### 路线 3：只治理无主区（保守，推荐先做）

只处理 `06-外部资料导入/` + `mineru/` + `mineru02/` = **1,714 行**（无主区，可放手修），
其余按责任线分发（`04-题库/` 红线不碰）。

### 路线 4：登记不修

作为已知缺陷登记，等有消费端需求时再处理。
