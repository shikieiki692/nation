## 二、P0 两项（会实际毁产物）

### P0-1 `✅在媒体仓库` 标签失实 834 条

`AGENTS.md` 明文规定：「**状态列为 `✅在媒体仓库` 的条目可直接用于 Word 管线**」。
实测 `10-索引与统计/全库核心图谱总索引.md`：

| 项 | 实测 |
|:--|--:|
| 标 `✅在媒体仓库` 的行 | **2,782** |
| 其中**实际不在** `媒体仓库/` | **834（30.0%）** |
| 登记总条目 | 2,759（自报 2,796，**对不上**） |
| 真在媒体仓库 | 1,926（69.8%） |

**为什么是 P0**：pandoc 找不到图时**不报错**——只打一条 `[WARNING] Could not fetch resource ...:
replacing image with description`，然后**把图换成一行文字描述**继续编译。实测（见 §三）三种
`--resource-path` 配置下均正常退出（`rc=0`）。⇒ **产物静默少图，编译日志不中断，验收看不到。**

**根因**：索引的 ✅ 是「登记时打标」，**从未与媒体仓库实盘对账**。索引 md 更新于 09-12，
而媒体仓库在 08-23 之后经历过一次大规模改名（见 §五），此后两者再未对齐。

**修法（二选一）**：
- **A（推荐，最小侵入）**：把状态值 `✅在媒体仓库` 改名为 `✅已登记`，另加一列
  `媒体仓库` 存实盘核对结果 `有／无（在X目录）`。语义与事实对齐，不动取图规则。
- **B**：把 834 条不在媒体仓库的图**补进媒体仓库**（源路径大多在版本库内，可脚本化），
  使 ✅ 恢复为真。

### P0-2 媒体仓库子目录在 Word 管线取不到（**实测**）

`媒体仓库/` 现有 4 个子目录，共 147 文件：

| 子目录 | 文件数 | 仅存在于该子目录（顶层无同名） |
|:--|--:|--:|
| `pchem_principles_4th` | 97 | — |
| `weller_ch19-21` | 24 | — |
| `chemistry-textbook-images` | 18 | — |
| `zhao_ch200_350` | 8 | — |
| **合计** | **147** | **60** |

**决定性实测**（三样本：A 顶层 / B 仅子目录 / C 不在媒体仓库）：

| `--resource-path` | 嵌入成功 |
|:--|:--:|
| `媒体仓库` | **1 / 3** |
| 仓库根 | **0 / 3** |
| `媒体仓库` + 仓库根 | **1 / 3** |

⇒ **pandoc 的 `--resource-path` 是「扁平查找」，不递归子目录**；把仓库根加进去也无效（同因）。
**结论**：`媒体仓库/pchem_principles_4th/xxx.jpg` 这类图，在采用 `--resource-path=媒体仓库`
的管线（如 `build_chusai_zhenti_layout.py`、`build-all-handout-docx.py`）里**必然取不到**。
「仅存在于子目录」的 **60 张**就是确定会丢的那批。

另：147 个文件中有 **87 个与顶层完全同内容重复** ⇒ 当初是**「复制」而非「移动」**进子目录。

**修法**：① 把 147 个文件**并入顶层**（与 `媒体仓库`「扁平哈希原名」约定一致，75s 可脚本化）；
或 ② 管线 resource-path 改为**逐个列出子目录**（治标，且以后每加一个子目录都要改管线）。

## 四、P1 四项（规则与实际脱节）

### P1-1 别名文件 409 个，343 个正被引用

媒体仓库中 **409 个文件的文件名不是 64 位哈希**（`zhao_*` 94、`zjwx_*` 45、`zgxg_*` 44、
`2021/2022/2023-*` 38、`crystal*` 9、`clayden*` 8、`perovskite*` 5…）。
这与两条明文规则**直接冲突**：

- `00-首页/规则-配图来源优先级.md` §一.1：「绝不允许物理重命名、加路径前缀或断链」
- `AGENTS.md` 搜图规范：「**绝对禁止**使用英文标签别名（如 `zhao_methyl.jpg`）作为插入名」

**而其中 343 个正在被引用**，引用者以**消费端**为主：

| 引用者顶层目录 | 引用次数 |
|:--|--:|
| `03-知识点` | 265 |
| `04-题库` | 186 |
| `04-课件` | 169 |
| `09-审计报告` | 39 |
| `05-真题库` | 10 |

⇒ 规则说「禁止」，实际「在用且用得不少」。**且 182 组「哈希名 ＋ 别名」是同内容副本**
（别名是哈希文件的拷贝）⇒ 既是口径问题，也是 9.8 MB 冗余的来源。

**修法**：承认现状或彻底收敛，二选一。若要收敛，**先出「别名 → 哈希」映射表并全库改引用，
再删别名副本**；不要只删文件（会造大批断链）。

### P1-2 / P1-3 索引状态与覆盖

| 索引 | 登记 | 真在媒体仓库 | 比例 | 不在媒体仓库（库内他处可寻 / 全库皆无） | 自报规模 |
|:--|--:|--:|--:|:--|:--|
| `01-有机化学图谱总索引` | 1,198 | 1,071 | 89.4% | 125 / 2 | 1,184（**差 14**） |
| `02-结构与无机化学图谱总索引` | 939 | 673 | 71.7% | 257 / 9 | 937（差 2） |
| `03-物化与分析化学图谱总索引` | 664 | 225 | **33.9%** | 434 / 5 | 663（差 1） |
| `全库核心图谱总索引` | 2,759 | 1,926 | 69.8% | 817 / 16 | — |
| `视觉已验证图片索引` | 1,221 | 1,164 | 95.3% | 46 / 11 | — |

**两套状态口径并存**，且只有一套写进了 `AGENTS.md`：

| 索引 | 状态取值 |
|:--|:--|
| 三大分流索引 | `🟢已视觉核验` / `🟡名著候选(待目检)` / `🔴纯公式切片` |
| 全库核心索引 | `✅在媒体仓库` |

`AGENTS.md` 只描述了 `✅` 那套，**对 `🟢/🟡/🔴` 一字未提**；而 `🟡` 恰恰是最大的一档（1,916 张）。

**修法（口径统一）**：建议合并为**两维正交**——「是否在媒体仓库」（实盘核对）与
「视觉核验状态」（🟢已核验 / 🟡待目检 / 🔴弃用）。一维管管路，一维管质量，各自独立可维护。

### P1-4 媒体仓库不受版本控制

```
git check-ignore -v --no-index 媒体仓库/x.jpg
  → .gitignore:9:媒体仓库/      （命中）
git ls-files -- 媒体仓库
  → 0 个文件
```

对照：`media/` 848 个、`高中化学竞赛笔记/` 2,362 个、`06-外部资料导入/` 34,206 个
**全部在版本库内**。即：**唯一的「正式图库」是唯一不受保护的目录**。
09-18 补图清单已把这条列为「⚠️ 可恢复性」并给出重建方法（按表把源路径复制为 `媒体仓库/<名>`），
但**可恢复性依赖手工台账，而台账本身停在 08-04**（§五）。

**修法**：① 解除 ignore（体积 296 MB，可控）；或 ② 保留 ignore 但**把「媒体仓库清单」升格为
可重建的权威台账**并纳入版本库 + 在 CI/闸门里校验清单与实盘一致。

## 五、P2 五项（卫生与可维护性）

### P2-1 孤儿 3,114 张 / 66.3 MB

媒体仓库 15,022 张中 **20.7% 从未被任何 md 引用**。中位 11 KB，最大 535 KB。
这不必然是缺陷（可能是**预置图源**），但需要一个**明确判定**：是「预置待用」还是「搬迁残留」。
建议加一个 `status: 预置|在用` 字段或单独清单，否则每轮审计都要重新判一次。

### P2-2 内部重复 336 组 / 冗余 9.8 MB

| 类型 | 组数 |
|:--|--:|
| 同名重复（子目录 ↔ 顶层，同内容） | 83 |
| 异名重复（**哈希名 ＋ 别名**，同内容） | 253 |

其中「哈希名 ＋ 别名」占 182 组 ⇒ **别名文件多数是哈希文件的副本**（与 P1-1 同源）。

### P2-3 `媒体仓库清单.json` 已过期 —— **且极易被误判为「丢失」**

| 项 | 值 |
|:--|:--|
| 清单生成时间 | **2026-08-23 00:56** |
| 清单登记 | 17,639（unique name） |
| 现盘 | 14,935 |
| 清单有·盘上无 | **10,746** |
| 盘上有·清单无 | 8,042 |

⚠️ **若直接相减会得出「丢了 10,746 张」的错误结论。** 实测三项证据表明是**大规模改名**：

1. 缺失的**别名式**条目（5,573 个）中，**467 个的「裸哈希名」已在盘上**——
   例：清单 `ccho_37_0e511fedc64a…jpg` → 盘上已有 `0e511fedc64a…jpg` ⇒ **别名前缀被剥**。
2. 缺失的**纯哈希**条目（5,173 个）中 **5,129 个库内他处可寻**，全库皆无仅 **44 个 / 2.5 MB**。
3. **总字节不降反增**（清单 287.3 MB → 现盘 295.6 MB）⇒ 若是真丢失不可能变大。

**修法**：重生成清单（脚本化），并把「清单 vs 实盘」纳入常规闸门；否则任何「据清单核账」
的动作都会踩坑。

### P2-4 `media/` 影子图库未清干净

`media/`（仓库根级）**841 张**，其中 **344 张媒体仓库没有**；而与媒体仓库同名的 497 张
是**重复副本**。迁移台账 `10-索引与统计/旧media迁移摘要.json` 停在 **2026-08-04**
（`files: 63 / refs: 346 / copied: 159 / reused: 185`）——**已完全不反映现状**。
规则 v1.2 明确「避免 `media/` 命名和引用失控」，但收尾未做。

### P2-5 图片审计工具碎片化

`.workbuddy/scripts/` 与 `11-模板/scripts/` 下 **30+ 个**图片相关脚本：
`audit_missing_images_v2` / `audit_vault_images` / `check_img_detail` / `check_img_dpi` /
`check_img_paths` / `classify_orphans` / `find_fake_images` / `find_recoverable_imgs` /
`rescue_nearmiss_imgs` / `fix_broken_img_refs` / `gen_vault_img_report` / `image_usage_stats` /
`recover_images_from_git` / `analyze_orphan_risk` / `build_dup_image_analysis` / `phase2_image_triage` …

特征是**一次性、命名带 v2/_full/near-miss**、**无统一入口**、**无口径版本**。
后果：**每次做图片审计都得重写一遍**（本次亦不例外），且不同时期的口径互相不可比
（09-17 报告 §三 与本报告 §三 记录的同一类假阳性，两次都各踩了一遍）。

**本次已收敛**：`.workbuddy/scripts/img_asset_audit.py`（v2026-09-23.2）把 V1–V7 七组口径
固化进单文件，文件头写明口径定义与**已知假阳性清单**，支持 `--json` 落基线。
后续「改前 / 改后」用同一脚本对照即可，**不再新增一次性脚本**。
