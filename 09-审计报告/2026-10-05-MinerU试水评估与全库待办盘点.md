# MinerU OCR 试水评估 ＋ 全库待办盘点

### 2.1 第一轮症状：顺序错乱 ＋ 公式丢失

```
弱， 3-2-1 多一个 Ni(CO)₂ 且含有大环。 如果把 物 C。Zn-Zn 配合物 X 中的…
3-2-1  2-3-3  2-3-2  2-3-1  ← 小问编号倒序
Dip NC( pPh2R \fac\$           ← LaTeX 碎片
```

- 中文能认出来，但**阅读顺序被打乱**（小问编号倒排、句子片段交叉）
- **LaTeX 公式 0 个**，全部退化为碎片
- 该页 3 张反应式图**全丢**

### 2.2 第二轮症状：转正后更差

| 假设「90° 旋转是主因」⇒ 转正后重试，结果**更差**： |
|:--|

| 公式区全是 `\mathbf{u}_{Z^{-}}` / `\pmb{x}` / `\forall` 之类噪声 |
| ⇒ 转正是**错误假设**，已否决 |

### 2.3 根本原因

| 差异项 | 现有 204 张卡的源头 | 本批 5 题的源头 |
|:--|:--|:--|
| PDF 类型 | **原生排版 PDF**（文字可选中） | **扫描件**（文字层仅 8 字/页） |
| 二次扫描 | 无 | **有**（「扫描全能王 创建」水印） |
| 来源 | 用户自行 OCR（MinerU 处理的清晰 PDF） | **从未 OCR** |

⇒ **本批是「扫描件的扫描件」**，MinerU 的版面分析模型在这种输入下失效。本轮已把它能做的都试了（两个旋转方向、两种裁切方式），⛔ **不建议继续投入**——即使勉强产出，也无法达到现有卡「题面可检索、按考点召回」的标准。
