## 五、另发现：51 份 md 有「转义符被吃」的源级损坏（docx A/B 查不到）

**机制**：某脚本用**非 raw 字符串**拼接内容 → Python 把 `\f` `\t` `\r` `\b` `\v` `\a` 当转义符吃掉：

| 控制字节 | 原命令 | 残留 |
|---|---|---|
| `\x0c`(FF) | `\frac` | `rac{` |
| `\t`(TAB) | `\text` / `\times` / `\theta` | `ext{` / `imes` / `heta` |
| `\r`(CR) | `\rightarrow` / `\rho` | `ightarrow` / `ho`（**并断行**） |
| `\b`(BS) | `\beta` / `\begin` | `eta` / `egin` |
| `\v`(VT) | `\vec` / `\varepsilon` | `ec` / `arepsilon` |
| `\a`(BEL) | `\alpha` / `\approx` | `lpha` / `pprox` |

**影响面（51 份）**：`04-题库/教材习题` 24、`04-题库/有机化学` 15（这两组是 **`\r\r\n` 双 CR 行尾**，非命令损坏）、`00-首页/工作日志` 5、`03-知识点/决赛要求` 3、`03-知识点/无机和结构化学` 1、`04-课件/新授课` 1、`07-资料提炼` 1、`00-首页/经验沉淀` 1。

**好消息（已实测）**：

- **习题书不受影响**。`build_module_book.py:215-220` 有「行首 `rac{` → 并回前行并补 `\frac`」的修复规则，而 `\x0c`/`\x0b` 在 `str.splitlines()` 里算**行分隔** → 残留正好落在行首 → 被自动还原。实测 `04-课件/习题集`（教师版+学生版 全部 md）控制字符 **0 命中**，且题面里是正确 `\frac{k_{1}}{k_{1}'}`。
- **A/B 扫描查不到这一层**——`rac{`/`ightarrow` 不在 A 类模式里。判断这类问题**必须单独扫控制字符**（`scan_ctrl_dir.py`）。

**已在同日后半程修完（见「八」）**。修法是规则化还原（`<CTRL>+remainder` → `\+首字母+remainder`，删孤立控制字节），逐条变更日志 + 逐文件断言；`00-首页/工作日志/*` 5 份历史记录也一并清掉了控制字节（只删字节、不改文义）。
