# OCR 符号误识人工修复清单（$ 数为奇数）

> [!abstract] 这份清单解决什么
> 全库数字拆分修复完成后，仍有若干文件因 **`$` 数为奇数** 被安全策略挡下。
> 经核查，这些**不是「少了一个 `$`」**，而是 OCR 把 `$` 与 `(`、`)` 互相误识，
> 或在行尾多出孤立的 `\$`。自动补 `$` 必然补错，故逐处定位交人工判定。

## 一、判定方法

1. 打开清单给出的文件与行号；
2. 看上下文：该处本应是**行内公式**还是**普通文字**；
3. 按「建议改法」改；改完用 `jsyaml_verify.js` + `validate_kb.py` 复跑双闸门；
4. 该文件的 `$` 总数变为偶数后，再重跑 `fix_ocr_split_gray2.py` 即可自动修复数字拆分。

## 二、常见误识形态对照

| OCR 输出 | 通常是 | 处理 |
|:--|:--|:--|
| `...\right]^-\$。` | 行内公式结尾的 `$` 被转义 | `\$` → `$` |
| `E2 >> S\_N1\$` | 同上 | `\$` → `$`，并核对行首是否缺 `$` |
| `$( \$ 123,456,7$`） | `(` 被误识为 `\$` | 删掉多余 `\$` |
| `$( \$ 10.84\times 10^{23}$` | 同上 | 删掉多余 `\$` |
| `$ 5 \times 10^{5} )$` | `$` 被误识为 `)` | `)` → `$` |
| `$\$ 02$` | 多余转义 | `\$` → 删除或按语境还原 |
| `1 - \$` | 纯噪声 | 删除 |
