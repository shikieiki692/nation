格式线可做的是**可机械验证、可回滚**的部分 —— 而它**已经做完了**。

## 二、建议方案

> **建议：把「内容线大规模修补」降级暂缓；先做下面三件（P0/P0/P1）。**
> 理由一句话：**剩下的既不便宜、也不在交付路径上；而水龙头还没关严、健康度还看不见。**

### P0-1 把闸门写进**顶层 SOP**（最高杠杆）

**目标**：任何会话在「改 md / 导入 / 产出」时**默认会跑闸门** —— 不依赖谁的记性。

**具体要求**
1. 在 `00-首页/Agent标准作业流程.md` 增一节「格式闸门（改 md 必跑）」；
   在 `00-首页/Agent最小执行协议.md` 的收工/验收清单加一行。
2. **措辞必须与 `04-题库/新题入库SOP.md §5.2c` 对齐**（先读它，避免出现两套口径）。
3. 三条要点：
   - 改完 md → `python -X utf8 11-模板/scripts/render_gate.py --changed <文件…>`（0 失败才算过）
   - 批量导入/产出后 → `python -X utf8 11-模板/scripts/import_gate.py --domain <域>`
   - `pre-commit` 已装（带 75s 预算）；**超时会如实报「跳过 N 未检」——那不是通过**
4. **验收**：两文件能 grep 到 `render_gate` 与 `import_gate`；
   与 §5.2c 无措辞冲突；不覆盖并行会话的在途改动（用 `-o` 提交、只 add 本会话文件）。

### P0-2 产出「内容线精确工单」（我这边可交付）

**目标**：把「169 份待处理」变成一个**分组、带失败公式原文、按影响面排序**、
**可直接委派**的工作表 —— 而不是一个数字。

**具体要求**
1. 对全部失败域跑 `render_gate -q`，**落盘原因**（不是只看计数）。
2. 按**根因签名**分组：texmath 语法错 / 仅字面 `$`（不配平）/ `$$` 结构错位 / 其他。
3. 每组逐条给出：文件路径、**失败公式原文**（用 `render_probe.py`）、**是否需原书**。
4. 按影响面排序：`06-学生侧材料/练习卷`（交付物·内容截断，P0）
   ＞ `03-知识点`（KP 锚点）＞ `07-资料提炼` ＞ 源层（**建议不修**，见下）。
5. **明确写出「哪些建议不修及理由」**（源层 106 份）。
6. **验收**：工单分组计数之和 **==** `render_gate` 报告的失败总数（逐域对账）；
   每份失败文件都能看到失败公式**原文**，不需要再跑一次才能动手。

### P1 让健康度可见

**目标**：公式健康度成为「一个能看的数字 + 一条能重跑的命令」，而不是一次性结论。

**具体要求**：把域级汇总（受检/失败 + 命令）固定存进审计报告并在下次复跑后 diff；
**不新建看板、不新建脚本**（避免过度建设）——用现有 `render_gate --domain` 的输出即可。
