## 四、🔴🔴 回声清洗事故（已全部回滚）

### 4.1 事故链

```
写 p6_clean_echo.py（判据：归一化长度≥12 且 与题面任一行相似度≥0.85 或互为子串）
  ↓
① --dry 运行实际写盘（clean() 未判 DRY）⇒ 178 张被清洗
  ↓
② 5 张答案段被误清空（判据「删完只剩≤2 行」过宽）⇒ git checkout 恢复
  ↓
③ 改判据后正式跑 ⇒ 131 张进 commit 1891d9c39
  ↓
④ 全量 render_gate 报 61 张「oMath 倒退」
  ↓
⑤ 逐张 git show HEAD: 对照 ⇒ 倒退全在答案段（56/61），
   被删的不是复述而是答案实体（含公式/图/独立结论）
  ↓
⑥ 识别 336 张答案段被删行 ⇒ git checkout 1891d9c39^ -- ⇒ 全部回滚
  ↓
⑦ 复跑全量闸门 ⇒ 1268 张 PASS（失败 0）
```

### 4.3 根因

**相似度判据把「含公式的答案行」误判为复述**。原因是归一化时剥掉了 `$` 与图片，剩下的中文与题面某句高度重合（例如答案里复述题干条件再作答，第一句像复述，整行就被删）。

### 4.4 沉淀的纪律

| # | 纪律 |
|:--|:--|
| 1 | 🔴 **回滚目标ref 必须是「误修复之前」的 commit** —— `git checkout HEAD --` 在已提交后是**空操作**（本次先踩了一次才发现） |
| 2 | 🔴 **备份文件本身可能被污染** ⇒ 只能当第一道防线，**回源`git show <ref>:` 对照才是权威** |
| 3 | 🔴 **判「删的是否为回声」必须回源比对题面**，不能只信相似度阈值 |
| 4 | 🔴 **「答案段变空」判据须判「原段有实质内容 且删后无实质内容」**，不可用「删完只剩 ≤2 行」（会误杀「小标题＋图片」型答案） |
| 5 | 🔴 **`--dry` 必须真不写盘**（入口判 DRY 直接 return） |
| 6 | 🔴 **本项目已 4 次「修复让闸门变差」** ⇒ 闸门失败数与基线比对是**唯一止损信号** |

## 六、判据过期修正：`p2a_fm_check.py`

```python
# ❌ 旧（P2-a 时期「建卡不带锚点」假设）
if d.get("knowledge_points") != []:
    errs.append((b, "kp 非空"))

# ✅ 现：只校验非空时格式合法
_kp = d.get("knowledge_points")
if _kp not in ([], None):
    if not isinstance(_kp, list) or not all(
            isinstance(x, str) and x.strip() for x in _kp):
        errs.append((b, "kp 格式非法 %r" % (_kp,)))
```

**影响**：T4锚点线补锚点后，旧判据**误报 557 个 Error**；修正后 **Error 归零**。

> 🔴 这是一个**判据过期**的典型案例：脚本判据与库演进不同步时，会把**正确状态**判成缺陷。
> 与 MEMORY 记的「判据三连坑」同源 —— 判据本身需要定期随库演进复核。
