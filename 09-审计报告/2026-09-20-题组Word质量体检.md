## §三 ❌ P0 缺陷 1：源码残留（25 份）

### 现象

Word 正文里**直接出现 Markdown/frontmatter 源码**：

```
used_in: “第二轮习题集-元素与分析一” ___ ## 第 2 题
```

读者（学生）会直接看到这串源码。

### 根因（**已完整定位，9 步证据链闭合**）

**一句话：题文件的 `used_in` 字段被写入「正文末尾」而非头部 FM，`strip_fm()` 剥不到；该行与紧邻的 `---` 被 Pandoc 解析为 YAML 元数据块起止符，导致源码外泄 + 吞掉紧随的整道题。**

| 环节 | 状态 |
|:---|:---|
| 源卷 `04-题库/第二轮习题集-元素与分析一.md` | ✅ **干净**（题头为 `### [[题名]]（d2，2 分）`，无 `used_in`） |
| 题文件（**09-07 时点**） | ❌ **`used_in` 写在 L30 正文区**（FM 结束于 L24），不在 FM 内 |
| `strip_fm()` | ✅ 正确剥头部 FM（L1-24），**但剥不到正文区的 L30** |
| `extract_stem()` | ❌ **过滤名单里没有 `used_in:` 规则** → 原样 `out.append` |
| `ANS_SECTION` 截断 | ⚠️ 匹配 `## 参考答案` 时 `break`，但**上一行的 `---` 已先入 `out`** → 残留 `---` |
| 中间产物 `.workbuddy/tmp/exam_build/*.md` | ❌ 含 6 处 `used_in` + 紧邻 `---` |
| `_old_build_docx.py` L1689 | ⚠️ 本有 `re.sub(r'^---\s*$', '___', ...)` 防此坑，但 `used_in: "[[…]]"` 与 `---` **相邻**构成元数据块，替换后仍被 Pandoc 识别 |
| **Pandoc** | ❌ 把 `used_in: "[[…]]"` + `---` 当**新 YAML 元数据块** → **吞掉紧随的整道题** |
| docx 产物 | ❌ 源码残留 + 题面缺失双症并发 |

### 决定性证据（09-07 历史版本原文）

```
L24  ---                                          ← FM 结束
L25  > [!info] 2026-08-25 忠实重录…
L27  5. 称量法测定黄铁矿中硫的含量…                  ← 题面
L30  used_in: "[[第二轮习题集-元素与分析一]]"        ← ⚠️ 正文区！mark_used.py 追加位置错误
L31  ---
L33  ## 参考答案
```

**⇒ 这是「台账字段写入位置错误」的产物。** `mark_used.py` 把 `used_in` 追加到了正文末尾（L30），违反「FM 七字段必填」规范（应在头部 FM 内）。

### 🔑 为什么「重跑无效」的精确原因

**当前题文件里的 `used_in` 已被移入 FM（或清理），重跑会跑出干净结果 —— 但那不修复已固化的 docx。** 反之，若不先修数据/脚本而直接重出，在**同代数据**上会原样复现。故正解是**两步：① 确认源数据已修正 ② 修 `extract_stem()` 加 `used_in` 兜底过滤，再重出**。
