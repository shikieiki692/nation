# 断链台账判据修正与全量复判（2026-10-02）

> 结论先行：**原台账「`04-课件` 断链 208 处」的判据有误，真断链仅 7 处，且全部落在归档豁免区。**
> 本文件同时记录对本会话早前一次误操作的回滚。

## 一、原台账判据的缺陷

原台账 `09-审计报告/2026-10-01-04-课件断链台账.csv`（143 行 / 208 次）在判「断链」时**只按文件名（basename）匹配**，
未读取目标页 frontmatter 的 `title` / `aliases`。

但本库：

- `03-知识点/` 共 **960** 个页面，其中 **873 个（90%）带 `aliases` 字段**；
- 库内权威实现 `11-模板/scripts/validate_kb.py` 明确建立了两套索引并同时使用：
  - `build_filename_index()` —— `basename → [Path]`（L476）
  - `build_label_index()` —— `title / aliases / syllabus_code → [Path]`（L492）

也就是说，**`[[拉乌尔定律]]` 在 Obsidian 与 `validate_kb` 下都能正常解析**，因为
`03-知识点/决赛要求/物理化学深化/Raoult与Henry定律.md` 的 FM 写着：

```yaml
aliases: [Raoult's Law, Henry's Law, 拉乌尔定律, 亨利定律]
```

原台账把它记成了断链。

## 二、复判方法

脚本 `.workbuddy/tmp/td_full_recheck.py`：**直接 `import validate_kb` 并调用库内权威索引**（不另起炉灶），
对台账 143 行的每一个链接目标做 `filename + label` 双通道判定。

```bash
PY="C:/Users/蕾赛/.workbuddy/binaries/python/versions/3.13.12/python.exe"
"$PY" -X utf8 .workbuddy/tmp/td_full_recheck.py
```

## 五、结论与建议

1. **「非归档断链 101 处」这个待办项应整体关闭**——它是判据缺陷造成的假阳性，不是内容缺陷。
2. **「归档断链 107 处」同理**，其中真断链只有 7 处，且归档区本就豁免。
3. 后续任何断链审计应使用 `validate_kb.py` 的 `build_filename_index` + `build_label_index`，
   ⛔ 不要再用「仅文件名子串匹配」的脚本（`.workbuddy/tmp/t1~t3_*.py` 即属此类，已停止使用）。
4. 若要真正改善链接质量，方向不是「消断链」，而是**消歧义**：把指向 `04-题库` 真题卡、
   `_归档` 页面、或存在多候选的链接，改指向唯一且权威的正式页。这类项需另行盘点。
