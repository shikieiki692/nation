# 公式渲染流水线优化方案

## 一、今天到底修了什么（13 笔的归纳）

一次会话内修了 **7 类**缺陷、13 笔提交：

| # | 缺陷类 | 检出手段 | 规模 |
|:--|:--|:--|:--|
| 1 | `<div class="mineru-algorithm">` 包裹块 | pandoc（CommonMark 方言）/ 肉眼 | 源+产物共 148 块 |
| 2 | `\AA` 宏（texmath 不支持） | pandoc texmath | 源+产物 100+ 处 |
| 3 | **TAB 污染**（`\t` 写成真制表符） | **只有 hex 能抓** | 12 处 |
| 4 | 行内公式混入 `\[` / `\]` | texmath | 5 处 |
| 5 | 断行宏（`\r` + 换行把命令劈开） | 渲染失败 | 1 处 |
| 6 | `$$` 块结构错位（吞引用块 / 孤儿 `$$`） | 渲染失败 / 奇数计数 | 3 处 |
| 7 | `\text{\text{Å}}` 嵌套 | texmath | 3 处（**我自己引入的回归**） |

### 三个共性（这才是重点）

1. **全部源自「导入」，不是「创作」** —— 7 类里有 6 类可追到 MinerU OCR 产物或导入脚本，
   只有第 7 类是人（我）在修补时引入的。
2. **全部「静默」** —— grep / 编辑器 / 阅读都不显示：TAB 不可见；
   div 在 pandoc 默认方言下无害；`\AA` 被管线自动兜底；
   `$$` 错位要理解配对才看得出。
3. **修复总是发生在错的层** —— 我最初在**生成物**（成书层/卷）上改，
   而这些是 `--clean` 会重建的产物：**下次重建即还原**。
   实证：用改动前的生成器跑一遍，41 份产物带 16 个 div。

## 二、结构性根因（5 条）

| # | 根因 | 证据 |
|:--|:--|:--|
| R1 | **没有导入边界校验** | MinerU 产物直接落库，无 sanitize、无 gate。7 类缺陷 6 类由此进入 |
| R2 | **净化逻辑散落 4 处** | `_strip_mineru_div` 我复制了 4 份（docx 管线 + 3 个生成器）。同一类知识 4 个副本，必然漂移 |
| R3 | **两套渲染器、两套真相，却无测试矩阵** | docx 走 pandoc `markdown` 方言，Obsidian 走 CommonMark。此前一律用 `commonmark` 测 → **双向假阳性**（实测跨行 `$$` 与 div 的表现完全相反） |
| R4 | **生成物被当作源文件修改** | 成书层/第一轮卷由生成器全量重写；改它等于白改 |
| R5 | ~~闸门只管结构、不管渲染~~ → **【2026-09-20 更正】真相是「两级盲区」** | 见下方更正 |

> ### ⚠️ 更正（2026-09-20 晚，写方案后经查证）
>
> **本方案初稿的 R5 是错的**，错在「没读代码就下判断」。查证后的事实：
>
> **库里早有一套成熟的公式预检** —— `build-all-handout-docx.py::_run_word_formula_precheck`，
> **19 条规则**（`bare_subscript_critical` / `bare_script_braced` / `latex_outside_math` /
> `standard_state_circ` / `mo_antibonding_star_*` / `mermaid_block_*` …），
> 且由 `convert_file()` 在**每次 docx 构建时自动调用**，**ERROR 阻断、WARN 仅打印**
> （判定见 `WordFormulaPrecheckReport.has_errors`）。
>
> 所以正确的 R5 是**两级盲区**：
> 1. **覆盖域盲区**：预检绑在 docx 管线上，只会跑 `04-课件/学生讲义`、`04-课件/习题集`
>    这类**会出 Word 的域**。`03-知识点/`、`07-资料提炼/`、`06-学生侧材料/` 等
>    **永远不会被它检查** —— 实测那批 `bare_script_fatal` 存量里有相当比例正在这些域。
> 2. **手段盲区**：预检是**纯模式匹配**（源码正则 + 掩码），它能说「源码里有个可疑写法」，
>    但**说不了「这个文件到底渲没渲染出来」** —— 没有任何环节真的调用 pandoc 并核对产物。
>
> 另：**Obsidian 侧完全无人管**。`<div>` 吞公式、`\AA` 不渲染这类**只伤 Obsidian、
> 不伤 docx** 的缺陷，既不在预检视野内、也不在任何闸门内 —— 而这恰是用户最初的报障。
>
> 结论：`render_gate` 的价值应重新定位为「**渲染级断言 + Obsidian 栏 + 覆盖 docx 管线之外的域**」，
> **而不是**「从零建一个公式闸门」。新增规则则应**并入既有预检**（复用其
> `_append_precheck_issue` / 掩码 / 严重级基础设施），避免两套判据并行。


> **R5（更正版）是核心**：今天每一类缺陷都不是「没检查」，而是「**检查够不到那个地方**」——
> 要么不在覆盖域内，要么检查手段（模式匹配）看不见渲染结果。

## 三、优化方案

### P0-1 新增 `render_gate`（渲染闸门）—— 最缺的一块

对每个 changed md 跑两栏断言：

| 栏 | 方言 / 前置 | 断言 |
|:--|:--|:--|
| **出 Word** | `markdown+tex_math_dollars+tex_math_single_backslash+pipe_tables+raw_tex`，**且先跑 `_preprocess_markdown`** | `Could not convert TeX math == 0`；产物正文字面 `$ == 0`；oMath 不减少 |
| **Obsidian 阅读** | `commonmark+tex_math_dollars` | 行首块级 HTML 标签 == 0；`\AA` == 0；真 TAB 残名 == 0 |

**为什么先做它**：把今天全部 7 类一次覆盖，且**与既有闸门互补**（它查渲染、jsyaml 查结构）。
成本：一个脚本（今天用的探针稍作整合即可）。

### P0-2 净化逻辑收敛为**唯一模块**

建 `11-模板/scripts/md_sanitize.py`，导出 `sanitize(text)`（**有序**规则集）：

```
div 剥离 → 字体开关 → \AA（顺序：\text{\AA} → \mathrm{\AA} → 裸 \AA）
→ \text{} 内命令→Unicode → HTML 表转换 → \ce{} 展开 → 断行宏并回 → TAB 复位 → 实体归一
```

4 个消费方全部改为 import 它：`build-all-handout-docx.py` / `build_module_book.py` /
`gen_r1.py` / `gen_r1_mixed.py`。

**顺序即语义**：今天的第 7 类（`\text{\text{Å}}` 嵌套）就是**顺序错**造成的；
管线自己的处理器有顺序保护，源侧裸替换绕过了它 → 收敛成单一模块可根治。

### P1-1 导入边界加 **import gate**（治本）

MinerU 产物**入库前**强制：① 跑 `sanitize()`；② 跑 `render_gate` 两栏；
③ 打标记 `import_sanitized: <版本>`。
→ 缺陷**永不入仓**。存量按 domain 分批 backfill（今天已清完 div 与 `\AA` 的主要存量）。

### P1-2 固化**双方言测试矩阵**（纪律层）

把上表写进规范与技能：**任何「已修好」的结论必须写明在哪一栏测的**。
今天两次口径错（`\AA` 的 docx 影响、`$$` 跨行假阳性）根子都在这里。

### P2-1 生成物标记与「只改源头」纪律

- 生成物文件头写入 `generated_by: <脚本>`（可被闸门识别）
- 明令：**只在源头改**；对生成物的手工修复一律视为临时，须同时登记源头 issue
- 生成器可加断言：拒绝覆盖带「手工修复」标记的产物

### P2-2 一次性普查入口 `audit_formula.py`

把今天用过的 7 类**正则签名**（秒级、全库）+ 渲染抽查合成一条命令，纳入提交前检查。

## 四、落地顺序建议

| 优先 | 项 | 理由 | 成本 |
|:--|:--|:--|:--|
| **P0** | `render_gate` | 今天 7 类全在它盲区，一次到位 | 小 |
| **P0** | 净化模块收敛（4→1） | 已在漂移，越晚越贵 | 中 |
| P1 | import gate | 治本，需改导入流程 | 中 |
| P1 | 双方言测试矩阵 | 固化口径，防再犯 | 小 |
| P2 | 生成物标记 | 防「改生成物」重演 | 小 |
| P2 | `audit_formula.py` | 日常体检 | 小 |

## 五、附：本次会话的实测教训（供规范引用）

1. **成对定界符必须配对状态机**——「见到 `$$` 就切换」曾把正文误判为公式块，
   一个字面 `$` 从 6 飙到 204。**禁止「见标记即切换」。**
2. **扫控制字符类缺陷必须 hex 复核**（真 TAB = `09`；`5c 74` 是正常反斜杠），
   且判据写成 `chr(9)` 这类**不含反斜杠字面量**的形式。
3. **含反斜杠的正则一律 Write 成 `.py` 再跑**（`python -c` 会被引号层改写，
   我曾因此报出 20 文件 / 73 处的假系统性缺陷，真值仅 12 处）。
4. **源侧替换 LaTeX 宏必须与管线处理器镜像同序**。
5. **验收判据要独立于修复对象**：本次最有力的一条是「管线产物应与修复前逐字一致」
   （因为管线本就会做同样转换）——一次证明 docx 中性 + 零回归。
