## 〇、最重要的一件事：**发现并修复了一个真实缺陷，21 张卡差点被错标**

我先按上一轮的分层给「A 层 21 张」标「源确缺答案」，落盘后**抽查第一张就发现不对**：

```
题-有机-周环-DielsAlder反应endo选择性判断.md
  ## 参考答案
  ### (1) 环戊二烯的二聚
  Endo 过渡态：…（这里有完整答案）
```

**这 21 张卡本来都有答案。** 立刻 `git checkout HEAD --` 全量回滚（21 → 0）。

### 根因：`find_answer_section` 的段边界缺陷

段边界原先用「下一个**任意**标题」作结束：

```python
nxt = _ANY_HEAD.search(body, m.end())   # ❌ 匹配到任意级标题
```

但答案区里**紧跟子标题是常态**（`## 参考答案` → `### (1) …`），
于是段长被截成 **0 字符** ⇒ `has_entity=False` ⇒ 21 张有答案的卡被误判为"答案区空"。

### 修复：区界用「level ≤ 本级」

```python
def _end_after(m):
    """从 m.end() 起扫（不能从 m.start()，否则匹配到标题自己），
    找 level <= 本级的标题；###/#### 是答案区的子结构，要并入。"""
```

修复过程中又暴露两个连带 bug：
1. **`_ANY_HEAD` 不捕获 `#` 号**（`h.group(1)` 拿到的是标题文字不是井号）⇒ level 判断失效。
   改为 `^(#{1,6})[ \t]*(.+?)[ \t]*$`。
2. **外链型判据被带坏**：`_EXT_REF` 原来只认「答案见/答案在」，
   而 `> 见 [[卷-01]] 的参考答案区` 这种**省略主语**的写法判不出来 ⇒ 被当成有实体答案。
   放宽为 `(?:答案(?:见|在)|见|参见|详见)[^\n]{0,24}?\[\[`。

**回归测试 7/7 通过**（新增用例进 `pipe_tests.py`，现 **26/26 全绿**）；
三张真实卡段长从 0 修复为 1994 / 1095 / 2873 字。
