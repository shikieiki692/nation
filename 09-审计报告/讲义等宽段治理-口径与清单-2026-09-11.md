### 阶段 6 · 字体修复（ASCII 等宽网格恢复）

**根因是两处归一化，缺一不可**：
1. **样式层**：`docx_utils.postprocess_pandoc_docx()` 的 `for style in doc.styles` 把 `VerbatimChar` 的 `SimSun` 换成 `FangSong`；
2. **run 层**（同函数 1139–1148 行）：把每个 run 的 `eastAsia` 重置为 仿宋/TNR。**run 级直格式会覆盖样式**，所以只改样式完全无效。

**修法**：新增常量 `MONO_FONT = "SimSun"`、`MONO_STYLES = {"VerbatimChar", "SourceCode"}`；
样式层豁免这两个样式，且 `pStyle = SourceCode` 的段落内 run 层强制 `ascii/hAnsi/eastAsia/cs = SimSun`。
选 SimSun 的理由：西文字形半角等宽、汉字全角，天然成网格，字形仍是衬线、不刺眼。

**验证**：`VerbatimChar` / `SourceCode` = SimSun；`Normal` / `BodyText` / `FirstParagraph` / `Table`
仍为 `FangSong + Times New Roman`、`Heading1` 仍为 `SimHei + TNR` —— 正文与标题**零误伤**。

**历史产物**：新增 `patch_mono_font.py`，直接给已存在的产物打补丁（改 styles.xml 两个样式 +
`SourceCode` 段落内 rFonts），**81/81 份已生效、0 损坏、幂等**（复跑 0 改动）。
踩坑：同一份 `styles.xml` 的前缀是**混合**的（`VerbatimChar` 用 `ns0:`、`SourceCode` 用 `w:`），
正则不能假定统一前缀，且 rFonts 的前缀要取自实际命中的元素。
