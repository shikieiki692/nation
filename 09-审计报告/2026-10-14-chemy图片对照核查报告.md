# chemy 图片对照核查报告

> 🔴🔴 **更正（2026-10-14 同日）**：本报告「库内 ≈87dpi vs 站点 ≈255dpi / **2.9×**」的结论**不可比、已作废** ——
> 站点图是**整页宽条带**（1505px 含大量白边），库内图是**同图形的紧裁切**，比「图宽」不成立。
> 按**墨迹外接框**归一后的**真实增益只 1.26× 线性**（墨迹量比 1.56 ≈ 1.26²）。
> 实测与执行见 **`09-审计报告/2026-10-14-chemy图升级线-实测与决策.md`**（已换 314 图 / 186 卡）。
> 本报告 §一/§二 的 dpi 数值仅供**历史审阅**，勿再引用。
> **触发**：owner 指令「注意图片的引用，当前知识库 OCR 后的图片可能会有问题，可以和这个项目对照一下」。

## 〇、结论先行

| # | 结论 |
|:--|:--|
| 1 | 🔴 **库内存量 OCR 切图分辨率系统性偏低**：宽中位 **515 px**；站点原卷切图宽中位 **1,505 px**（≈ **2.9 倍**）。按 150 mm 版面折算，库内 ≈**87 dpi**、站点 ≈**255 dpi**——库内**大面积不满足闸门 12「每图 dpi ≥150」**。|

## 一、量化对照

| 指标 | 存量·库内 OCR 切图 | 39 届·站点原卷切图 |
|:--|--:|--:|
| 被引用图 | 6,378 次 / 6,307 张（1,201 卡）| 1,146 次 / 1,142 张（210 卡）|
| **宽 中位** | **515 px** | **1,505 px** |
| 宽 最小 / 最大 | 46 / 1,862 | 185 / 1,642 |
| 高 中位 | 201 px | 245 px |
| 窄条（高<90 或 宽<150）| 429 张（6.7%）| 86 张（7.5%）|
| `images/` 全目录 | 10,037 张（宽中位 609 / 高中位 204）| — |

**判读**：
- 库内图**宽**的分布明显偏小——OCR 切图按文本块紧凑裁切；站点图按**原卷版面宽度**切（1,505 px ≈ A4 正文宽），故纵横比与清晰度均更优。
- 这解释了长期记忆中的历史遗留「**打印版低 DPI 图**」问题（`题库架构总览` §八.6：「学生版 505 张引用图中 437 张有效 DPI<150，全库无更大副本」）。**chemy 域现在有更大副本了**——即站点 assets。

## 二、P2 批1 的图片处理（已落地）

1. **来源**：站点 `dist/assets/`（13,935 张 / 262 MB），按题面与答案 HTML 中实际引用**精确提取**——39 届仅需 1,159 张 / 24.8 MB（不必全量下载）。
2. **下载通道**：`https://brucejllpku.github.io/Chemy-/assets/<name>`（GitHub Pages CDN，**无 60 req/h 速率限制**）。
   ⚠️ 三条坑，已写入工具备注：
   - `raw.githubusercontent.com` 首轮不可达（`schannel: server closed abruptly`），**次轮恢复** → 须带重试；
   - `api.github.com/.../contents/` **单目录上限 1,000 条**（`dist/assets` 有 13,935 条，被静默截断）→ 全量清单须走 **`git/trees?recursive=1`**；
   - 未认证 API 限额 **60 次/小时**（本轮用到 remaining=20）→ 批量下载**禁用 API**，一律走 Pages。
3. **格式**：webp → **jpg**（quality=92；alpha 白底合成），文件名 = **内容 sha256（64 hex）**，与库内 8,823 张 jpg 命名体例一致；**13 张 SVG 原样复制**（PIL 不可读，⛔ 不栅格化、不重绘）。
4. **核验**：新卡图引用 **1,159 / 断链 0** / 残留 `assets/` 引用 **0**；逐张目检抽样（含窄条图）确认内容与原卷一致。

## 三、存量卡升级可行性（P3 建议）

**定位规则**：站点图名 `e<届>-p<套>-[qa]<题号>-<序号>-<hash>.webp`（`q`=题面图、`a`=答案图）↔ 库内卡 `(届, 套, 题号)`。
配合 P1 的 `mapping.json`（库内套 → 站点 paper），可**逐卡精确定位**。

| 届 | 可定位卡 | 站点有对位图 | 覆盖率 |
|:--|--:|--:|--:|
| 32 | 124 | 94 | 76% |
| 33 | 134 | 103 | 77% |
| 34 | 164 | 130 | 79% |
| 35 | 182 | 159 | 87% |
| 36 | 122 | 99 | 81% |
| 37 | 153 | 126 | 82% |
| 38 | 121 | 101 | 83% |
| **合计** | **1,000** | **812** | **81.2%** |

**建议（P3 单列一条线，须 owner 立项）**：
1. 只**替换**（不新增）——把库内卡对位到站点 `q` 图的引用换为高清版，落 `images/<新sha>.jpg`；
2. **逐张目检**后方可换（沿用「图像资产 100% 视觉核验铁律」），并保留旧图（旧图可能含 OCR 正确而站点切偏的个例）；
3. 换图必走「图数守恒断言 ＋ 断链 0」；
4. 未覆盖的 **188 张（18.8%）** 维持原图并在卡内标注「⛔ 站点无对位图」。
