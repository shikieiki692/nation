## 三、关键突破：从 git 历史恢复 R5

R5 9,137 处集中在**视频课笔记**（学而思/质心/Zchem），引用的
`![[笔记名_images/哈希.jpg]]` 全部指向**未入库**的图片目录。

### 排查链路

1. **`_笔记_images` 目录全库 0 个**（应为几百个）→ 视频课笔记的图从未落盘
2. **裸 basename 全库不存在** → 不是路径写错
3. **库内 120 个 PDF 都是 `.workbuddy/_render/`（渲染产物）** → 没有源 PDF 可重提
4. **媒体仓库备份 zip（16,812 张）** → R5 与 zip 交集 = 5 张
5. **`git rev-list --objects --all` 列出 9,091 个 `*_笔记_images/` 下的历史图片** → 💡
6. **验证：`git cat-file -s 4f03…:<path>` 返回 1079 字节** → blob 完整可取

### 实施

`recover_images_from_git.py`：

1. `git rev-list --objects --all` → 建 `basename → blob sha` 索引（53,063 条）
2. 对 R5 每条引用：
   - 带目录的引用 → 恢复至 `<md所在目录>/raw路径`（原位）
   - 裸 basename → 恢复至 `媒体仓库/basename`，引用改 `![[basename]]`
3. `git cat-file --batch` 批量取 blob（用文件中转避免管道死锁——首次 PIPE 模式 SIGTERM）

### 落地数据

## 七、附加发现

   与本次修复无关，下一轮可考虑改 `![[...]]` 化简

   （`媒体仓库/` 不入库，新增只在本机生效）
