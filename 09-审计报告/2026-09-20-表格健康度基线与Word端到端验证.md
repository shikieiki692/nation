# 表格健康度基线快照（2026-09-20）

> **用途**：Word 端到端验证（实证本批收益）+ 全库表格健康度基线（供后续回归对照）。
> **方法**：只读扫描，不改动任何文件。判据与主转换器 `fix_html_tables.py` 同源。
> **扫描范围**：全库 10,133 个 md 文件（排除 `.git`/`.obsidian`/`node_modules`/`媒体仓库`/`.workbuddy`）。

## 一、Word 管线端到端验证（本批收益实证）

### 1.1 方法

本批结论若只在 md 层面成立、却在 Word 产出端无收益，则工作价值不成立。故做**端到端验证**：

- **「前」** = `.workbuddy/tmp/html_table_backup/` 里的**原始字节备份**（转换前）
- **「后」** = 工作区**现状**
- 两侧各跑一次 `pypandoc`（pandoc 3.10，`--from=markdown+tex_math_dollars+pipe_tables --to=docx`）
- 数 docx 内 `w:tbl`（表格对象数）与 `m:oMath`（OMML 公式数）

> **⚠️ 挑样本铁律**：必须从**备份中确认 `old <table> 数 > new <table> 数`** 的文件里挑。首版误选 `第33届…（解析版）.md`——该文件 **HEAD 里本就无 `<table>`**、本批未改 → A/B 显示「零变化」假象。**不用 `git show HEAD:file`**（本机 `core.autocrlf` + `.gitattributes` 使 `git show` 给仓库层 LF，工作区实为 CRLF，且部分文件已被其它会话改过）。

### 1.2 结果

| 样本 | 原 HTML 表数 | `w:tbl` 前 → 后 | 公式 (OMML) 前 → 后 | 判定 |
|:---|---:|:---:|:---:|:---:|
| 普通化学原理（mineru 副本） | 92 | **1 → 80** | 5642 → 5642 | ✅ 收益 |
| 普通化学原理（06 导入副本） | 92 | **0 → 79** | 5642 → 5642 | ✅ 收益 |
| 人教版必修2（教师版） | 61 | **11 → 44** | 706 → 706 | ✅ 收益 |
| 化学竞赛能力测试（含 rowspan） | 18 | **33 → 43** | 2951 → 2951 | ✅ 收益 |
| 奥赛试题解析（第4版，含 rowspan） | 11 | **5 → 8** | 2222 → 2222 | ✅ 收益 |
| 第八讲原子结构（三） | 7 | **15 → 21** | 143 → 143 | ✅ 收益 |

**结论**：

1. **收益成立** —— 全部 6 个样本 `w:tbl` 显著上升（HTML 表在 Word 端本不产生表格对象，转换后成为真表格）。
2. **零回归** —— 6 个样本**公式数完全不变**（5,642/5,642、706/706、2,951/2,951、2,222/2,222、143/143）。转换只把 HTML 表变 pipe 表，**不触碰任何数学内容**。
3. **表格数守恒** —— `w:tbl` 的增量 < 原 HTML 表数，属正常：部分表单行/单列被 pandoc 视作非表格；剩 ∈ 拒收判据（含图/实体/宽度）的表依设计保留。

### 1.3 隔离实验（前提复核）

为确证「HTML 表 → 无表格对象」这一前提，做最小隔离实验：

| 用例 | `w:tbl` | OMML | 残留 `$` | rawHTML |
|:---|---:|---:|---:|:---:|
| HTML 表（纯文字） | **0** | 0 | 0 | False |
| MD 表（纯文字） | **1** | 0 | 0 | False |
| HTML 表（含公式） | **0** | 2 | 0 | False |
| MD 表（含公式） | **1** | 2 | 0 | False |
| HTML 表（默认 reader） | **0** | 0 | 0 | False |
| MD 表（默认 reader） | **1** | 0 | 0 | False |

**要点**：HTML 表**无论 reader 怎么配**都拿不到 `w:tbl`；而含公式时 OMML 均为 2 —— 说明 pandoc 自带的 inline 解析器**能**处理 HTML 表内的 `$…$`，**md 层的公式「乱码」是 Obsidian 渲染侧问题，不是 pandoc 侧问题**。所以转换的 Word 端收益集中在**表格对象化**，公式数不增不减。
