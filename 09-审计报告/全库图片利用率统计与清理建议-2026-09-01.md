### 9.6 踩坑记录

1. **`send2trash` 在中文长路径下失败**——它会把路径转成 8.3 短名（`学生讲~2\_RENDE~1\2026-0~2\page-1.png`）再调 `SHFileOperation`，短名解析不了就报 `[WinError 2]`。但**文件实际已删除**（是事后校验的假警报）。
2. **直接用 `SHFileOperationW` 传宽字符长路径可行**，但中文路径下同样返回 `rc=2` 而实际成功。→ **成功判定必须以「文件是否还在」为准，不能看返回码**。
3. PowerShell 的 `Add-Type` / `Reflection.Assembly.Load` 被安全策略拦截，无法用 `Microsoft.VisualBasic.FileIO.FileSystem` 走回收站。
4. 最终方案：自写 `.workbuddy/scripts/trash_files.py`（ctypes + `SHFileOperationW` + `FOF_ALLOWUNDO`），分批 200 个提交，批后按存在性校验。

## §16 阶段八：真题子题断链折叠 + 口径对齐（2026-09-01）

### 16.1 先破案：v4 的「幻影断链」是个脚本 bug

v4 报告「10 条可折叠目标，但正文 0 处引用」，一度怀疑校验器凭空生成条目。
复用校验器自身逻辑重扫后确认：**这些引用全都带完整路径**，形如
`[[04-题库/真题/第36届初赛第二场/题-036b-1-1-铝铁合金制备方程式|题-036b-1-1]]`。

> 教训：**不要自己重写链接解析去"对齐"校验器**。直接 `import validate_kb`
> 复用 `collect_md_files` + `scan_file`，口径才能 100% 一致。

### 16.2 口径差异有多大

自己重扫全库 md 得到 **33,392** 条"断链"，校验器只报 **143**。原因是校验器：

| 差异点 | 自扫 | 校验器 |
|:---|:---|:---|
| 扫描范围 | 全库 9,695 md | 仅 `INCLUDE_DIRS`（6,162） |
| frontmatter | 算进正文 | 单独归 `断链-frontmatter`（1,597） |
| 排除目录 | 无 | `09-审计报告`/`06-外部资料导入`/`00-首页`/`.obsidian` 等 |
| 占位符 / 图片 / 目录链接 | 全当断链 | 跳过 / basename 解析 / 视为有效 |

因此 33,392 里绝大多数是噪音（如 YAML 数组 `[[0, 0]]` 被当链接）。

### 16.3 根因：真题是「一题一文件」的题组制

真题文件按**大题**组织，文件名取首个小问描述。生成器写关联小问时把子题号带了进去，
于是 `[[题-037-1-2-Ga低价碘化物结构]]` 找不到文件——**内容其实就在 `题-037-1-GaN刻蚀方程式.md` 里**
（该文件答案段标着（1）（2）（3））。

折叠前逐项机器对账「父文件内实际小问数 vs 链接请求子题数」，**全部吻合**：
