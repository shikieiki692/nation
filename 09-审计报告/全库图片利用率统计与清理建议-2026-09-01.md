### 9.6 踩坑记录

1. **`send2trash` 在中文长路径下失败**——它会把路径转成 8.3 短名（`学生讲~2\_RENDE~1\2026-0~2\page-1.png`）再调 `SHFileOperation`，短名解析不了就报 `[WinError 2]`。但**文件实际已删除**（是事后校验的假警报）。
2. **直接用 `SHFileOperationW` 传宽字符长路径可行**，但中文路径下同样返回 `rc=2` 而实际成功。→ **成功判定必须以「文件是否还在」为准，不能看返回码**。
3. PowerShell 的 `Add-Type` / `Reflection.Assembly.Load` 被安全策略拦截，无法用 `Microsoft.VisualBasic.FileIO.FileSystem` 走回收站。
4. 最终方案：自写 `.workbuddy/scripts/trash_files.py`（ctypes + `SHFileOperationW` + `FOF_ALLOWUNDO`），分批 200 个提交，批后按存在性校验。

### 10.3 ⚠️ 误删事故：脚本漏识别了三种引用写法

删除后 `validate_kb.py` 报 Warning 从 2,576 涨到 **2,848**，图片缺失 357 → **476**。排查出 `image_usage_stats.py` 三个漏洞：

| # | 漏洞 | 后果 |
|---|---|---|
| 1 | `RE_WIKI` 只写 `!\[\[`，**漏了 `[[` 单括号** | YAML frontmatter 的 `key_images: ["[[media/xxx.jpg]]"]` 全被当无人引用 |
| 2 | `SKIP_DIRS` 含 `_归档`/`_archive`/`备份`，**连引用扫描一起跳过了** | 归档目录里 md 的 `![[...]]` 引用被忽略 |
| 3 | `.canvas` 是 JSON，图片写在 `{"type":"file","file":"xxx.jpg"}` 里 | 三个正则全部抓不到 |

**修复**（已写入脚本）：
1. `RE_WIKI` 改为 `\[\[([^\]\|#\^]+)`——同时覆盖 `![[x]]` 与 `[[x]]`。
2. 拆成两套目录集合：`REF_SKIP_DIRS`（引用扫描，只排除 `.git/.workbuddy/node_modules/.obsidian/__pycache__/.trash`）与 `SKIP_DIRS`（图片清单=删除候选，额外排除 `_归档/_archive/备份`）。**归档目录的 md 必须参与引用扫描，但其图片不作为删除候选。**
3. 新增 `RE_CANVAS = r'"file"\s*:\s*"([^"]+)"'`，仅对 `.canvas` 生效。

**修复效果**：识别到的唯一引用 basename **38,550 → 49,046**（多找出 10,496 条）；被误删的 118 个文件重新判定为「在用」，0 个残留误判。

### 10.4 误删还原过程

1. 用**最保守口径**重建还原集：凡被 `![[ ]]` / `[[ ]]` / `![]()` / `<img src>` / canvas `"file"` 任一语法引用的已删图片，全部纳入 → **110 个 basename / 118 条路径**（涉及 16 个 md，其中 9 个在 `_归档`）。
2. 写 `restore_from_bin.py`：解析回收站 `$I<随机>` 元数据拿原始路径 → 把对应 `$R<随机>` 拷回原位。
   - **坑1**：网上流传的偏移 `0x14=长度 / 0x18=路径` 是旧版（version=1）布局。本机 version=2 实际是 **`0x18`=路径字符数、`0x1C` 起=UTF-16LE 路径**。用错偏移解析出 0 条。
   - **坑2**：`os.path.join("C:", "$Recycle.Bin")` 得到 `C:$Recycle.Bin`（盘符后**不加分隔符**），目录不存在。必须写 `"C:\\$Recycle.Bin"`。
   - **坑3**：`S-1-5-18`（SYSTEM）等 SID 目录会 `PermissionError`，需 try 跳过。
3. 第一次还原 118 个成功后，又用「basename 是否还能在全库解析」（Obsidian 的真实解析规则）做二次兜底 → 再发现 **23 个真断链**（命中 `03-知识点` 的 Frost图 / Latimer图 / 体心立方堆积 / 热力学循环 等正经内容文件），对应 **39 条路径**，全部还原。
   - 说明：第一轮扫出的 160 个候选中，137 个是**假警报**——索引文件（`图片索引-Ch351-482.md`、`zhao_ch351-482_image_index.md`）引用的图，同名副本仍存在于书自己的 `_images` 目录，basename 照样能解析。
4. 合计还原 **157 条路径**，逐个校验文件大小与删除前记录一致，**0 异常**。
