## 三、事故记录与处置：陈旧真实索引（幻影「已暂存删除」）

- **现象**：全量 QA 时发现 `git status` 在 `04-题库/教材习题/北斗40/` 报出 `D `（已暂存删除）10 条、`??` 10 条，另 `07-…/习题-北斗40-2015BAT4二模.md`、`09-审计报告/…图片映射清单.md` 各 1 条 —— 共 **12 处幻影删除**，而文件在工作区**确实存在**。
- **根因**：本会话批5g 曾在**真实索引**上执行过一次 `git add`（快照=当时的 HEAD `a3e329721`），其后所有提交均走**临时索引**；于是真实索引长期停留在旧快照，相对新 HEAD「缺少」后加的文件 → 表现为「已暂存删除」。
- **风险等级：高**。任何从真实索引直接 `git commit` 的会话，都会把题-369~378 等 12 个文件**真的删掉**（与 09-20 记录的「并行会话提交误删 9 张题卡」同类事故）。
- **处置**：`git add -- <北斗40目录> <2015BAT4二模台账> <图片映射清单>` 将真实索引对齐 HEAD/工作区；复核**全库 `D ` 计数＝0**、北斗40 目录 `git status` 洁净。
- **新增纪律**：**用过临时索引后，必须把真实索引对本次涉及的路径重新 `git add` 对齐**（不能只删 tmp 索引）；收尾必查 `git status --porcelain -uall | awk 'substr($0,1,2)=="D "{n++}'` 是否为 0。

## 四、其它工程记录（本会话）

- **HEAD 并发前移被 git 正确拦截**：知识锚点改指提交时，`read-tree → add → commit` 链条中的 `pre-commit`（render_gate 19 文件）耗时期间，并行会话（`1b253efd6` 补 `\ce{}` 转换器）提交致 HEAD 前移 → git 报 `cannot lock ref 'HEAD': is at 1b253efd6… but expected 1565e8b68`（exit 128）**拒绝提交**，未造成误删；基于新 HEAD 重试通过。**印证**：临时索引 + 一条 `&&` 链可防「树错误」，但**不能防 HEAD 前移**——需接受「失败即重试」，绝不可 `--force`。
- **推送链路**：`git -c http.proxy=http://127.0.0.1:7897 -c credential.helper=manager push` 生效（根因＝`~/.gitconfig` 的 `[credential] helper =` 空值清空 helper）。
- **平台陷阱**：bash 内联 Python 中的反引号会被命令替换吞（任务卡 commit 哈希曾丢失）→ 含反引号的脚本一律落 `.py` 再跑，改文件用编辑工具。
