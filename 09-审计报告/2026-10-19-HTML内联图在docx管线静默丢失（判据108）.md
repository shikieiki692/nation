# HTML 内联图在 md→docx 管线静默丢失

## 〇、一句话结论

题卡中用 HTML 标签写的图（`<img src="images/x.jpg"/>`）在 **pandoc 转 docx 时被静默丢弃**——
`document.xml` 里连 `<img>` 字样都不剩、无占位符、无警告。全库 **643 张卡、3,775 处**受影响。
这些卡在 Obsidian 里**看着有图**，一旦进入组卷/学生版/讲义等 docx 管线就变成**无图**。

## 一、根因（对照实验）

用同一张真实 jpg 造三种写法，`pandoc 3.10` 转 docx 后数 `word/media/` 内嵌媒体：

| 输入写法 | docx 内嵌媒体数 |
|:--|--:|
| `![](images/x.jpg)`（Markdown） | **1** |
| `<img src="images/x.jpg"/>`（HTML） | **0** |
| 两者并存 | **1**（只有 Markdown 的那张进了） |

补充验证：

- 换 reader（`markdown` / `markdown+raw_html` / `gfm` / `commonmark_x`）**均 0 张** ⇒ 与 reader 无关；
- 加 `--resource-path`（图片路径可解析）**仍 0 张** ⇒ 不是路径问题；
- `document.xml` 内**无任何 `img` 残留** ⇒ docx writer 直接吞掉 raw HTML，不落地也不报错。

**机制**：pandoc 的 markdown reader 把裸 HTML `<img>` 记为 *raw inline*；docx writer 不支持 raw HTML，
按规范**丢弃**，且不产生 warning。整条链路上没有任何环节会提示"这里有张图没转"。

## 七、判据沉淀

- **判据 108（HTML 内联图在 docx 管线静默丢失）**：`<img src>` 写法在 pandoc→docx 中**完全丢弃**
  （无媒体、无占位、无 warning、`document.xml` 无残留）。凡走 md→docx 的卡，HTML img 等于无图。
  ⇒ **"文档中有图引用"不等于"成稿里有图"**；判定缺图必须以**渲染产物**（`word/media/` 计数）为准，
  不能只看 Markdown 源码或 Obsidian 预览。
- **判据 109（语法转换的等价性验证）**：把 `<img>` 转 `![]()` 前必须①确认无 `width`/`height`
  属性（有则丢尺寸）、②确认 `src` 文件存在、③**转换前后各转一次 docx 并比 `word/media/` 计数**
  （期望 +n，多则说明误伤了别处）。
- **判据 112（表内嵌图不可单独替换）**：raw HTML `<table>` 内的 markdown 不会被渲染
  ⇒ 单独把 `<td><img/></td>` 换成 `![]()` 会让"图变字面量文本"，比原来更糟。
  含 `rowspan` 的图文表在 docx 中整表塌陷（`w:tbl=0`），只能整表重构。
