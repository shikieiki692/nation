## 二、过期内容：48 条只是冰山一角（判据有洞）

### 2.1 官方口径复现成功

严格复现 `validate_kb.check_stale`（`threshold_days=30`）：

```text
过期文件（updated 距今 > 30 天）: 48
  27  03-知识点/无机和结构化学
  21  03-知识点/有机化学
  48  type=知识点  status=已填充
陈旧程度: 31-60 天 2 ｜ 61-90 天 1 ｜ 91-180 天 45 ｜ >180 天 0
```

### 2.2 🔴 但 48 这个数字本身不可信—— 判据存在 99.3% 盲态

读`check_stale` 源码（`11-模板/scripts/validate_kb.py:867-879`）：

```python
updated = fm.get("updated")
if updated and isinstance(updated, str):        # ← 类型闸门
    try:
        d = datetime.date.fromisoformat(updated)
```

而 frontmatter 里有**两种写法**：

| 写法 | YAML 解析结果 | 是否被检查 |
|---|---|---|
| `updated: 2026-05-25`（裸日期，占绝大多数） | `datetime.date` 对象 | ❌ **静默跳过** |
| `updated: "2026-05-25"`（带引号） | `str` | ✅ 被检查 |

`datetime.date` 不是 `str` ⇒ 直接落进 `if` 的 false 分支，**无任何提示地跳过**。实测：

```text
validate_kb 当前报出的过期（仅 str）      : 48
被 isinstance(str) 静默跳过的 date 对象  : 6,718
⇒ 若判据修正，真实过期总量: 6,766
盲态覆盖率: 99.3% 的过期文件从未被检查过
```

我第一次用 `str(upd)[:10]` 截断解析时得出 **6,766**，与validate 的 48 差 140 倍——**差值全部来自这个类型闸门**，不是数据不一致。

### 2.3 真实的 6,766 条长什么样

status：  已填充 5,622 ｜ 已补全答案 579 ｜ 已审校 176 ｜ (空) 93 ｜ deprecated 73 ｜ …
行数：    min=1  中位=51  max=2,255

**关键观察：**

1. **无一超过 180 天** ⇒ 全库不存在「放了一年以上没碰」的腐化内容。
2. **主体是 `type=题目`（4,665）** ⇒ 题目卡的「updated」本就是入库时间戳，不代表内容需要复核。
3. **3,256 个<50 行的薄页** 才是真正值得看的，但其中大批是 `04-题库/元文件/` 下的**占位/索引页**（如 `物理化学Atkins/主题10-分子对称性-习题.md` 只有 1 行），属正常形态而非缺陷。

### 2.5 复评：闸门该不该修？（owner 二次追问后的结论）

上一版我建议「P0 修闸门」。**复核后改判：不修。** 理由是收益侧的两条前提都被证伪。

#### 2.5.1 前提一：「报告会被淹没」→ ❌ 证伪

`validate_kb.py:1215-1223` 的 Info 明细**只输出分类计数，不列逐条**：

```python
# Info 明细（仅显示数量，不列出全部）
if report.infos:
    for c, n in sorted(by_info.items()):
        lines.append(f"- **{c}**: {n} 处")
```

只有 Error / Warning 会列明细表。⇒ 修闸门后报告从 `- **过期内容**: 48 处` 变成 `6,766 处`，**体量不变**。当前报告 30 行，修完仍是 30 行。「淹没」是错的。

**但代价真实存在**：`save_metrics()`（`:1248`）会把 `stale_files` 追加进 `02-数据库/quality-metrics.jsonl` 时序文件。48 → 6,766 是**指标口径断裂**，历史趋势图从此不可比（该库 MEMORY 明确要求「做账」和量化自洽）。

#### 2.5.2 前提二：「露出来的 6,766 里有真信号」→ ❌ 严重证伪

按「是否值得人工看」分层：

| 层 | 数量 | 占比 | 性质 |
|---|---:|---:|---|
| ① 题目/真题卡 | 4,665 | 68.9% | `updated` = **入库时间戳**，入库即「不更新」是正确状态 |
| ② 占位/索引/元文件页 | 245 | 3.6% | 薄是正常形态 |
| ③ 非题目 + 非占位 + ≥50 行 | 1,796 | 26.5% | 多为**成型但需定期复核**的知识点 |
| ④ 非题目 + 非占位 + <50 行 | 60 | 0.9% | 疑似真缺口 |

噪音（①②）占 **72.6%**。

**④组 60 条逐张目检 ⇒ 全部不是缺陷：**

| 样本 | 实际内容 | 定性 |
|---|---|---|
| `03-知识点/有机化学/Lewis式.md`（3 行） | `status: deprecated`，孪生页已并入`[[Lewis结构式]]`，正文写明合并理由与引用改指清单 | ✅ 治理产物 |
| `03-知识点/化学原理/共振结构.md`（7 行） | `status: deprecated`，并入 `[[共振论]]`（829 行 vs 68 行） | ✅ 治理产物 |
| `03-知识点/化学原理/沉淀溶解平衡.md`（9 行） | `status: deprecated`，并入 `[[溶度积]]`，含 6 个别名迁移说明 | ✅ 治理产物 |
| `04-题库/元文件/…Atkins/主题10-分子对称性-习题.md`（**1 行**） | 正文全压在一行：16 道题 + 完整答案 + 知识点索引表 |✅ **行数判据失效** |
| `04-题库/教材习题/赵鑫光/题-赵鑫光-配位-例1.md`（4 行） | `fidelity: 原书逐字`，完整题目 + 完整答案 | ✅ 正常题卡 |

**两个致命发现：**

1. **「薄页」判据本身失效** —— 本库大量 md 把整页压成 1 行（Atkins 页 1 行含 16 题＋答案＋索引表）。行数与内容量**不相关**。
2. **退役页的 `updated` 本就该冻结** —— `deprecated` 页 73 条，合并完成后不再维护，日期陈旧是**正确状态**。把它们算作「过期」是语义错误。

#### 2.5.3 修正后的统计

把 `deprecated` 排除后再看真候选（活跃 + 薄页 + 非题目）：

```text
过期总量 6,766 ｜ deprecated 73 ｜ 活跃页 6,693
status 分布：已填充 5,670 ｜ 已补全答案 579 ｜ 已审校 176 ｜ (空) 93 ｜ deprecated 73 ｜ …
```

而6,693 条活跃页里，**无一超过 180 天**（最大陈旧 156 天），主体是题目卡与已审校成稿。**全库不存在「放了一年以上没碰」的腐化内容。**

#### 2.5.4 判定

| 选项 | 结论 |
|---|---|
| 修闸门 + 不改口径 | 🔴 **不建议**：输出 72.6% 噪音，metrics 时序断裂，且「薄页」判据已证伪 ⇒ 报出来的仍不可用 |
| 修闸门 + 按 type/status/体量分级 | 🟡 理论干净，但**当前无判据可依**（行数失效、题目卡语义特殊），需要先定义「什么才算内容陈旧」——这是业务决策，不是代码修复 |
| **不动** | ✅ **建议**：闸门是**保守失效**（漏报而非误报），对 Warning/Error 零影响；真实风险已由 git 历史与专项抽查覆盖 |

**核心判断：`check_stale` 是「过期内容」这一个纯提示性Info 项，它既不影响 Error/Warning，也不参与任何放行闸门。** 漏报 6,718 条的代价（看不到一个本来就没人看的指标）远小于改动它的代价（引入无法定义的新口径 + 打断 metrics 时序）。

**如果一定要动，唯一正确的形态是**：先由业务侧定义「过期」语义（例如：`type in (知识点, 学生讲义, 课件)` 且 `status != deprecated` 且 N 天未更新），再改判据。**这是口径决策，不是本轮该顺手改的 bug。**

## 三、方法论沉淀（本轮新增判据）

1. 🔴 **凡判「某类问题很少」先查是否有类型闸门在静默过滤。** 本轮 48 vs 6,766 就是 `isinstance(x, str)` 造成的。判据链上每一层 `if` 都可能是黑洞。
   同类已知：basename 卡号复用（曾虚高 169 族）、`status` 枚举白名单、`is_placeholder_target()` 收录范围。

2. 🔴 **「引用初筛」用文件名子串匹配会虚高。** 上一轮「975 张被引用」用的是子串匹配；换成严格 `![[name]]` / `![[name|alias]]` / `![](path)` 正则后为 **1,403 张被引用 / 536 张未引用**。子串匹配会把OCR 源料 md 里的路径文本算成引用。

3. 🔴 **范围扫描必须覆盖全库一级目录。** 上一轮只扫 7 个目录得 1,188，实际 1,939——漏掉 `mineru`／`2026机构初赛模拟题`／`clayden 有机化学` 等顶层素材目录，漏了 751 张。

4. 🔴 **「未引用」≠「可删」。** 必须再分区：OCR 源料 / 归档保真区 / 红区的未引用资产属**可追溯性资产**，不是垃圾。

5. 🔴 **元数据（`updated`）与 git 历史不一致时，以 git 为真值。** 批量脚本写死的日期不会跟着内容迭代走。
