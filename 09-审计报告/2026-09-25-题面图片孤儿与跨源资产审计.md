# 2026-09-25 题面图片孤儿与跨源资产审计

## 一、审计目标与纪律

本轮目标是核查两个高风险缺图题的图片资产是否存在“未被 OCR 引用但可能是真实题图”的候选，并区分题面图、答案图、邻题图和跨源污染资产。

硬纪律：

1. 只接受经视觉核验且属于题面的物理哈希图片。
2. 答案图、答案结构条、相邻题答案/解析图不得上移、裁切或替代题面。
3. 未引用图片不能因为“看起来像结构式”就绑定到当前题。
4. 来源承接不清时只登记歧义，不补题、不反推、不猜答案。
5. 本轮没有把任何候选图写入题面，也没有改变题-1088、题-155 的隔离状态。

## 二、执行方式

- 使用根目录脚本 `broken_link_audit.js` 运行集合审计。
- 该脚本本轮实际覆盖两个图片目录，统计物理 JPG、OCR 图片引用、去重引用 hash、未引用 JPG、source-local 缺失引用、`媒体仓库/` 全局缺失引用及 compact 候选。
- 对高概率候选、compact portrait/square 候选、部分大图和剩余候选列表做了视觉筛查。
- 所有题库记录更新通过 KB Vault MCP 完成。

> [!warning] 脚本命名债务
> 历史报告曾称 `broken_link_audit.js` 已退役，但本轮在根目录复用了同名脚本。它现在实际是“题面图片孤儿/重复资产审计”，不是全库 Markdown 断链审计。后续建议改名为 `question_image_orphan_audit.js`，或在脚本头明确限定作用域；本轮不直接改名，避免历史引用与 `kb_move autoFix` 不修引用造成新的断链。

## 五、工具与流程债务

1. **脚本命名冲突**：`broken_link_audit.js` 名称与历史“全库断链审计”语义冲突，当前脚本只覆盖两个图片目录；2026-09-25 已在脚本头明确标注“题面图片孤儿/重复资产审计、非全库断链审计”及建议名称。
2. **脚本作用域有限**：本报告统计不是全库图片断链审计，也不是 `媒体仓库/` 全量资产审计。
3. **视觉债务未清**：题-1088 的 184 张、题-155 的 111 张未引用 JPG 尚未逐张视觉穷尽。
4. **`kb_search` 大目录 glob 可能截断**：不能直接把截断结果当完整集合。
5. **`kb_read` 长输出会截断**：关键结论必须用精确行段或 grep 锚点复核。
6. **`kb_bash` 只支持很窄的只读命令白名单**：`node`、`Get-Item`、`Get-Content` 等均可能被拒，不能依赖它做通用只读审计。
7. **`kb_edit` 多行 oldText 对 CRLF/转义敏感**：批量编辑失败时不得视为已落地；应使用短、单行、唯一锚点。
8. **`kb_move autoFix` 可能不修 Markdown 引用**：资产迁移后必须人工同步题卡、OCR 和索引引用。
9. **`kb_edit` 偶发 `UNKNOWN: open` 文件打开错误**：2026-09-25 在题-1088 已成功修改后，追加“(1) 待补/待原页核验”说明的前两次编辑均瞬时报 `UNKNOWN`，且当时 `kb_read` 未见部分写入；随后改用短锚点重试已成功落地。瞬时失败仍不得视为已应用，必须以重试后的 `kb_read` 为准。
