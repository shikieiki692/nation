## 三、根因：构建器的图源与现状**脱钩**

```python
MEDIA = VAULT / "媒体仓库"            # build_chusai_zhenti_layout.py:41
def resolve_images(body, log):
    p = MEDIA / name                  # :283  ← 只查媒体仓库，无 fallback
    if not p.exists(): log.append(f"   [缺图] {name}"); return ""
```

**实测对照（卷 md 图引用 vs `媒体仓库/` 命中）**：

| I / III / V / VII / IX（**老**） | 10/11/13/31/14 | **全中** | ✅ **可重建** |

**⇒ 老卷（北斗40 系）的图在 `媒体仓库/`；新卷（2026 机构模拟题系）的图全在
`04-题库/2026机构初赛模拟题/<机构>/images/`——构建器不查该路径。**

**⇒ 故：现有新卷 docx 的图，是**构建当时**（图可能一度落过 `媒体仓库/`，或流程含"部署"步骤）产生的；
以**当前代码 + 当前图位置**重出，必丢图。**

## 四、建议（三条，请择一）

| 方案 | 做法 | 风险 |

## 五、判据沉淀

1. 🔴🔴 **重出 docx 前必验「媒体数守恒」**（`docx word/media` 数 == 卷 md 图引用数）——
   否则构建器静默丢图，产物看似成功（脚本报"完成 3/3"，实际 media=0）。
2. 🔴🔴 **`resolve_images` 只有 `媒体仓库/` 一个搜索根** ⇒ **新卷（图在卡片 `images/`）必然丢图**；
   老卷（图在媒体仓库）不受影响 ⇒ **单卷成功不能外推**。
3. 🔴 **构建脚本报「完成 N/N」≠ 产物正确**——必须叠加**内容级断言**（图数、页数）。
4. 📌 交付件（docx）**入 git**，重出前**先备份**，出问题可即时回滚。
5. 📌 **学生版/答题卡不含来源行** ⇒ FM 类改动只需重出**答案与解析版**。
