## 二、P0：必须处理

### P0-1 教师向元信息泄漏进学生可见正文（24 份）

**现状**：v1.2 明令「教师侧管理信息（深度边界、使用建议、来源审计、课堂推进建议）只允许出现在 frontmatter 或 HTML 注释，**禁止进入学生可见正文**」。实测 24 份讲义在 HTML 注释**之外**保留了可见 blockquote：

| 泄漏字段 | 典型形态 | 涉及 |
|:--|:--|:--|
| 对应备课大纲 | `> **对应备课大纲**：[[04-课件/备课大纲/2026-06-04-亲核取代与消除反应-提高班]]` | 11 份（有机板块为主） |
| 前置要求 | `> **前置要求**：[[杂化轨道理论]]、[[VSEPR理论]]…` | 4 份 |
| 考纲覆盖 | `> **考纲覆盖**：§20 分光光度法` | 3 份 |
| 使用建议 | `> **使用建议**：基础巩固重点覆盖 §一-§四…` | 3 份 |
| 深度边界 | `> **深度边界**：本讲覆盖第一轮全部原子结构内容…` | 2 份 |

**影响**：这些 blockquote 会原样导出到 Word/PDF。学生能看到备课大纲内部链接、教师对题目的分层使用建议、考纲条目编号——既破坏学生版定位，也把教师对难度的判断提前摊给学生。

**优化动作**：把标题下方那组 `> **字段**` 整体包进 `<!-- … -->`（排版规范 §九 已给出正确范式，只是执行没跟上）。可脚本化，24 份一次过。

### P0-2 半截 math 474 处（集中在 6 份「超级充实版」）

**现状**：`$` 前面是基体字符、math 内只剩上下标，即 `H$_2$O`、`N$_2$`、`$_{57}\mathrm{La}$` 之外那类：

| 文件 | 处数 |
|:--|--:|
| 分子结构基础-超级充实版（自学完整） | 342 |
| 晶体学与晶体结构-超级充实版（自学完整） | 66 |
| 配位化合物基础-超级充实版（自学完整） | 41 |
| 原子结构-超级充实版（自学完整） | 20 |
| 元素周期表与周期律-超级充实版（自学完整） | 4 |
| 分光光度法-超级充实版（自学完整） | 1 |

最常见的基体是 `H$_`(101) / `O$_`(95) / `F$_`(74)。

**影响**：AGENTS.md 与库铁律明列「高风险写法：`Na$^+$`、`2s$^2$2p$^3$`，严禁半截 math」。Word 管线里 `H` + `$_2$` 是两个 run，下标极易与基体错位；这 6 份恰恰是最核心的自学讲义。

**优化动作**：简单式改 Unicode 下标（`H₂O`、`N₂`），复杂式整段 `$H_2O$`。建议新写脚本（`clean_bare_subscripts.py` 是题库硬编码版，不能复用），改后跑一遍 docx 重导出验证 oMath 数。

**现状**：md 源在 8 月改过、docx 仍是 6-25 版。有机板块几乎全军覆没：

| md 改 | docx 停在 | 讲义 |

| 2026-08-10 | 2026-06-25 | 周环反应、有机波谱分析、有机立体化学、杂原子与生物高分子、羰基化学与缩合反应、自由基反应、超分子化学 |

**影响**：学生手里的纸质/电子讲义与库内源已经不是一个版本，改过的讲解、补的题都没下发。

**优化动作**：二选一——(a) 补源：由自学完整版用脚本生成填空版 md（留占位符 diff，便于同步）；(b) 承认手工产物，把 5 个填空 docx 标 `_archive-手工产物` 并在 README 注明不可重建。**推荐 (a)**，因为课堂填空是上课主用版本。

### 6.2 执行中挖出的三个新问题（体检时没查到）

1. **公式渲染类问题（体检完全没查到，本轮最大发现）**——分三种形态，都会让 Word 里出现 LaTeX 源码字面量：
   - **裸 LaTeX 宏**：整行是公式却漏写 `$`（如 `\rho = \frac{ZM}{N_A V}`）。`晶体学与晶体结构-超级充实版` 因这类问题被导出 precheck 判 **18 error 直接阻塞导出**，已修。
   - **反引号包公式**：写成 `` `E^\theta = 0.34 V` ``（行内代码），pandoc 渲染成等宽字体的源码。**42 处**，已转 `$...$`（溶液与相图 4 / 热力学初步 2 / 电化学 33 / 配合物深化 2 / 酸碱理论 1）。
   - **类裸公式**：`$\mathrm{V_y}$$\mathrm{O_z}$` 相邻 `$$` 造成解析错乱，已合并。

   **过程中的事故与教训**：诊断脚本初版未识别**跨行 `$$...$$` 展示块**（含 blockquote 内 `> $$\begin{aligned}...$$`），全库命中虚高到 381 行；据此批量包裹 360 行后，**366 行其实是展示块内本来正确的行**，被包成 `$$` + `$公式$` + `$$`（破坏性）。靠 `git diff -U3` 抽查上下文才发现，用「成对 fence 配对法」（而非 toggle 状态机）新写 `handout_unwrap_in_display.py` 全数还原。修正诊断脚本后，**真正的块外裸 LaTeX 只有约 24 行**。
   → **流程教训**：诊断脚本的命中数必须先验证不是假阳性再谈批量 apply；全库 apply 前在单份文件上做完整 diff 目检；涉及 `$$` 的判定一律用配对法。
   → 当前剩余 4 行均为 blockquote 内 aligned 块的假阳性，实为 0。
2. **mermaid 箭头污染注释统计**：钛钒铬锰、铁钴镍铜锌、银金汞钼钨等把流程图裸写在 blockquote 内（`> A[x] -- "y" --> B(z)`），`-->` 被当成注释闭合标签，导致「注释不闭合」误报 6 份。屏蔽后真不闭合只剩 `讲义升级模式-原子结构样板.md`（type=参考，本轮未动）。
3. **5 个「孤儿」其实已归档**：`git ls-tree HEAD` 查得这 5 个课堂填空 docx 在版本库里早已在 `_archive/`，工作区只是残留。**判断孤儿前必须先查 HEAD**，否则会重复劳动。
