## 八、【重要机制】导出脚本会把「简单上标公式」降级成文本（不是 bug 也不是 pandoc 问题）

- 现象：Word 表格里 `$MT^{-2}$` 显示为带格式的 `MT⁻²`（**不是 OMML 公式对象**），
  纯文本提取看到 `MT-2`，容易误判为「公式没转」。实际 `vertAlign` 上标仍在，Word 里视觉正常。
- 根因：`build-all-handout-docx.py` 的 `_normalize_simple_inline_math_tokens()`（约 1047 行）
  用 `_SIMPLE_INLINE_SCRIPT_TOKEN_RE = r'(?<!\$)\$(?!\$)([A-Za-z0-9]+(?:(?:\^|_)(?:\{[^{}$\n]+\}|[^{}$\n]))+)\$(?!\$)'`
  把 `$10^{23}$`→`10²³`、`$MT^{-2}$`→`MT⁻²`、`$ITN^{-1}$`→`ITN⁻¹`，并去掉 `$`。
  同级还有 `_normalize_attached_simple_math_scripts()`（处理 `NO$_2^-$` 这类）。
- **排查手法（可复用）**：①pandoc 直转源文件作对照（`pandoc x.md -o probe.docx`）；
  ②脚本输出到临时目录再比对；③用 `zipfile` 读 `word/document.xml`，正则取 `<w:tc>…</w:tc>`，
  对每格判断 `<m:oMath`（是否公式）与 `<w:vertAlign`（是否上标格式）。
- 已验证 **pandoc 原生能正确转换**表格里所有公式（含 `$\text{kg m}^{2}\text{ s}^{-2}$`），
  与 `--from` 里是否开 `raw_tex` **无关**。所以「公式没转」要先怀疑脚本预处理，不要先怀疑 pandoc。

- **讲清楚「成环位置 vs 双键位置」的四层口径（可复用）**：
  ①价键层：碳四价，a–b 已有 σ 键 → 新键只能长在**两个 π 体系之间**；
  ②键级层：原 C=C **降级为单键**并成为环的两条边，π 电子全部转投两根新 σ 键（2×(σ+π) → 4σ）；
  ③拓扑层：只有两种完美匹配 —— straight {a–c, b–d} → 桥 0,2,2 → 双环[2.2.0]（环 4·4·6）；
  crossed {a–d, b–c} → 桥 2,1,1 → 双环[2.1.1]（环 4·5·5）。**桥头碳恒为系链两端 a、c，从未变过**，
  变的只是 b、d 挂在哪一侧；
  ④几何层：sp²→sp³，环丁烷折叠成蝶形（键角≈88°）。
  **编号映射**（solanoeclepin 双环[2.1.1]己烷）：C1=a、C4=c（桥头）、C2–C3=t1–t2、
  C5=b、C6=d；四元环 = C1–C5–C4–C6，其中 C1–C5、C4–C6 是原双键降级，C5–C4、C6–C1 是新键。
- **易错提醒**：crossed 产物里系链环是**五元**（straight 是四元），所以产物图上一眼认出的
  「那个环」常常不是环丁烷 —— 这是「位置对不上」错觉的主要来源。
