**根因：单个 commit 的 pack 体积过大 + 网络慢**
- 用脚本算出 15 笔的累计增量体积，精确定位：
  - 第 1~9 笔（到 `e001b231a`）：**仅 11.6 MB**

- docx 是 zip 二进制，git 无法增量压缩 → 必须整份重传

**关键教训：`Everything up-to-date` 是误导**
- 它出现在 push 失败之后，容易被误读为"已经是最新"
- 真相：本地 remote-tracking ref 未更新，远端实际没变
- **唯一可信判据：`git ls-remote origin master` 的输出**

**「卡住」是假象**
- 上传 106 MB 大包时 Git **不打印实时进度**（尤其慢速连接）
- 66 KiB/s 下 106 MB ≈ 27 分钟
- 判据：`tasklist | grep git-remote` 若有进程且内存上百 MB，说明**正在传**

### 🔑 新沉淀：大 pack 推送的分批方案
1. 先算体积：`git rev-list --objects <base>..<commit>` + `git cat-file --batch-check=%(objectsize)`
2. 按体积分批，用 `git push origin <commit>:master` 逐批快进
3. 大包批配 `git config http.postBuffer 524288000`
4. 仍失败 → 换 SSH（`git remote set-url origin git@github.com:...`），不受 HTTP 包体限制

## 23:30~ 习题书 Word 排版污染治理（新战场，用户报热力学两处格式乱）

### 用户报的两个问题与根因
1. **玻恩-哈伯循环 `$$...$$` 整段印进 Word**：`build-all-handout-docx.py` 4b4 步的尺寸前缀正则只清了 `Bigl/Bigr/bigl/bigr`，**裸 `\Big` 漏网** → texmath 拒绝转换 → pandoc 回退成 TeX 源码。
2. **大豆发热量 HTML 表散成十几段**：源是 `<table><tr><td>…`，pandoc 输出 docx 时不落 `w:tbl`，只摊成段落。附带 `$w_b/(%)$` 的 `%` 是 LaTeX 注释符，吃掉 `)$` 致 `$` 未闭合，百分号在 Word 里消失。

### 修复（全落在导出管线，未碰 04-题库）
commit `3c8ca9864`，`11-模板/scripts/build-all-handout-docx.py`：
- 新增 `_convert_html_tables()`（步骤 0-pre）：`<table>` → pipe table；保守条件 无 span/`<br>`/图片、列数 1–8
- 4b4 补齐 `Big/bigg/Bigm/bigm` + `(?![a-zA-Z])` 守卫（防误伤 `\bigcirc`/`\bigcup`）
- 新增 4b7 `\textcircled{X}`→`\text{X}`；4b8 `\xrightleftharpoons[下]{上}`→`\underset{下}{\overset{上}{\rightleftharpoons}}`；4b8b `\longrightleftharpoons`→`\rightleftharpoons`；4b9 `\atop`→`\substack{A \\ B}`
- 新增 4b10 `_map_math_spans()`：只在 `$…$`/`$$…$$` 内反转义 HTML 实体 + 转义裸 `%`/`#`

### 关键教训（复用必读）
- **`\{([^{}]*)\}` 在参数含嵌套花括号时整体失配**（如 `\mathrm{p}K_\mathrm{a1}`）→ 静默不替换、极难发现。**凡是 LaTeX 宏参数一律用平衡括号扫描**，不要用 `[^{}]`。
- **bash 内联 `python -c` 会吃反斜杠** → 含正则的验证必须 Write 成 `.py` 再跑（记忆里已记，再次踩）。
- 定位 pandoc 公式失败的有效手段：**跑全量 `_preprocess_markdown` + pandoc docx，收集 stderr 的 `Could not convert TeX math`**，比扫 docx 产物准（docx 里的 `$$` 还有 OCR 误识/奇偶失衡两类非转换失败）。
- 回归验证方法：`git show HEAD:<脚本>` 存为 `_old_build_docx.py`，同进程 import 新旧两版，逐文件 diff `_preprocess_markdown` 输出，按差异类型归因。
