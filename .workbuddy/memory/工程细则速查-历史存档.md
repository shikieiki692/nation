### git
- **`git status --porcelain` 中文路径是八进制转义** → 脚本解析**必须用 `-z`**。⚠️ **`-z` 输出的路径恒为正斜杠 `/`**：与 git 输出比对时**禁** `replace("/", os.sep)`（只有与 Windows 文件系统路径比对才需要）——批9 做反了，把本会话 6 个文件全判成「无改动」，差点误判脚本未生效。
- **并发会话共享工作区（不只是 index）**：你 `--apply` 的改动可能被他人 commit 带走（批9 A 节 apply 后 7 分钟被并行会话提交 `1e31f0377`）→ **提交前必查 `git diff --stat -- <文件>` 是否为空；为空 ≠ 没改，可能是已被他人提交**。判据：`git log -1 -- <文件>` + `git show HEAD:<文件>` 比对字节/关键串。
- **`git commit -- <pathspec>` 会覆盖 index**（丢 rename 识别）→ 不用 pathspec；或先 `reset` 再精确 `add`。
- **并发 index 共享**：他人 `git add` 的会被你的 `commit` 带走 → **commit 前必核暂存区总数 = 预期数**。误携带恢复：`reset --soft HEAD~1` → 路径限定重提。
- **⛔ 有并行会时严禁 `commit --amend`**（静默重写 HEAD）。信号：`N files changed, M insertions` 且 M≪N。
- 只 add 本会话文件；**禁 add→commit 一条龙**；推送前后**一律 `ls-remote` 取真值**；提交信息 `git commit -F <文件>`；`push >log 2>&1; echo "exit=$?"`。
- ✅ 推送受阻正解 = Clash Verge（端口 `7897`）→ skill `github-push-proxy-recovery`。
- **媒体仓库/ 被 .gitignore 忽略不入库**（既有惯例）→ 图只本地复制入仓，commit 只含 md。
- **⛔⛔ 禁用 `git rm` 删文件**（09-20 实证）：safe-delete 环境下 `git rm` 若被 SIGTERM，① 留 **stale `.git/index.lock`** ② 可能伴随**远超 pathspec 规模的 worktree 缺失**（曾致 289 份 docx「消失」）。正解＝**逐文件 `os.remove`（走 safe-delete）** 或改完 **`git restore`**。
  - **`index.lock` 判 stale**：持有者可能是 `git fsmonitor--daemon`（长驻守护，**非元凶**）；判据＝**mtime 长时间不变 ＋ `find .git -maxdepth 1 -newermt <时刻>` 无其他写痕迹**。删锁前必须两项齐核。
  - **丢失恢复第一原则**：**先 `git checkout HEAD -- <区域>` 全量恢复，再谈其他**；成功判据四项齐备＝`D`=0 ／ 暂存区=0 ／ `git diff HEAD` 为空 ／ 抽查 md5 相同。

### git
- 中文路径用 `-z`（`-z` 输出恒正斜杠，与 git 输出比对禁 replace sep）；`-c core.quotepath=false` 的 `-c` 必须在子命令前。

### git
- 中文路径用 `-z`；`-c core.quotepath=false` 的 `-c` 须在子命令前。⚠️ **路径含空格须加引号**（`git add -- "$F"`）：不加会被拆成多 pathspec 报 `did not match`，且 **HEAD 不变**（易误判成功）。
- 只 add 本会话文件；msg 唯一命名＋`-F`；**commit 后 `git show --numstat HEAD` 核行数＝本批文件数**。`git commit -- <pathspec>` 取**工作区**内容、**不含未跟踪新文件**；派生新文件须 `git add -- "$F"` → `commit -- "$F"` → `git reset -q HEAD -- "$F"`。⛔ **禁 `git add -- <目录>`**（连带该目录下**全部未跟踪文件**）。
- **暂存区会被并行会话注入** → 临时索引 `GIT_INDEX_FILE=<tmp> git read-tree HEAD && add && commit`（**同一条 `&&` 链**）。⚠️ 用过临时索引后须把真实索引对本次路径重新 `git add` 对齐；否则真实索引停在旧快照 → 新增文件报**幻影「已暂存删除」（`D `）**、就地修改报 `MM`，其他会话据此提交会**真删新文件／静默回滚改动**。收尾必查 `git status --porcelain -uall | awk 'substr($0,1,2)=="D "{n++}` ＝ 0 且本次路径为空；撞 `index.lock` **勿手删**。
- 临时索引**防不住 HEAD 并发前移**：报 `cannot lock ref 'HEAD'`（exit 128）→ **基于新 HEAD 重试，绝不 `--force`**；提交后 `git diff --name-only <基线> HEAD` 核对只含自己文件。
- 🔴 **报「未推送数」只能信 `ls-remote`**：本环境 `refs/remotes/origin/` 不存在（只剩 packed-refs 旧值）⇒ `git log origin/master..HEAD` 虚报（曾 140 vs 真值 5）；`git update-ref` 返 rc=0 但引用读不回来。**纪律**：报数/推送前后一律 `git ls-remote origin master`，**禁用** `git branch -vv` 与 `origin/master..HEAD`；**推送成功判据 ＝ 远端 tip == 本地 HEAD**。
- `git rm` SIGTERM → stale index.lock（活锁勿手删）；恢复第一原则 `git checkout HEAD -- <区域>`；禁 `--no-verify`；推送用 Clash 7897 ＋ `-c credential.helper=manager`（`~/.gitconfig` 的 `helper =` 空值会清空 helper）→ skill `github-push-proxy-recovery`。`媒体仓库/` 不入库。
