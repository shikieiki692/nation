## 推送受阻：根因定位（23:25~23:35）

### 排查路径（逐步排除）
1. `git fetch origin` → 成功（`[new branch] master -> origin/master`），但 `refs/remotes/` 仍空（沙箱拦了 ref 落盘）→ 证明 **`[origin/master: gone]` 是 ref 过期假象**
2. `git -c credential.helper= push` → `could not read Username`（置空 helper 反而断认证）
3. 查明凭据链两级：
   - **system 层**（PortableGit etc/gitconfig）：`helper-selector` ← 抢在 global 前
   - **global 层**（~/.gitconfig）：`git-credential-wincred.exe`，且 `[credential "helperselector"] selected = manager`
4. `git-credential-wincred.exe` push → **卡死 180s**（无输出，SIGTERM）
5. `git-credential-manager.exe` push → **明确报错** `schannel: failed to receive handshake, SSL/TLS connection failed`
6. 查 TLS/代理：`http.sslBackend` 空（默认 schannel）；**存在沙箱代理 `http_proxy=http://127.0.0.1:65433`**
   - `ls-remote` 走 HTTP CONNECT 可透传 → 成功（读操作 OK）
   - `push` 需 TLS 握手 + 双向传输 → schannel 经代理握手失败
7. `-c http.sslBackend=openssl` 后再 push → **仍卡死**（无输出）
8. 探测失败层级：用不存在的仓库 push → **立即**返回 `could not read Username`（未等网络）
   → **结论：卡点在「认证（无可用 GitHub 凭据）」而非网络**

### 次级问题（凭据解决后仍需处理）
