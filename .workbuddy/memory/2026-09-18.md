## 【意外插曲】git 对象库缺失 → 零丢失恢复（非本会话造成）

### 现象
- `git rev-list --objects HEAD` **rc=128 中断**（祖先链有空洞）→ 无法做「提交前核验祖先链」
- `git fsck` 报 `invalid reflog entry 0075b769…`、`broken link`、`cache-tree invalid sha1`

### 诊断链（逐层暴露，共 22 个对象缺失）
- **`rev-list` 遇第一个缺失即中断** → 每次只暴露 1 个 → 需**闭环迭代**（我写了 `heal_objects_0918f.py`）
- ⚠️ **关键词两形态**：`missing blob object` **与** `bad tree object` **都是缺失**
  （首版正则只认 `missing` → 漏抓 tree 层，卡住一轮）
- ⚠️ **`cat-file --batch-all-objects` 不含 pack 内对象**（只 13,229 而 pack 有 186,219）
  → 用 `show-index` 逐 pack 建全集才对
- ⚠️ **无索引批处理读 tree 内容**：`subprocess.run(cat-file --batch, input=..., capture_output=True)`
  → 完成 147,806 对象扫描（`text=True` + 大输入会**卡死**）

### 恢复（三源）
- **回收站直取命中 21/22**：`$I` 元数据 8 字节头 + UTF-16LE 路径 → 正则 `objects[\/]+([0-9a-f]{2})[\/]+([0-9a-f]{38})`
  - ⚠️ **`C://$Recycle.Bin` 与 `C://$RECYCLE.BIN` 是同一目录的两个路径**（walk 会**双计**，需去重）
  - ⚠️ 末位 1 个（`0083febc7d`）**不在回收站** → 属**历史版本 blob**（工作区无此内容，源2 不适用）
- **源3 远端补齐**：`git fetch --refetch --filter=blob:none origin master`
  - `--refetch` **不做共同祖先协商** → **绕过祖先链空洞**（普通 fetch 必失败）
  - ⚠️ **TLS 间歇失败**（`schannel: failed to receive handshake`）；实测**代理 7897 完全正常**
    （`gstatic 204` / `github 200`）→ **重试即成功**，非节点问题
  - ⚠️ **`--filter=blob:none` 会写入 promisor 配置 → 制造假绿**：
    缺失 blob 被当「已承诺」，报错从 `missing` 变成 `promisor remote fetch failed`
    → **必须 `git config --local --unset remote.origin.promisor` + `…partialclonefilter` 才是真判据**

### 收官核验
- `git rev-list --objects HEAD` → **rc=0，173,358 对象全可读，stderr 空**
- `git fsck --no-progress --no-dangling` → **rc=0，0 error / 0 broken link / 0 missing**
